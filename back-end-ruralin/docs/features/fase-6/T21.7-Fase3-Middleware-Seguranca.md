## Tarefas Detalhadas

### 1. tenantActivationMiddleware

**Arquivo**: `src/middleware/tenantActivation.ts`

**Responsabilidades**:
- Verificar se tenant está ativo (para ROOT/CLIENT)
- Verificar se consultoria está ativa (para CONSULTOR)
- Bloquear acesso se inativo
- Retornar 403 Forbidden com mensagem clara

**Lógica**:
```typescript
1. Obter usuário do RequestContext
2. Se usuário é ROOT ou CLIENT:
   a. Obter tenantId do usuário
   b. Buscar tenant (com cache)
   c. Verificar se tenant está ativo
   d. Se inativo: retornar 403
   e. Verificar se consultoria está ativa
   f. Se inativa: retornar 403
3. Se usuário é CONSULTOR:
   a. Obter consultoriaId do usuário
   b. Buscar consultoria (com cache)
   c. Verificar se consultoria está ativa
   d. Se inativa: retornar 403
4. Se usuário é GOD:
   a. Bypass (não verificar)
5. Continuar para próximo middleware
```

**Cache**:
- Cache de status do tenant: `tenant:status:{tenantId}` (TTL: 5 minutos)
- Cache de status da consultoria: `consultoria:status:{consultoriaId}` (TTL: 5 minutos)
- Invalidação ao ativar/desativar

**Ordem de Execução**:
1. `requestContextMiddleware`
2. `authMiddleware`
3. `tenantActivationMiddleware` ← **NOVO**
4. `tenantMiddleware`
5. `authorizationMiddleware`

### 2. consultoriaAccessMiddleware

**Arquivo**: `src/middleware/consultoriaAccess.ts`

**Responsabilidades**:
- Validar acesso de CONSULTOR aos recursos
- Verificar que tenant pertence à consultoria do CONSULTOR
- Bloquear acesso não autorizado

**Lógica**:
```typescript
1. Obter usuário do RequestContext
2. Se usuário é CONSULTOR:
   a. Obter consultoriaId do usuário
   b. Se requisição envolve tenant:
      - Obter tenantId (params ou body)
      - Buscar tenant
      - Verificar se tenant.consultoriaId === user.consultoriaId
      - Se não: retornar 403
3. Continuar para próximo middleware
```

**Aplicação**:
- Rotas de tenants (criar, atualizar, deletar, ativar, desativar)
- Rotas de consultoria (listar tenants)

### 5. Atualizar RequirePermission

**Arquivo**: `src/core/authorization/RequirePermission.ts`

**Alterações**:
1. Adicionar bypass para GOD
2. Adicionar validação de acesso para CONSULTOR
3. Manter validação normal para ROOT/CLIENT

**Lógica**:
```typescript
export function RequirePermission(permission: string) {
  return function (target: any, propertyKey: string, descriptor: PropertyDescriptor) {
    const originalMethod = descriptor.value;
    
    descriptor.value = async function (...args: any[]) {
      const context = getRequestContext();
      const user = context?.getUser();
      
      // Bypass para GOD
      if (user?.tipo === 'GOD') {
        return originalMethod.apply(this, args);
      }
      
      // Validação de acesso para CONSULTOR
      if (user?.tipo === 'CONSULTOR') {
        // Validar acesso à consultoria (se necessário)
        await validateConsultoriaAccess(user.consultoriaId, args);
      }
      
      // Validação normal de permissões
      const hasPermission = await authorizationService.hasPermission(
        user.id,
        permission
      );
      
      if (!hasPermission) {
        throw new ForbiddenException('Permissão negada');
      }
      
      return originalMethod.apply(this, args);
    };
  };
}
```

### 6. Atualizar AuthorizationService

**Arquivo**: `src/application/services/AuthorizationService.ts`

**Métodos Adicionais**:

- `canAccessTenant(userId: number, tenantId: number): Promise<boolean>`
- `isGod(userId: number): Promise<boolean>`

**Lógica**:
```typescript
async canAccessConsultoria(userId: number, consultoriaId: number): Promise<boolean> {
  const user = await this.usuarioRepository.findById(userId);
  
  // GOD pode acessar qualquer consultoria
  if (user.tipo === 'GOD') {
    return true;
  }
  
  // CONSULTOR só acessa sua consultoria
  if (user.tipo === 'CONSULTOR') {
    return user.consultoriaId === consultoriaId;
  }
  
  return false;
}

async canAccessTenant(userId: number, tenantId: number): Promise<boolean> {
  const user = await this.usuarioRepository.findById(userId);
  
  // GOD pode acessar qualquer tenant
  if (user.tipo === 'GOD') {
    return true;
  }
  
  // CONSULTOR acessa tenants da sua consultoria
  if (user.tipo === 'CONSULTOR') {
    const tenant = await this.tenantRepository.findById(tenantId);
    return tenant.consultoriaId === user.consultoriaId;
  }
  
  // ROOT/CLIENT só acessa seu tenant
  if (user.tipo === 'ROOT' || user.tipo === 'CLIENT') {
    return user.tenantId === tenantId;
  }
  
  return false;
}
```

## Ordem de Middleware

```
1. requestContextMiddleware
   ↓
2. authMiddleware
   - Valida token JWT
   - Adiciona usuário ao RequestContext
   - Adiciona tipo, tenantId, consultoriaId
   ↓
3. tenantActivationMiddleware ← NOVO
   - Verifica se tenant está ativo (ROOT/CLIENT)
   - Verifica se consultoria está ativa (CONSULTOR)
   - Bloqueia acesso se inativo
   ↓
4. tenantMiddleware
   - Aplica filtro de tenantId (ROOT/CLIENT)
   - Aplica filtro de consultoriaId (CONSULTOR)
   - Bypass para GOD
   ↓
5. consultoriaAccessMiddleware ← NOVO (opcional, em rotas específicas)
   - Valida acesso de CONSULTOR aos recursos
   ↓
6. authorizationMiddleware
   - Valida permissões
   - Bypass para GOD
   ↓
7. Controller
```
