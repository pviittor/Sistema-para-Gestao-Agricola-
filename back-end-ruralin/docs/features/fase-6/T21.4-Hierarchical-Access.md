## Hierarquia de Acesso

### GOD (God User)

**Características**:
- Tipo: `GOD`
- `tenantId`: NULL
- `consultoriaId`: NULL
- Acesso: Total, sem restrições
- Bypass: Todas as permissões

**Permissões**:
- Criar/gerenciar consultorias
- Criar/gerenciar consultores
- Acessar dados de qualquer tenant (com header especial)
- Aumentar limites de tenants
- Desativar/ativar consultorias

**Validações**:
- Não aplica filtro de `tenantId`
- Não aplica filtro de `consultoriaId`
- Bypass de `@RequirePermission` (opcional)

### CONSULTOR (Consultant User)

**Características**:
- Tipo: `CONSULTOR`
- `tenantId`: NULL
- `consultoriaId`: NOT NULL (FK para Consultoria)
- Acesso: Apenas tenants da sua consultoria

**Permissões**:
- Criar/gerenciar tenants da sua consultoria
- Visualizar dados agregados dos seus tenants
- Desativar/ativar seus tenants
- Listar usuários dos seus tenants (agregado)

**Validações**:
- Aplica filtro de `consultoriaId`
- Não aplica filtro de `tenantId` (acessa múltiplos)
- Valida que tenant pertence à sua consultoria

### ROOT (Root User)

**Características**:
- Tipo: `ROOT`
- `tenantId`: NOT NULL
- `consultoriaId`: NULL
- Acesso: Apenas seu tenant

**Permissões**:
- Gerenciar usuários do seu tenant
- Acessar todos os dados do seu tenant
- Criar sub-usuários (CLIENT)

**Validações**:
- Aplica filtro de `tenantId` automaticamente
- Não pode acessar outros tenants

### CLIENT (Client User)

**Características**:
- Tipo: `CLIENT`
- `tenantId`: NOT NULL
- `consultoriaId`: NULL
- Acesso: Apenas seu tenant (limitado)

**Permissões**:
- Acessar dados do seu tenant (conforme permissões)
- Operações limitadas conforme roles

**Validações**:
- Aplica filtro de `tenantId` automaticamente
- Não pode acessar outros tenants

## Funcionalidades

### 1. Bypass para GOD

**Localização**: `src/core/authorization/RequirePermission.ts`

**Lógica**:
```typescript
// Antes de verificar permissões
const user = getRequestContext()?.getUser();
if (user?.tipo === 'GOD') {
  return; // Bypass, permite acesso
}
// Continua com validação normal de permissões
```

**Aplicação**:
- Todos os decorators `@RequirePermission`
- Todos os métodos de `AuthorizationService`
- Middleware de autorização

### 2. Validação de Acesso de CONSULTOR

**Localização**: `src/middleware/consultoriaAccess.ts`

**Lógica**:
```typescript
if (user.tipo === 'CONSULTOR') {
  // Validar que recurso pertence à consultoria do CONSULTOR
  const consultoriaId = user.consultoriaId;
  
  // Para operações em tenants
  if (req.params.tenantId || req.body.tenantId) {
    const tenant = await Tenant.findByPk(tenantId);
    if (tenant.consultoriaId !== consultoriaId) {
      throw new ForbiddenException('Acesso negado');
    }
  }
}
```

**Aplicação**:
- Rotas de tenants
- Rotas de consultoria
- Qualquer operação que envolva tenant

### 3. Filtro Automático por Tipo

**Localização**: `src/core/repository/BaseRepository.ts`

**Lógica**:
```typescript
getTenantFilter(): WhereOptions | null {
  const user = getRequestContext()?.getUser();
  
  if (user?.tipo === 'GOD') {
    return null; // Sem filtro
  }
  
  if (user?.tipo === 'CONSULTOR') {
    // Filtro por consultoriaId (se aplicável)
    return { consultoriaId: user.consultoriaId };
  }
  
  if (user?.tipo === 'ROOT' || user?.tipo === 'CLIENT') {
    // Filtro por tenantId
    return { tenantId: user.tenantId };
  }
  
  return null;
}
```

### 4. Validação Cross-Tenant

**Localização**: `src/application/services/*/ApplicationService.ts`

**Lógica**:
```typescript
// Ao criar/atualizar entidade com referência a tenant
if (dto.tenantId) {
  const user = getRequestContext()?.getUser();
  
  if (user?.tipo === 'CONSULTOR') {
    // Validar que tenant pertence à consultoria do CONSULTOR
    const tenant = await Tenant.findByPk(dto.tenantId);
    if (tenant.consultoriaId !== user.consultoriaId) {
      throw new ForbiddenException('Tenant não pertence à sua consultoria');
    }
  }
  
  if (user?.tipo === 'ROOT' || user?.tipo === 'CLIENT') {
    // Validar que é o próprio tenant
    if (dto.tenantId !== user.tenantId) {
      throw new ForbiddenException('Acesso negado a outro tenant');
    }
  }
}
```

## Validações por Tipo

### Criação de Usuário

**GOD pode criar**:
- CONSULTOR (com `consultoriaId`)
- GOD (outro GOD)

**CONSULTOR pode criar**:
- ROOT (com `tenantId` da sua consultoria)
- CLIENT (com `tenantId` da sua consultoria)

**ROOT pode criar**:
- CLIENT (com mesmo `tenantId`)

### Acesso a Dados

**GOD**:
- Sem filtros
- Pode especificar `tenantId` em header especial
- Endpoint administrativo: `/api/admin/tenants/:id/data`

**CONSULTOR**:
- Filtro por `consultoriaId`
- Acesso a múltiplos tenants da sua consultoria
- Dados agregados

**ROOT/CLIENT**:
- Filtro por `tenantId`
- Acesso apenas ao próprio tenant
