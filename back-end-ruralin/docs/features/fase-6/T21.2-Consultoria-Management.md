## Modelo de Dados

### Consultoria

**Tabela**: `C011_consultoria`

**Campos**:
```typescript
{
  id: number;                    // PK, AUTO_INCREMENT
  tenantId?: number;             // FK opcional (tenant da consultoria)
  razaoSocial: string;           // NOT NULL
  nomeFantasia?: string;          // NULLABLE
  cnpj: string;                  // UNIQUE, NOT NULL
  email: string;                 // NOT NULL
  telefone?: string;             // NULLABLE
  ativo: boolean;                // NOT NULL, DEFAULT true
  dataAtivacao: Date;            // NOT NULL
  dataDesativacao?: Date;        // NULLABLE
  limiteTenants: number;         // NOT NULL, DEFAULT 10
  tenantCount: number;           // NOT NULL, DEFAULT 0 (calculado)
  usercreation: number;          // FK -> usuarios.id, NOT NULL
  datecreation: Date;             // NOT NULL
}
```

**Índices**:
- PRIMARY KEY: `id`
- UNIQUE: `cnpj`
- INDEX: `ativo`
- INDEX: `usercreation`

**Relacionamentos**:
- 1:N → `Tenant` (via `consultoriaId`)
- 1:N → `Usuario` (via `consultoriaId`, apenas CONSULTOR)

## Funcionalidades

### 1. Criar Consultoria (GOD)

**Endpoint**: `POST /api/consultorias`

**Validações**:
- Apenas usuário tipo `GOD` pode criar
- CNPJ deve ser único
- Email deve ser válido
- `razaoSocial` obrigatório

**Lógica**:
1. Validar permissão (GOD)
2. Validar CNPJ único
3. Criar consultoria com `ativo: true`
4. Definir `dataAtivacao: now()`
5. Definir `usercreation: userId do GOD`
6. Retornar `ConsultoriaResponseDto`

### 2. Listar Consultorias (GOD)

**Endpoint**: `GET /api/consultorias`

**Validações**:
- Apenas GOD pode listar todas
- Paginação opcional

**Lógica**:
1. Validar permissão (GOD)
2. Buscar todas as consultorias (sem filtro de tenant)
3. Retornar lista paginada

### 3. Obter Consultoria por ID (GOD)

**Endpoint**: `GET /api/consultorias/:id`

**Validações**:
- Apenas GOD pode acessar qualquer consultoria

**Lógica**:
1. Validar permissão (GOD)
2. Buscar consultoria por ID
3. Retornar `ConsultoriaResponseDto`

### 4. Atualizar Consultoria (GOD)

**Endpoint**: `PUT /api/consultorias/:id`

**Validações**:
- Apenas GOD pode atualizar
- CNPJ único (se alterado)
- Não permitir alterar `tenantCount` diretamente

**Lógica**:
1. Validar permissão (GOD)
2. Validar CNPJ único (se alterado)
3. Atualizar campos permitidos
4. Retornar `ConsultoriaResponseDto` atualizado

### 5. Desativar Consultoria (GOD)

**Endpoint**: `PUT /api/consultorias/:id/desativar`

**Validações**:
- Apenas GOD pode desativar
- Consultoria deve estar ativa

**Lógica**:
1. Validar permissão (GOD)
2. Verificar se consultoria está ativa
3. Desativar consultoria (`ativo: false`)
4. Desativar todos os tenants (cascade)
5. Definir `dataDesativacao: now()`
6. Retornar sucesso

### 6. Ativar Consultoria (GOD)

**Endpoint**: `PUT /api/consultorias/:id/ativar`

**Validações**:
- Apenas GOD pode ativar
- Consultoria deve estar inativa

**Lógica**:
1. Validar permissão (GOD)
2. Verificar se consultoria está inativa
3. Ativar consultoria (`ativo: true`)
4. Definir `dataAtivacao: now()`
5. Limpar `dataDesativacao`
6. Retornar sucesso

### 7. Listar Tenants da Consultoria (GOD/CONSULTOR)

**Endpoint**: `GET /api/consultorias/:id/tenants`

**Validações**:
- GOD pode acessar qualquer consultoria
- CONSULTOR pode acessar apenas sua consultoria

**Lógica**:
1. Validar permissão (GOD ou CONSULTOR da consultoria)
2. Buscar todos os tenants da consultoria
3. Retornar lista de tenants

### 8. Aumentar Limite de Tenants (GOD)

**Endpoint**: `PUT /api/consultorias/:id/limite-tenants`

**Validações**:
- Apenas GOD pode alterar limite
- Novo limite deve ser >= `tenantCount`

**Lógica**:
1. Validar permissão (GOD)
2. Validar que novo limite >= `tenantCount`
3. Atualizar `limiteTenants`
4. Retornar sucesso

## Regras de Negócio

### 1. Criação de Consultoria

- Apenas usuário tipo `GOD` pode criar
- CNPJ deve ser único no sistema
- Consultoria é criada como ativa por padrão
- `limiteTenants` padrão: 10

### 2. Atualização de Consultoria

- Não permitir alterar `tenantCount` diretamente (calculado)
- Não permitir alterar `usercreation` (auditoria)
- CNPJ pode ser alterado, mas deve permanecer único

### 3. Desativação

- Desativar consultoria desativa todos os tenants (cascade)
- Dados são mantidos (soft delete)
- Reativação restaura acesso

### 4. Limite de Tenants

- `limiteTenants` define máximo de tenants permitidos
- `tenantCount` é incrementado automaticamente ao criar tenant
- `tenantCount` é decrementado ao excluir tenant (soft delete)
- Apenas GOD pode aumentar limite

### UpdateConsultoriaDto

- Mesmas validações de `CreateConsultoriaDto`
- CNPJ único (se fornecido)

## Autorização

### Permissões

- **GOD**: Acesso total a todas as consultorias
- **CONSULTOR**: Acesso apenas à sua consultoria (via `consultoriaId`)
- **ROOT/CLIENT**: Sem acesso a consultorias

### Decorators

```typescript
@RequirePermission('consultoria:create')  // Apenas GOD
@RequirePermission('consultoria:read')    // GOD ou CONSULTOR (própria)
@RequirePermission('consultoria:update')   // Apenas GOD
@RequirePermission('consultoria:delete')   // Apenas GOD (soft delete)
```
