## Tarefas Detalhadas

### 1. Model Consultoria

**Arquivo**: `src/models/Consultoria.ts`

**Campos**:
- `id` (PK)
- `tenantId` (FK, nullable)
- `razaoSocial` (string)
- `nomeFantasia` (string, nullable)
- `cnpj` (string, unique)
- `email` (string)
- `telefone` (string, nullable)
- `ativo` (boolean)
- `dataAtivacao` (Date)
- `dataDesativacao` (Date, nullable)
- `limiteTenants` (number)
- `tenantCount` (number)
- `usercreation` (FK -> Usuario)
- `datecreation` (Date)

**Relacionamentos**:
- `belongsTo` Usuario (via `usercreation`)
- `hasMany` Tenant (via `consultoriaId`)

### 2. Model Tenant

**Arquivo**: `src/models/Tenant.ts` (criar se não existir)

**Campos**:
- `id` (PK)
- `consultoriaId` (FK -> Consultoria) - **NOVO**
- `nome` (string)
- `slug` (string, unique)
- `ativo` (boolean) - **NOVO**
- `dataAtivacao` (Date)
- `dataDesativacao` (Date, nullable)

**Relacionamentos**:

### 3. Atualização Model Usuario

**Arquivo**: `src/models/Usuario.ts`

**Alterações**:
- Adicionar campo `consultoriaId` (FK -> Consultoria, nullable)
- Expandir enum `tipo` para incluir `'GOD'` e `'CONSULTOR'`

**Regras**:
- `GOD`: `consultoriaId = null`, `tenantId = null`
- `CONSULTOR`: `consultoriaId != null`, `tenantId = null`
- `ROOT/CLIENT`: `consultoriaId = null`, `tenantId != null`

### 4. Migrations

#### 4.1. create-consultoria
- Criar tabela `C011_consultoria`
- Índices: PK, UNIQUE(cnpj), INDEX(ativo), INDEX(usercreation)

#### 4.2. add-consultoriaId-to-tenant
- Adicionar coluna `consultoriaId` em `C012_tenant` (ou tabela de tenants)
- FK para `C011_consultoria.id`
- NOT NULL após migração de dados

#### 4.3. add-consultoriaId-to-usuario
- Adicionar coluna `consultoriaId` em `usuarios`
- FK para `C011_consultoria.id`
- NULLABLE (apenas CONSULTOR tem)

#### 4.4. add-ativo-to-tenant
- Adicionar colunas `ativo`, `dataAtivacao`, `dataDesativacao` em `C012_tenant`
- `ativo` DEFAULT true
- Índice em `ativo`

#### 4.5. expand-tipo-usuario
- Atualizar enum `tipo` em `usuarios` para incluir `'GOD'` e `'CONSULTOR'`
- Validar dados existentes

## Validações

### Consultoria
- CNPJ único
- Email válido
- `razaoSocial` obrigatório
- `limiteTenants` >= 1

### Tenant
- Slug único globalmente
- `nome` obrigatório
- `consultoriaId` obrigatório
- `slug` formato válido (sem espaços, lowercase)

### Usuario
- `tipo` deve ser um dos: `'GOD'`, `'CONSULTOR'`, `'ROOT'`, `'CLIENT'`
- Se `tipo = 'CONSULTOR'`, `consultoriaId` obrigatório
- Se `tipo = 'GOD'`, `consultoriaId = null`, `tenantId = null`
- Se `tipo = 'ROOT'` ou `'CLIENT'`, `tenantId` obrigatório
