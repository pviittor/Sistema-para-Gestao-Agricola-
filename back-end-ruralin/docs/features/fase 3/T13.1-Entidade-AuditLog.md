## Estrutura do Modelo

### Schema da Tabela

```sql
CREATE TABLE audit_logs (
  id INT AUTO_INCREMENT PRIMARY KEY,
  userId INT NOT NULL,
  action ENUM('CREATE', 'UPDATE', 'DELETE', 'READ', 'LOGIN', 'LOGOUT') NOT NULL,
  entity VARCHAR(100) NOT NULL,
  entityId INT NULL,
  changes JSON NULL,
  ip VARCHAR(45) NULL,
  userAgent TEXT NULL,
  timestamp DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  createdAt DATETIME NOT NULL,
  updatedAt DATETIME NOT NULL,
  
  FOREIGN KEY (userId) REFERENCES usuarios(id),
  
  INDEX idx_audit_logs_user_timestamp (userId, timestamp),
  INDEX idx_audit_logs_entity (entity, entityId),
  INDEX idx_audit_logs_timestamp (timestamp),
  INDEX idx_audit_logs_action (action)
);
```

### Tipos de Ação

**AuditAction**:
- `CREATE` - Criação de entidade
- `UPDATE` - Atualização de entidade
- `DELETE` - Exclusão de entidade
- `READ` - Leitura de entidade (opcional, para auditoria de acesso)
- `LOGIN` - Login de usuário
- `LOGOUT` - Logout de usuário

---

## Índices Criados

### 1. `idx_audit_logs_user_timestamp`

**Campos**: `userId`, `timestamp`

**Uso**: Buscar logs de um usuário ordenados por data

**Exemplo de query otimizada**:
```sql
SELECT * FROM audit_logs 
WHERE userId = 1 
ORDER BY timestamp DESC 
LIMIT 100;
```

### 2. `idx_audit_logs_entity`

**Campos**: `entity`, `entityId`

**Uso**: Buscar logs de uma entidade específica

**Exemplo de query otimizada**:
```sql
SELECT * FROM audit_logs 
WHERE entity = 'Usuario' AND entityId = 123 
ORDER BY timestamp DESC;
```

### 3. `idx_audit_logs_timestamp`

**Campos**: `timestamp`

**Uso**: Buscar logs por período de tempo

**Exemplo de query otimizada**:
```sql
SELECT * FROM audit_logs 
WHERE timestamp BETWEEN '2025-01-01' AND '2025-01-31' 
ORDER BY timestamp DESC;
```

### 4. `idx_audit_logs_action`

**Campos**: `action`

**Uso**: Buscar logs por tipo de ação

**Exemplo de query otimizada**:
```sql
SELECT * FROM audit_logs 
WHERE action = 'DELETE' 
ORDER BY timestamp DESC;
```

## Exemplos de Uso

### Exemplo 1: Criar Log de Auditoria

```typescript
import AuditLog from '../models/AuditLog';

const auditLog = await AuditLog.create({
  userId: 1,
  action: 'UPDATE',
  entity: 'Usuario',
  entityId: 123,
  changes: {
    before: { nome: 'João' },
    after: { nome: 'João Silva' }
  },
  ip: '192.168.1.1',
  userAgent: 'Mozilla/5.0...',
  timestamp: new Date()
});
```

### Exemplo 2: Buscar Logs por Usuário

```typescript
import { container } from '../core/di';
import { TYPES } from '../core/di/types';
import { IAuditLogRepository } from '../infrastructure/repository/IAuditLogRepository';

const repository = container.resolve<IAuditLogRepository>(TYPES.IAuditLogRepository);
const logs = await repository.findByUsuario(1, 50);
```

### Exemplo 3: Buscar Logs por Entidade

```typescript
// Buscar todos os logs de uma entidade
const logs = await repository.findByEntity('Usuario');

// Buscar logs de uma entidade específica
const logs = await repository.findByEntity('Usuario', 123);
```

### Exemplo 4: Buscar Logs por Período

```typescript
const logs = await repository.findByPeriodo(
  new Date('2025-01-01'),
  new Date('2025-01-31'),
  1000
);
```

### Exemplo 5: Buscar Logs por Usuário e Período

```typescript
const logs = await repository.findByUsuarioAndPeriodo(
  1,
  new Date('2025-01-01'),
  new Date('2025-01-31')
);
```

### Exemplo 6: Buscar Logs por Ação

```typescript
const deleteLogs = await repository.findByAction('DELETE', 100);
```

## Estrutura do Campo `changes`

O campo `changes` armazena um objeto JSON com informações sobre mudanças:

**Para UPDATE**:
```json

  "before": {
    "nome": "João",
    "email": "joao@example.com"
  },
  "after": {
    "nome": "João Silva",
    "email": "joao.silva@example.com"
  }
}
```

**Para CREATE**:
```json
{
  "after": {
    "nome": "João Silva",
    "email": "joao.silva@example.com"
  }
}
```

**Para DELETE**:
```json
{
  "before": {
    "nome": "João Silva",
    "email": "joao.silva@example.com"
  }
}
```

## Performance

### Otimizações Implementadas

1. **Índices Compostos**: Para queries comuns (usuário + timestamp, entidade + entityId)
2. **Índices Simples**: Para queries por timestamp e ação
3. **Limites Padrão**: Evitar queries muito grandes
4. **Ordenação**: Sempre por timestamp DESC (mais recentes primeiro)

### Considerações

- **Volume de dados**: Tabela pode crescer rapidamente
- **Retenção**: Considerar política de retenção (T14.4)

## Considerações Importantes

### Segurança

- **Dados sensíveis**: Não armazenar senhas ou dados sensíveis no campo `changes`
- **IP e User Agent**: Úteis para segurança, mas podem ser falsificados
- **Integridade**: Logs não devem ser modificáveis após criação

### Performance

- **Volume**: Tabela pode crescer muito rapidamente
- **Índices**: Importantes para performance de consultas
- **Particionamento**: Considerar em produção para grandes volumes

### Compliance

- **LGPD/GDPR**: Logs podem conter dados pessoais
- **Retenção**: Definir política de retenção adequada
- **Acesso**: Controlar quem pode acessar logs de auditoria
