## Endpoints Implementados

### 1. GET /api/audit-logs

Lista logs de auditoria com filtros opcionais.

**Query Params**:
- `userId?: number` - Filtrar por usuário
- `entity?: string` - Filtrar por entidade
- `entityId?: number` - Filtrar por ID da entidade
- `action?: string` - Filtrar por ação (CREATE, UPDATE, DELETE, READ, LOGIN, LOGOUT)
- `startDate?: string` - Data de início (ISO date)
- `endDate?: string` - Data de fim (ISO date)
- `ip?: string` - Filtrar por IP
- `page?: number` - Número da página (padrão: 1)
- `limit?: number` - Limite por página (padrão: 10)

**Exemplo de Requisição**:
```http
GET /api/audit-logs?userId=1&entity=Usuario&action=UPDATE&startDate=2025-01-01&endDate=2025-01-31&page=1&limit=20
Authorization: Bearer <token>
```

**Exemplo de Resposta**:
```json
{
```

## Autorização

### Permissão Necessária

Todos os endpoints requerem a permissão `audit.read`.

**Middleware**:
- `authMiddleware` - Verifica autenticação
- `requirePermission('audit.read')` - Verifica permissão

**Exemplo de uso**:
```typescript
router.get('/', requirePermission('audit.read'), asyncHandler(async (req, res) => {
  await getAuditLogController().index(req, res);
}));
```

### Configuração de Permissão

A permissão `audit.read` deve ser:
1. Criada no banco de dados (tabela `permissoes`)
2. Atribuída a roles apropriados (ex: Admin, Auditor)
3. Verificada pelo middleware `requirePermission`

**Exemplo de criação**:
```sql
INSERT INTO permissoes (nome, descricao) VALUES 
('audit.read', 'Permite consultar logs de auditoria');
```

## Filtros e Paginação

### Filtros Suportados

**Filtros simples**:
- `userId` - Filtrar por usuário
- `entity` - Filtrar por entidade
- `entityId` - Filtrar por ID da entidade
- `action` - Filtrar por ação
- `ip` - Filtrar por IP

**Filtros de data**:
- `startDate` - Data de início (ISO date string)
- `endDate` - Data de fim (ISO date string)

**Filtros combinados**:
- Todos os filtros podem ser combinados
- Filtros são opcionais
- Apenas filtros fornecidos são aplicados

### Paginação

**Parâmetros**:
- `page` - Número da página (padrão: 1, 1-indexed)
- `limit` - Limite por página (padrão: 10)

**Resposta**:
```json
{
  "data": [...],
  "total": 150,
  "page": 1,
  "limit": 20,
  "totalPages": 8
}
```

**Exemplos**:
```http
# Primeira página, 10 registros
GET /api/audit-logs?page=1&limit=10

# Segunda página, 20 registros
GET /api/audit-logs?page=2&limit=20

# Primeira página, 50 registros
GET /api/audit-logs?page=1&limit=50
```

## Integração com Sistema Existente

### Middleware

**authMiddleware**:
- Verifica autenticação
- Adiciona `userId` ao `req`
- Aplicado em todas as rotas

**requirePermission**:
- Verifica permissão específica
- Lança `ForbiddenException` se não autorizado
- Aplicado em cada endpoint

**asyncHandler**:
- Captura erros assíncronos
- Passa para `errorHandler`
- Aplicado em todos os handlers

### Error Handling

**Erros tratados**:
- `NotFoundException` - Log não encontrado (404)
- `ForbiddenException` - Sem permissão (403)
- `UnauthorizedException` - Não autenticado (401)

**Formato de erro**:
```json
{
  "error": "Not Found",
  "message": "Log de auditoria com ID 123 não encontrado",
  "statusCode": 404
}
```

## Considerações Importantes

### Segurança

- **Autorização**: Todos os endpoints requerem `audit.read`
- **Autenticação**: Requer token JWT válido
- **Dados sensíveis**: Dados já sanitizados pelo AuditService
- **Rate Limiting**: Considerar rate limiting (futuro)

### Performance

- **Índices**: Usa índices criados no modelo AuditLog
- **Paginação**: Sempre usar paginação para grandes volumes
- **Limites**: Limitar `limit` máximo (ex: 100)
- **Cache**: Considerar cache para consultas frequentes (futuro)

### Compliance

- **Acesso**: Registrar consultas de logs (futuro)
- **Retenção**: Implementar política de retenção (T14.4)
