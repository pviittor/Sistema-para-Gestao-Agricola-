## Contexto Técnico

### Por que Authorization Service?

O Authorization Service centraliza toda a lógica de verificação de permissões e roles:

- **Centralização**: Toda lógica de autorização em um único lugar
- **Reutilização**: Usado por decorators, middleware e Application Services
- **Testabilidade**: Fácil de testar e mockar
- **Manutenibilidade**: Mudanças na lógica de autorização são centralizadas
- **Performance**: Base para implementação de cache (futuro)

### Estrutura de Dados

O sistema usa relacionamentos many-to-many:

- **UsuarioHasRole**: Relaciona usuários com roles (usuarioId, roleId)
- **RoleHasPermissao**: Relaciona roles com permissões (roleId, permissaoId)

**Fluxo de verificação**:
1. Buscar roles do usuário através de `UsuarioHasRole`
2. Para cada role, buscar permissões através de `RoleHasPermissao`
3. Verificar se a permissão específica está nas permissões do usuário

## Métodos Implementados

### `hasPermission(userId: number, permission: string): Promise<boolean>`

Verifica se o usuário tem uma permissão específica.

**Implementação**:
1. Verifica se usuário existe
2. Busca permissão por nome
3. Busca roles do usuário através de `UsuarioHasRole`
4. Busca permissões das roles através de `RoleHasPermissao`
5. Verifica se a permissão está nas permissões do usuário

**Exemplo de Uso**:
```typescript
const authService = container.resolve<IAuthorizationService>(TYPES.IAuthorizationService);
const canCreate = await authService.hasPermission(userId, 'usuario.create');
if (!canCreate) {
  throw new ForbiddenException('Permissão necessária');
}
```

**Casos de Retorno**:
- `true`: Usuário tem a permissão através de uma de suas roles
- `false`: Usuário não existe, permissão não existe, usuário não tem roles, ou usuário não tem a permissão

### `hasRole(userId: number, role: string): Promise<boolean>`

Verifica se o usuário tem uma role específica.

**Implementação**:
1. Verifica se usuário existe
2. Busca role por nome
3. Verifica se existe relacionamento `UsuarioHasRole` para o usuário e role

**Exemplo de Uso**:
```typescript
const isAdmin = await authService.hasRole(userId, 'ADMIN');
if (!isAdmin) {
  throw new ForbiddenException('Role ADMIN necessária');
}
```

**Casos de Retorno**:
- `true`: Usuário tem a role
- `false`: Usuário não existe, role não existe, ou usuário não tem a role

### `hasAnyRole(userId: number, roles: string[]): Promise<boolean>`

Verifica se o usuário tem pelo menos uma das roles especificadas (OR).

**Implementação**:
1. Verifica se usuário existe
2. Retorna `false` se array de roles está vazio
3. Busca todas as roles por nomes
4. Verifica se usuário tem pelo menos uma das roles através de `UsuarioHasRole`

**Exemplo de Uso**:
```typescript
const hasRole = await authService.hasAnyRole(userId, ['ADMIN', 'MANAGER']);
if (!hasRole) {
  throw new ForbiddenException('Role ADMIN ou MANAGER necessária');
}
```

**Casos de Retorno**:
- `true`: Usuário tem pelo menos uma das roles
- `false`: Usuário não existe, array vazio, nenhuma role existe, ou usuário não tem nenhuma das roles

### `hasAllRoles(userId: number, roles: string[]): Promise<boolean>`

Verifica se o usuário tem todas as roles especificadas (AND).

**Implementação**:
1. Verifica se usuário existe
2. Retorna `true` se array de roles está vazio (caso especial)
3. Busca todas as roles por nomes
4. Verifica se todas as roles existem (se não, retorna `false`)
5. Verifica se usuário tem todas as roles através de `UsuarioHasRole`

**Exemplo de Uso**:
```typescript
const hasAllRoles = await authService.hasAllRoles(userId, ['ADMIN', 'MANAGER']);
if (!hasAllRoles) {
  throw new ForbiddenException('Roles ADMIN e MANAGER necessárias');
}
```

**Casos de Retorno**:
- `true`: Usuário tem todas as roles (ou array vazio)
- `false`: Usuário não existe, alguma role não existe, ou usuário não tem todas as roles

## Exemplos de Uso

### Exemplo 1: Verificar permissão em decorator

```typescript
import { container } from '../core/di/container';
import { TYPES } from '../core/di/types';
import { IAuthorizationService } from '../core/authorization/IAuthorizationService';

export function RequirePermission(permission: string) {
  return function (target: any, propertyName: string, descriptor: PropertyDescriptor) {
    const originalMethod = descriptor.value;

    descriptor.value = async function (...args: any[]) {
      const authService = container.resolve<IAuthorizationService>(TYPES.IAuthorizationService);
      const userId = getUserIdFromContext(...args);

      const hasPermission = await authService.hasPermission(userId, permission);
      if (!hasPermission) {
        throw new ForbiddenException(`Permissão '${permission}' necessária`);
      }

      return await originalMethod.apply(this, args);
    };

    return descriptor;
  };
}
```

### Exemplo 2: Verificar role em middleware

```typescript
import { container } from '../core/di/container';
import { TYPES } from '../core/di/types';
import { IAuthorizationService } from '../core/authorization/IAuthorizationService';

export const requireRole = (role: string | string[]) => {
  return async (req: Request, res: Response, next: NextFunction): Promise<void> => {
    const authService = container.resolve<IAuthorizationService>(TYPES.IAuthorizationService);
    const userId = req.userId;

    const roles = Array.isArray(role) ? role : [role];
    const hasRole = await authService.hasAnyRole(userId, roles);
    
    if (!hasRole) {
      throw new ForbiddenException(`Role '${roles.join(' ou ')}' necessária`);
    }

    next();
  };
};
```

### Exemplo 3: Verificar permissão em Application Service

```typescript
@Injectable()
export class UsuarioApplicationService {
  constructor(
    @Inject(TYPES.IAuthorizationService) private authService: IAuthorizationService,
    @Inject(TYPES.IUsuarioRepository) private repository: IUsuarioRepository
  ) {}

  async delete(id: number): Promise<boolean> {
    // Verificar permissão manualmente (ou usar decorator)
    const hasPermission = await this.authService.hasPermission(
      this.getCurrentUserId(),
      'usuario.delete'
    );
    
    if (!hasPermission) {
      throw new ForbiddenException('Permissão para deletar usuários necessária');
    }

    // Continuar com a lógica de negócio...
    return await this.repository.delete(id);
  }
}
```

## Fluxo de Execução

### Fluxo: Verificar Permissão

```
1. hasPermission(userId, 'usuario.create')
   ↓
2. Verificar se usuário existe (usuarioRepository.findById)
   ↓
3. Buscar permissão por nome (permissaoRepository.findByNome)
   ↓
4. Buscar roles do usuário (UsuarioHasRole.findAll)
   ↓
5. Buscar permissões das roles (RoleHasPermissao.findAll)
   ↓
6. Verificar se permissão está nas permissões do usuário
   ↓
7. Retornar true/false
```

### Fluxo: Verificar Role

```
1. hasRole(userId, 'ADMIN')
   ↓
2. Verificar se usuário existe (usuarioRepository.findById)
   ↓
3. Buscar role por nome (roleRepository.findByNome)
   ↓
4. Verificar relacionamento (UsuarioHasRole.findOne)
   ↓
5. Retornar true/false
```

## Limitações e Considerações

### Dependência de Repositórios

O serviço depende dos repositórios estarem implementados e registrados no DI container. Se algum repositório não estiver disponível, o serviço lançará erro.

### Performance

O serviço executa múltiplas queries para verificar permissões. Para melhorar performance:

- Implementar cache de permissões (T12.4)
- Otimizar queries com joins
- Considerar buscar todas as permissões do usuário de uma vez

### Validação de Dados

O serviço valida:
- Existência de usuário
- Existência de role
- Existência de permissão

Se algum não existir, retorna `false` em vez de lançar exceção. Isso permite que o sistema continue funcionando mesmo com dados inconsistentes.
