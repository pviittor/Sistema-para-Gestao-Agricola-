## Ordem de Execução dos Decorators

A ordem dos decorators aplicada é consistente em todos os métodos:

1. **`@RequirePermission`** - Verifica autorização primeiro
2. **`@Transactional`** - Inicia transação (quando aplicável)
3. **`@Auditable`** - Registra auditoria após operação

**Exemplo**:
```typescript
@RequirePermission('financeiro.create')
@Transactional()
@Auditable('Financeiro')
async create(dto: CreateFinanceiroDto): Promise<FinanceiroResponseDto> {
  // Método executado
}
```

## Validação

### Como Validar

1. **Executar operações em cada service**:
   - Criar, atualizar e excluir registros
   - Verificar que logs são criados

2. **Verificar logs no banco**:
   ```sql
   SELECT 
     entity,
     action,
     COUNT(*) as total
   FROM audit_logs
   WHERE timestamp >= DATE_SUB(NOW(), INTERVAL 1 DAY)
   GROUP BY entity, action
   ORDER BY entity, action;
   ```

3. **Validar campos**:
   - ✅ userId está correto
   - ✅ action está correto (CREATE, UPDATE, DELETE)
   - ✅ entity está correto
   - ✅ entityId está correto
   - ✅ changes contém dados corretos
   - ✅ ip e userAgent estão presentes (quando Request disponível)
   - ✅ timestamp está correto

## Integridade dos Logs

### Validações

**Campos obrigatórios**:
- ✅ userId (pode ser 0 se não autenticado)
- ✅ action (CREATE, UPDATE, DELETE)
- ✅ entity (nome da entidade)
- ✅ entityId (ID da entidade)
- ✅ timestamp (data/hora da ação)

**Campos opcionais**:
- changes (pode ser null para algumas ações)
- ip (pode ser null se Request não disponível)
- userAgent (pode ser null se Request não disponível)

**Validações de integridade**:
- ✅ entityId corresponde a registro existente (no momento da criação do log)
- ✅ changes.before existe para UPDATE/DELETE
- ✅ changes.after existe para CREATE/UPDATE
- ✅ changes.changes existe para UPDATE (com mudanças)

## Considerações Importantes

### Performance

- **Overhead mínimo**: Decorator adiciona pouco overhead
- **Assíncrono**: Não bloqueia operações
- **Não crítico**: Erros não interrompem fluxo principal

### Segurança

- **Dados sensíveis**: Sanitizados automaticamente pelo AuditService
- **IP e UserAgent**: Capturados automaticamente quando Request disponível
- **Integridade**: Logs não são modificáveis após criação

### Manutenção

- **Código limpo**: Decorator mantém código simples
- **Fácil de aplicar**: Basta adicionar `@Auditable('Entity')`
- **Consistente**: Mesmo padrão em todos os métodos

### Padrão para Novos Services

Ao criar novos Application Services:

1. Importar `Auditable`:
   ```typescript
   import { Auditable } from '../../../core/audit';
   ```

2. Aplicar em métodos create, update, delete:
   ```typescript
   @RequirePermission('entity.create')
   @Transactional()
   @Auditable('Entity')
   async create(dto: CreateEntityDto): Promise<EntityResponseDto> {
     // ...
   }
   ```
