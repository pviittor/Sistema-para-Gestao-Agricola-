# T13.2 - AuditService

## Funcionalidades Implementadas

### 1. Registro de Criação

Registra quando uma entidade é criada.

```typescript
await auditService.logCreate('Usuario', 123, {
  nome: 'João',
  email: 'joao@example.com'
}, req);
```

**O que é registrado**:
- userId (do RequestContext)
- action: 'CREATE'
- entity: 'Usuario'
- entityId: 123
- changes.after: dados criados (sanitizados)
- ip: IP do cliente
- userAgent: User agent do cliente
- timestamp: data/hora atual

### 2. Registro de Atualização

Registra quando uma entidade é atualizada, incluindo mudanças detalhadas.

```typescript
await auditService.logUpdate(
  'Usuario',
  123,
  { nome: 'João', email: 'joao@example.com' }, // before
  { nome: 'João Silva', email: 'joao.silva@example.com' }, // after
  req
);
```

**O que é registrado**:
- userId (do RequestContext)
- action: 'UPDATE'
- entity: 'Usuario'
- entityId: 123
- changes.before: estado anterior (sanitizado)
- changes.after: estado novo (sanitizado)
- changes.changes: apenas propriedades que mudaram
- ip: IP do cliente
- userAgent: User agent do cliente
- timestamp: data/hora atual

**Cálculo de mudanças**:
- Compara before e after
- Identifica propriedades que mudaram
- Identifica propriedades removidas
- Armazena apenas mudanças relevantes

### 3. Registro de Exclusão

Registra quando uma entidade é excluída, preservando dados anteriores.

```typescript
await auditService.logDelete('Usuario', 123, {
  nome: 'João',
  email: 'joao@example.com'
}, req);
```

**O que é registrado**:
- userId (do RequestContext)
- action: 'DELETE'
- entity: 'Usuario'
- entityId: 123
- changes.before: dados excluídos (sanitizados)
- ip: IP do cliente
- userAgent: User agent do cliente
- timestamp: data/hora atual

### 4. Registro de Leitura (Opcional)

Registra quando uma entidade é lida (para auditoria de acesso).

```typescript
await auditService.logRead('Usuario', 123, req);
```

**O que é registrado**:
- userId (do RequestContext)
- action: 'READ'
- entity: 'Usuario'
- entityId: 123
- changes: null
- ip: IP do cliente
- userAgent: User agent do cliente
- timestamp: data/hora atual

### 5. Registro de Login

Registra quando um usuário faz login.

```typescript
await auditService.logLogin(123, req);
```

**O que é registrado**:
- userId: 123
- action: 'LOGIN'
- entity: 'Usuario'
- entityId: 123
- changes: null
- ip: IP do cliente
- userAgent: User agent do cliente
- timestamp: data/hora atual

### 6. Registro de Logout

Registra quando um usuário faz logout.

```typescript

```

**O que é registrado**:

- action: 'LOGOUT'
- entity: 'Usuario'
- entityId: 123

## Captura Automática de Informações

### 1. UserId

**Ordem de prioridade**:
1. `req.context.getUserId()` (RequestContext)
2. `req.userId` (definido pelo authMiddleware)
3. `0` (se não houver usuário autenticado)

**Exemplo**:
```typescript
// RequestContext tem prioridade
const context = new RequestContext();
context.setUserId(1);
req.context = context;
// userId será 1

// Fallback para req.userId
req.userId = 2;
// userId será 2

// Sem autenticação
// userId será 0
```

### 2. IP Address

**Ordem de prioridade**:
1. `req.ip` (definido pelo Express)
2. `req.headers['x-forwarded-for']` (primeiro IP da cadeia)
3. `req.headers['x-real-ip']`
4. `req.socket.remoteAddress`

**Exemplo**:
```typescript
// Com proxy/load balancer
req.headers['x-forwarded-for'] = '192.168.1.1, 10.0.0.1';
// IP será '192.168.1.1' (primeiro da cadeia)

// Sem proxy
req.ip = '192.168.1.1';
// IP será '192.168.1.1'
```

### 3. User Agent

**Fonte**:
- `req.headers['user-agent']`

**Exemplo**:
```typescript
req.headers['user-agent'] = 'Mozilla/5.0 (Windows NT 10.0; Win64; x64)';
// userAgent será 'Mozilla/5.0...'
```

## Sanitização de Dados Sensíveis

### Campos Sanitizados

O serviço remove automaticamente dados sensíveis antes de armazenar:

- `senha` / `password`
- `token`
- `apiKey`
- `secret` / `secretKey`
- `accessToken`
- `refreshToken`

**Comportamento**:
- Campos sensíveis são substituídos por `[REDACTED]`
- Sanitização é recursiva (objetos aninhados)
- Funciona com arrays e objetos

**Exemplo**:
```typescript
const data = {
  nome: 'João',
  senha: 'senha123',
  apiKey: 'key123',
  config: {
    secret: 'secret123'
  }
};

// Após sanitização:
{
  nome: 'João',
  senha: '[REDACTED]',
  apiKey: '[REDACTED]',
  config: {
    secret: '[REDACTED]'
  }
}
```

## Cálculo de Mudanças

### Algoritmo

1. Compara propriedades de `after` com `before`
2. Identifica propriedades que mudaram
3. Identifica propriedades removidas
4. Retorna apenas mudanças relevantes

**Exemplo**:
```typescript
const before = {
  nome: 'João',
  email: 'joao@example.com',
  idade: 30
};

const after = {
  nome: 'João Silva',
  email: 'joao@example.com',
  idade: 31
};

// Mudanças calculadas:
{
  nome: { from: 'João', to: 'João Silva' },
  idade: { from: 30, to: 31 }
}
```

## Integração com Logger

O serviço integra com o sistema de logging existente:

**Níveis de log**:
- `info`: CREATE, UPDATE, DELETE, LOGIN, LOGOUT
- `debug`: READ (opcional, menos crítico)
- `error`: Falhas ao registrar logs (não interrompe fluxo)

**Metadados incluídos**:
- entity
- entityId
- action
- userId
- changesCount (para UPDATE)

---

## Tratamento de Erros

### Estratégia

**Não lança erros**: O serviço não lança erros para não interromper o fluxo principal da aplicação.

**Loga erros**: Todos os erros são logados usando `logger.error()`.

**Exemplo**:
```typescript
try {
  await auditService.logCreate('Usuario', 123, data, req);
  // Continua normalmente mesmo se o log falhar
} catch (error) {
  // Não será lançado, erro foi tratado internamente
}
```

**Motivo**:
- Auditoria não deve interromper operações críticas
- Erros são logados para monitoramento
- Sistema pode continuar funcionando mesmo com problemas de auditoria

## Exemplos de Uso

### Exemplo 1: Em Application Service

```typescript
import { Injectable, Inject } from '../../core/di';
import { TYPES } from '../../core/di/types';
import { IAuditService } from '../../core/audit/IAuditService';
import { Request } from 'express';

@Injectable()
export class UsuarioApplicationService {
  constructor(
    @Inject(TYPES.IAuditService)
    private auditService: IAuditService,
    @Inject(TYPES.IUsuarioRepository)
    private usuarioRepository: IUsuarioRepository
  ) {}

  async create(dto: CreateUsuarioDto, req?: Request): Promise<UsuarioDto> {
    const usuario = await this.usuarioRepository.create(dto);
    
    // Registrar auditoria
    await this.auditService.logCreate('Usuario', usuario.id, dto, req);
    
    return this.toDto(usuario);
  }

  async update(id: number, dto: UpdateUsuarioDto, req?: Request): Promise<UsuarioDto> {
    const before = await this.usuarioRepository.findById(id);
    const usuario = await this.usuarioRepository.update(id, dto);
    
    // Registrar auditoria
    await this.auditService.logUpdate(
      'Usuario',
      id,
      before,
      usuario,
      req
    );
    
    return this.toDto(usuario);
  }

  async delete(id: number, req?: Request): Promise<boolean> {
    const usuario = await this.usuarioRepository.findById(id);
    const deleted = await this.usuarioRepository.delete(id);
    
    if (deleted && usuario) {
      // Registrar auditoria
      await this.auditService.logDelete('Usuario', id, usuario, req);
    }
    
    return deleted;
  }
}
```

### Exemplo 2: Em Controller

```typescript
import { Request, Response } from 'express';
import { container } from '../core/di';
import { TYPES } from '../core/di/types';
import { IAuditService } from '../core/audit/IAuditService';

export async function login(req: Request, res: Response) {
  const { email, senha } = req.body;
  
  const authService = container.resolve<IAuthService>(TYPES.IAuthService);
  const auditService = container.resolve<IAuditService>(TYPES.IAuditService);
  
  const result = await authService.login(email, senha);
  
  // Registrar auditoria de login
  await auditService.logLogin(result.user.id, req);
  
  res.json(result);
}
```

## Considerações Importantes

### Performance

- **Assíncrono**: Todas as operações são assíncronas
- **Não bloqueante**: Erros não interrompem fluxo principal

- **Sanitização**: Dados sensíveis são removidos automaticamente

- **Volume**: Considerar fila assíncrona para grandes volumes (futuro)
