# T11.1 - Decorators de Autorização - Documentação de Implementação

## Resumo Executivo

Implementação de decorators declarativos para autorização, permitindo verificação automática de permissões e roles em métodos de Application Services. Os decorators interceptam chamadas de métodos, verificam permissões/roles através do AuthorizationService, e lançam ForbiddenException se o usuário não tiver acesso. Esta implementação facilita manutenção, reduz código duplicado e torna a autorização declarativa e reutilizável.

## Decisões de Implementação

### Abordagem Escolhida

**Method Decorator Pattern**:
- Usa TypeScript method decorators para interceptar chamadas de métodos
- Substitui o método original por um wrapper que verifica permissões/roles
- Mantém contexto (`this`) e argumentos do método original

**Obtenção de userId**:
- Tenta obter userId de múltiplas fontes (RequestContext via DI, req.context, req.userId)
- Usa helper `getUserIdFromContext` para centralizar lógica
- Lança ForbiddenException se userId não estiver disponível

**Integração com AuthorizationService**:
- Usa `IAuthorizationService` resolvido do DI container
- Delega verificação de permissões/roles para AuthorizationService
- Não implementa lógica de autorização diretamente

**Simplicidade**:
- Decorators simples e fáceis de usar
- Não requer mudanças na assinatura dos métodos
- Transparente para o código que usa o método

### 1. `src/core/authorization/IAuthorizationService.ts`

Interface que define o contrato para Authorization Service:

```typescript
export interface IAuthorizationService {
  hasPermission(userId: number, permission: string): Promise<boolean>;
  hasRole(userId: number, role: string): Promise<boolean>;
  hasAnyRole(userId: number, roles: string[]): Promise<boolean>;
  hasAllRoles(userId: number, roles: string[]): Promise<boolean>;
}
```

**Características**:
- Define métodos para verificação de permissões e roles
- Interface genérica que pode ser implementada de diferentes formas
- Preparada para integração com sistema de permissões existente

**Nota**: A implementação do `AuthorizationService` será feita na tarefa T11.3. Por enquanto, apenas a interface foi criada para que os decorators possam ser implementados.

### 2. `src/core/authorization/RequirePermission.ts`

Decorator `@RequirePermission` para verificar permissão específica:

```typescript
export function RequirePermission(permission: string) {
  return function (target: any, propertyName: string, descriptor: PropertyDescriptor) {
    const originalMethod = descriptor.value;
    
    descriptor.value = async function (...args: any[]) {
      const authService = container.resolve<IAuthorizationService>(TYPES.IAuthorizationService);
      const userId = getUserIdFromContext(...args);
      
      if (!userId) {
        throw new ForbiddenException('Usuário não autenticado');
      }
      
      const hasPermission = await authService.hasPermission(userId, permission);
      if (!hasPermission) {
        throw new ForbiddenException(`Permissão '${permission}' necessária`);
      }
      
      return await originalMethod.apply(this, args);
    };
    
    return descriptor;
  };
}
```

**Características**:
- Verifica permissão antes de executar método
- Lança ForbiddenException se não tiver permissão
- Obtém userId do contexto automaticamente

### 3. `src/core/authorization/RequireRole.ts`

Decorator `@RequireRole` para verificar role(s):

```typescript
export function RequireRole(role: string | string[]) {
  return function (target: any, propertyName: string, descriptor: PropertyDescriptor) {
    const roles = Array.isArray(role) ? role : [role];
    
    descriptor.value = async function (...args: any[]) {
      const authService = container.resolve<IAuthorizationService>(TYPES.IAuthorizationService);
      const userId = getUserIdFromContext(...args);
      
      if (!userId) {
        throw new ForbiddenException('Usuário não autenticado');
      }
      
      const hasRole = await authService.hasAnyRole(userId, roles);
      if (!hasRole) {
        throw new ForbiddenException(`Role '${roles.join(' ou ')}' necessária`);
      }
      
      return await originalMethod.apply(this, args);
    };
  };
}
```

**Características**:
- Suporta role única ou array de roles (OR)
- Verifica se usuário tem pelo menos uma das roles
- Lança ForbiddenException se não tiver role

### 4. `src/core/authorization/RequireAnyPermission.ts`

Decorator `@RequireAnyPermission` para verificar múltiplas permissões (OR):

```typescript
export function RequireAnyPermission(permissions: string[]) {
  return function (target: any, propertyName: string, descriptor: PropertyDescriptor) {
    descriptor.value = async function (...args: any[]) {
      const authService = container.resolve<IAuthorizationService>(TYPES.IAuthorizationService);
      const userId = getUserIdFromContext(...args);
      
      if (!userId) {
        throw new ForbiddenException('Usuário não autenticado');
      }
      
      const hasAnyPermission = await Promise.all(
        permissions.map(permission => authService.hasPermission(userId!, permission))
      ).then(results => results.some(result => result === true));
      
      if (!hasAnyPermission) {
        throw new ForbiddenException(`Pelo menos uma das permissões é necessária: ${permissions.join(', ')}`);
      }
      
      return await originalMethod.apply(this, args);
    };
  };
}
```

**Características**:
- Verifica se usuário tem pelo menos uma das permissões (OR)
- Executa verificações em paralelo para melhor performance
- Lança ForbiddenException se não tiver nenhuma permissão

### 5. `src/core/authorization/RequireAllPermissions.ts`

Decorator `@RequireAllPermissions` para verificar múltiplas permissões (AND):

```typescript
export function RequireAllPermissions(permissions: string[]) {
  return function (target: any, propertyName: string, descriptor: PropertyDescriptor) {
    descriptor.value = async function (...args: any[]) {
      const authService = container.resolve<IAuthorizationService>(TYPES.IAuthorizationService);
      const userId = getUserIdFromContext(...args);
      
      if (!userId) {
        throw new ForbiddenException('Usuário não autenticado');
      }
      
      const permissionChecks = await Promise.all(
        permissions.map(permission => authService.hasPermission(userId!, permission))
      );
      
      const hasAllPermissions = permissionChecks.every(result => result === true);
      
      if (!hasAllPermissions) {
        const missingPermissions = permissions.filter((_, index) => !permissionChecks[index]);
        throw new ForbiddenException(
          `Todas as seguintes permissões são necessárias: ${permissions.join(', ')}. Faltando: ${missingPermissions.join(', ')}`
        );
      }
      
      return await originalMethod.apply(this, args);
    };
  };
}
```

**Características**:
- Verifica se usuário tem todas as permissões (AND)
- Identifica quais permissões estão faltando na mensagem de erro
- Executa verificações em paralelo para melhor performance

## Como Funciona

### Fluxo de Execução

```
1. Método decorado é chamado
   ↓
2. Decorator intercepta a chamada
   ↓
3. Decorator obtém userId do contexto
   ↓
4. Decorator resolve IAuthorizationService do container
   ↓
5. Decorator verifica permissão/role
   ↓
6a. Se tiver permissão: executa método original
6b. Se não tiver: lança ForbiddenException
   ↓
7. Retorna resultado (ou lança erro)
```

### Exemplo de Uso

**Antes (sem decorator)**:
```typescript
@Injectable()
export class UsuarioApplicationService {
  constructor(
    @Inject(TYPES.IUsuarioRepository)
    private repository: IUsuarioRepository,
    @Inject(TYPES.IAuthorizationService)
    private authService: IAuthorizationService
  ) {}

  async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
    const userId = req.context?.getUserId();
    if (!userId) {
      throw new ForbiddenException('Usuário não autenticado');
    }

    const hasPermission = await this.authService.hasPermission(userId, 'usuario.create');
    if (!hasPermission) {
      throw new ForbiddenException('Permissão necessária');
    }

    // Lógica de criação
    // ...
  }
}
```

**Depois (com decorator)**:
```typescript
@Injectable()

  constructor(
    @Inject(TYPES.IUsuarioRepository)
    private repository: IUsuarioRepository
  ) {}

  @RequirePermission('usuario.create')
  async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
    // Método executado apenas se usuário tiver permissão 'usuario.create'
    // Lógica de criação
    // ...
  }
}
```

**Benefício**: Código mais limpo, sem necessidade de injetar `IAuthorizationService` e fazer verificações manuais.

### @RequirePermission

Verifica se usuário tem uma permissão específica:

```typescript

async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
  // Método executado apenas se tiver permissão 'usuario.create'

  // Método executado apenas se tiver permissão 'usuario.delete'

```

### @RequireRole

Verifica se usuário tem uma ou mais roles:

```typescript
@RequireRole('ADMIN')
async delete(id: number): Promise<boolean> {
  // Método executado apenas se tiver role 'ADMIN'
}

@RequireRole(['ADMIN', 'MANAGER'])
async update(id: number, dto: UpdateDto): Promise<ResponseDto> {
  // Método executado se tiver role 'ADMIN' OU 'MANAGER'

```

### @RequireAnyPermission

Verifica se usuário tem pelo menos uma das permissões (OR):


## Integração com Application Services

### Exemplo Completo

```typescript
import { Injectable, Inject } from '../../../core/di';
import { TYPES } from '../../../core/di/types';
import { RequirePermission, RequireRole } from '../../../core/authorization';
import { IUsuarioRepository } from '../../../infrastructure/repository/IUsuarioRepository';
import { CreateUsuarioDto } from '../../dto/usuario/CreateUsuarioDto';
import { UpdateUsuarioDto } from '../../dto/usuario/UpdateUsuarioDto';
import { UsuarioResponseDto } from '../../dto/usuario/UsuarioResponseDto';

@Injectable()
export class UsuarioApplicationService {
  constructor(
    @Inject(TYPES.IUsuarioRepository)
    private repository: IUsuarioRepository
  ) {}

  @RequirePermission('usuario.create')
  async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
    // Apenas usuários com permissão 'usuario.create' podem criar
    const entity = await this.mapper.toEntity(dto);
    const created = await this.repository.create(entity as any);
    return this.mapper.toDto(created);
  }

  @RequirePermission('usuario.read')
  async getById(id: number): Promise<UsuarioResponseDto | null> {
    // Apenas usuários com permissão 'usuario.read' podem ler
    const entity = await this.repository.findById(id);
    return entity ? this.mapper.toDto(entity) : null;
  }

  @RequirePermission('usuario.update')
  async update(id: number, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
    // Apenas usuários com permissão 'usuario.update' podem atualizar
    const entity = await this.mapper.toEntity(dto);
    const updated = await this.repository.update(id, entity as any);
    return this.mapper.toDto(updated);
  }

  @RequireRole('ADMIN')
  @RequirePermission('usuario.delete')
  async delete(id: number): Promise<boolean> {
    // Apenas ADMINs com permissão 'usuario.delete' podem deletar
    return await this.repository.delete(id);
  }
}
```

## Limitações e Considerações

### Limitação: AuthorizationService Não Implementado

**Situação Atual**:
- A interface `IAuthorizationService` foi criada
- Mas a implementação do `AuthorizationService` ainda não existe
- Os decorators dependem do `AuthorizationService` estar registrado no DI container

**Solução**:
- A implementação do `AuthorizationService` será feita na tarefa T11.3
- Por enquanto, os decorators estão prontos e funcionarão assim que o service for implementado
- É possível criar um mock do `AuthorizationService` para testes

### Limitação: userId Pode Não Estar Disponível

**Situação Atual**:
- Decorators tentam obter userId de múltiplas fontes
- Mas se nenhuma fonte estiver disponível, lança ForbiddenException

**Solução**:
- Garantir que `requestContextMiddleware` seja executado antes dos decorators
- Garantir que `authMiddleware` defina `req.userId`
- Em contextos não-HTTP, pode ser necessário passar userId explicitamente

### Limitação: Performance

**Situação Atual**:
- Cada verificação de permissão faz uma chamada ao `AuthorizationService`
- Múltiplas verificações podem ser lentas

**Solução Futura**:
- Implementar cache de permissões no `AuthorizationService` (T12.4)
- Otimizar queries de autorização
- Considerar verificação em batch para múltiplas permissões

## Testes Unitários

### Estrutura de Testes

Os testes verificam:
1. **Interceptação**: Decorator intercepta chamada do método
2. **Verificação**: Verificação de permissão/role é executada
3. **Permissão concedida**: Método é executado quando tem permissão
4. **Permissão negada**: ForbiddenException é lançada quando não tem permissão
5. **Argumentos**: Argumentos são passados corretamente
6. **Contexto**: Contexto (`this`) é mantido
7. **Assíncrono**: Suporta métodos assíncronos
8. **Validação**: Valida que é aplicado apenas a métodos

### Exemplo de Teste

```typescript

  const result = await service.testMethod();
```
