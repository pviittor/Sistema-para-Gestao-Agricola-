## Decisões de Implementação

### Estrutura do Middleware

O ErrorHandler segue o padrão do Express para middlewares de erro:
- Assinatura: `(err, req, res, next)`
- Deve ser o último middleware adicionado
- Captura exceções customizadas e genéricas

### Formato de Resposta Padronizado

Todas as respostas de erro seguem o mesmo formato:

```typescript
{
  success: false,
  error: {
    code: string,        // Código de erro único
    message: string,     // Mensagem descritiva
    details?: any        // Detalhes adicionais (opcional)
  },
  timestamp: string,     // ISO 8601
  path: string,          // Caminho da requisição
  requestId?: string     // ID da requisição (opcional)
}
```

### Tratamento de Erros

1. **Exceções Customizadas** (BaseException):
   - StatusCode da exceção
   - Código e mensagem da exceção
   - Detalhes quando disponíveis

2. **Erros Genéricos**:
   - StatusCode 500
   - Código 'INTERNAL_ERROR'
   - Stack trace apenas em desenvolvimento

## Implementação Detalhada

### ErrorHandler Middleware

```typescript
export const errorHandler = (
  err: Error,
  req: Request,
  res: Response,
  next: NextFunction
): void => {
  // Verificar se já foi enviada resposta
  if (res.headersSent) {
    return next(err);
  }

  // Exceção customizada
  if (err instanceof BaseException) {
    const response: ErrorResponse = {
      success: false,
      error: {
        code: err.code,
        message: err.message,
        ...(err.details && { details: err.details }),
      },
      timestamp: new Date().toISOString(),
      path: req.path,
    };

    res.status(err.statusCode).json(response);
    return;
  }

  // Erro genérico
  const response: ErrorResponse = {
    success: false,
    error: {
      code: 'INTERNAL_ERROR',
      message: process.env.NODE_ENV === 'production'
        ? 'Erro interno do servidor'
        : err.message,
    },
    timestamp: new Date().toISOString(),
    path: req.path,
  };

  res.status(500).json(response);
};
```

### AsyncHandler

Wrapper para rotas assíncronas que captura erros automaticamente:

```typescript
export const asyncHandler = (
  fn: (req: Request, res: Response, next: NextFunction) => Promise<any>
) => {
  return (req: Request, res: Response, next: NextFunction): void => {
    Promise.resolve(fn(req, res, next)).catch(next);
  };
};
```

**Uso**:
```typescript
router.get('/users', asyncHandler(async (req, res) => {
  const users = await userService.findAll();
  res.json(users);
}));
```

## Exemplos de Uso

### Exemplo 1: Rota com BusinessException

```typescript
import { asyncHandler } from '../middleware/errorHandler';
import { BusinessException } from '../core/exceptions';

router.post('/transfer', asyncHandler(async (req, res) => {
  const { saldo, valor } = req.body;

  if (saldo < valor) {
    throw new BusinessException(
      'Saldo insuficiente',
      'INSUFFICIENT_BALANCE',
      { saldo, valor }
    );
  }

  // Processar transferência...
  res.json({ success: true });
}));
```

## Mapeamento de Exceções para HTTP

| Exceção | Status Code | Código Padrão | Quando Usar |
|---------|-------------|---------------|-------------|
| `BusinessException` | 400 | `BUSINESS_ERROR` | Regra de negócio violada |
| `ValidationException` | 400 | `VALIDATION_ERROR` | Dados inválidos |
| `UnauthorizedException` | 401 | `UNAUTHORIZED` | Não autenticado |
| `ForbiddenException` | 403 | `FORBIDDEN` | Sem permissão |
| `NotFoundException` | 404 | `NOT_FOUND` | Recurso não encontrado |
| Erro genérico | 500 | `INTERNAL_ERROR` | Erro inesperado |

## Integração com Express

O middleware deve ser adicionado **por último** no Express app:

```typescript
import { errorHandler } from './middleware/errorHandler';

const app = express();

// Outros middlewares...
app.use(cors());
app.use(express.json());
app.use('/api', routes);

// ErrorHandler DEVE ser o último
app.use(errorHandler);
```

**Importante**: Se o ErrorHandler não for o último middleware, erros podem não ser capturados corretamente.

## Boas Práticas

### 1. Sempre Use asyncHandler para Rotas Assíncronas

```typescript
// ✅ Bom
router.get('/users', asyncHandler(async (req, res) => {
  const users = await userService.findAll();
  res.json(users);
}));

// ❌ Errado - Erros não serão capturados
router.get('/users', async (req, res) => {
  const users = await userService.findAll();
  res.json(users);
});
```

### 2. Use Exceções Customizadas

```typescript
// ✅ Bom
if (!usuario) {
  throw new NotFoundException('Usuário', id);
}

// ⚠️ Evitar
if (!usuario) {
  res.status(404).json({ error: 'Usuário não encontrado' });
}
```

### 3. Forneça Detalhes Úteis

```typescript
// ✅ Bom
throw new BusinessException(
  'Saldo insuficiente',
  'INSUFFICIENT_BALANCE',
  { saldo: 100, valor: 200 }
);

// ⚠️ Evitar
throw new BusinessException('Saldo insuficiente');
```

### 4. Não Trate Erros Manualmente

```typescript
// ✅ Bom - Deixe o ErrorHandler tratar
router.get('/data', asyncHandler(async (req, res) => {
  const data = await service.getData();
  res.json(data);
}));

// ❌ Errado - Tratamento manual
router.get('/data', async (req, res) => {
  try {
    const data = await service.getData();
    res.json(data);
  } catch (error) {
    res.status(500).json({ error: 'Erro' });
  }
});
```

## Troubleshooting

### Problema: Erro não está sendo capturado

**Sintomas**: Erro retorna resposta padrão do Express

**Solução**:
1. Verificar se `errorHandler` é o último middleware
2. Verificar se rota usa `asyncHandler` para funções assíncronas
3. Verificar se erro está sendo lançado (não apenas retornado)

### Problema: Stack trace aparecendo em produção

**Sintomas**: Detalhes de erro expostos em produção

**Solução**:
1. Verificar se `NODE_ENV=production` está configurado
2. Verificar se condição de ambiente está funcionando

### Problema: Resposta não está no formato esperado

**Sintomas**: Formato de resposta diferente do padrão

**Solução**:
1. Verificar se está usando exceções customizadas
2. Verificar se ErrorHandler está sendo executado
3. Verificar se não há outro middleware interferindo
