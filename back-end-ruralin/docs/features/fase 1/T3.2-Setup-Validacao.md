## Decisões de Implementação

### Abordagem Escolhida

**class-validator + class-transformer**: Escolhido por ser:
- ✅ Padrão da indústria para validação em TypeScript
- ✅ Suporte completo a decorators
- ✅ Integração fácil com Express
- ✅ Mensagens de erro customizáveis
- ✅ Validação de objetos aninhados
- ✅ Conversão automática de tipos

**Estrutura de DTOs**: Organização hierárquica:
- `BaseDto`: Classe base abstrata
- `CreateDto`: Base para DTOs de criação
- `UpdateDto`: Base para DTOs de atualização (campos opcionais)

- `validateDto()`: Validação de body
- `validateQuery()`: Validação de query parameters
- `validateParams()`: Validação de route parameters

## Implementação Detalhada

### Estrutura de DTOs

#### BaseDto

```typescript
export abstract class BaseDto {}
```

Classe base abstrata que serve como ponto de partida para todos os DTOs.

#### CreateDto

```typescript
export abstract class CreateDto extends BaseDto {}
```

Classe base para DTOs de criação. Todos os campos são obrigatórios por padrão.

#### UpdateDto

```typescript
export abstract class UpdateDto extends BaseDto {
  // Todos os campos são opcionais por padrão
}
```

Classe base para DTOs de atualização. Permite atualizações parciais.

### Middleware de Validação

#### validateDto()

Valida o body da requisição contra um DTO:

```typescript
export function validateDto(
  dtoClass: new () => any,
  options?: {
    whitelist?: boolean;
    forbidNonWhitelisted?: boolean;
    transform?: boolean;
    validateNested?: boolean;
  }
)
```

**Funcionalidades**:
- Converte `req.body` em instância do DTO usando `plainToInstance`
- Valida usando `class-validator`
- Formata erros de validação em formato legível
- Lança `ValidationException` se houver erros
- Substitui `req.body` pela instância validada

#### validateQuery()

Valida query parameters:

```typescript
export function validateQuery(
  dtoClass: new () => any,
  options?: ValidationOptions
)
```

Similar ao `validateDto`, mas valida `req.query`.

#### validateParams()

Valida route parameters:

```typescript
export function validateParams(
  dtoClass: new () => any,
  options?: ValidationOptions
)
```

Similar ao `validateDto`, mas valida `req.params`.

### Formatação de Erros

A função `formatValidationErrors()` converte erros do `class-validator` em formato legível:

```typescript
[
  {
    field: 'email',
    message: 'Email deve ser um email válido',
    value: 'invalid-email',
    constraints: {
      isEmail: 'Email deve ser um email válido'
    }
  }
]
```

## Exemplos de Uso

### Exemplo 1: DTO de Criação

```typescript
import { IsString, IsEmail, IsNotEmpty, MinLength } from 'class-validator';
import { CreateDto } from '../application/dto';

export class CreateUsuarioDto extends CreateDto {
  @IsString({ message: 'Nome deve ser uma string' })
  @IsNotEmpty({ message: 'Nome é obrigatório' })
  nome!: string;

  @IsEmail({}, { message: 'Email deve ser um email válido' })
  @IsNotEmpty({ message: 'Email é obrigatório' })
  email!: string;

  @IsString({ message: 'Senha deve ser uma string' })
  @IsNotEmpty({ message: 'Senha é obrigatória' })
  @MinLength(8, { message: 'Senha deve ter no mínimo 8 caracteres' })
  senha!: string;
}
```

### Exemplo 2: Uso em Rotas

```typescript
import { Router } from 'express';
import { validateDto } from '../middleware/validation';
import { CreateUsuarioDto } from '../application/dto/usuario/CreateUsuarioDto';

const router = Router();

router.post('/usuarios', validateDto(CreateUsuarioDto), async (req, res) => {
  // req.body agora é uma instância validada de CreateUsuarioDto
  const dto = req.body as CreateUsuarioDto;
  
  // Criar usuário...
  res.status(201).json({ success: true });
});
```

### Exemplo 3: DTO de Atualização

```typescript
import { IsString, IsEmail, IsOptional } from 'class-validator';
import { UpdateDto } from '../application/dto';

export class UpdateUsuarioDto extends UpdateDto {
  @IsString({ message: 'Nome deve ser uma string' })
  @IsOptional()
  nome?: string;

  @IsEmail({}, { message: 'Email deve ser um email válido' })
  @IsOptional()
  email?: string;
}
```

### Exemplo 4: Validação de Query Parameters

```typescript
import { IsInt, IsPositive, IsOptional } from 'class-validator';

export class ListUsuarioQueryDto {
  @IsInt({ message: 'Página deve ser um número inteiro' })
  @IsPositive({ message: 'Página deve ser um número positivo' })
  @IsOptional()
  page?: number;

  @IsInt({ message: 'Limite deve ser um número inteiro' })
  @IsPositive({ message: 'Limite deve ser um número positivo' })
  @IsOptional()
  limit?: number;
}

// Uso em rota
router.get('/usuarios', validateQuery(ListUsuarioQueryDto), async (req, res) => {
  const query = req.query as ListUsuarioQueryDto;
  const page = query.page || 1;
  const limit = query.limit || 10;
  // ...
});
```

### Exemplo 5: Validação de Route Parameters

```typescript
import { IsInt, IsPositive } from 'class-validator';

export class IdParamDto {
  @IsInt({ message: 'ID deve ser um número inteiro' })
  @IsPositive({ message: 'ID deve ser um número positivo' })
  id!: number;
}

// Uso em rota
router.get('/usuarios/:id', validateParams(IdParamDto), async (req, res) => {
  const params = req.params as IdParamDto;
  const id = params.id; // number (convertido automaticamente)
  // ...
});
```

### Exemplo 6: Múltiplas Validações

```typescript
router.put('/usuarios/:id', 
  validateParams(IdParamDto),
  validateDto(UpdateUsuarioDto),
  async (req, res) => {
    const params = req.params as IdParamDto;
    const dto = req.body as UpdateUsuarioDto;
    // ...
  }
);
```

## Integração com Exception Handling

O middleware de validação lança `ValidationException` quando a validação falha:

```typescript
throw new ValidationException(
  `Dados de entrada inválidos: ${errorMessages}`,
  'VALIDATION_ERROR',
  formattedErrors
);
```

O `ErrorHandler` captura automaticamente e formata a resposta:

```json
{
  "success": false,
  "error": {
```

## Decorators Disponíveis do class-validator

### Validação de Tipos

- `@IsString()` - Valida se é string
- `@IsNumber()` - Valida se é número
- `@IsInt()` - Valida se é inteiro
- `@IsBoolean()` - Valida se é boolean
- `@IsDate()` - Valida se é data
- `@IsArray()` - Valida se é array
- `@IsObject()` - Valida se é objeto

### Validação de Strings

- `@IsEmail()` - Valida email
- `@IsUrl()` - Valida URL
- `@IsUUID()` - Valida UUID
- `@MinLength(n)` - Tamanho mínimo
- `@MaxLength(n)` - Tamanho máximo
- `@Matches(regex)` - Valida regex

### Validação de Números

- `@Min(n)` - Valor mínimo
- `@Max(n)` - Valor máximo
- `@IsPositive()` - Número positivo
- `@IsNegative()` - Número negativo

### Validação de Campos

- `@IsNotEmpty()` - Campo obrigatório
- `@IsOptional()` - Campo opcional
- `@IsDefined()` - Campo definido

### Validação de Arrays

- `@ArrayMinSize(n)` - Tamanho mínimo do array
- `@ArrayMaxSize(n)` - Tamanho máximo do array
- `@ArrayUnique()` - Valores únicos no array

### Validação de Objetos Aninhados

- `@ValidateNested()` - Valida objeto aninhado
- `@Type(() => Class)` - Define tipo do objeto aninhado

## Opções de Validação

### whitelist

Se `true`, remove propriedades não definidas no DTO:

```typescript
validateDto(CreateUsuarioDto, { whitelist: true })
```

**Padrão**: `true`

### forbidNonWhitelisted

Se `true`, lança erro se houver propriedades extras:

```typescript
validateDto(CreateUsuarioDto, { forbidNonWhitelisted: true })
```

**Padrão**: `true`

### transform

Se `true`, converte tipos automaticamente (ex: string para number):

```typescript
validateDto(CreateUsuarioDto, { transform: true })
```

**Padrão**: `true`

### validateNested

Se `true`, valida objetos aninhados:

```typescript
validateDto(CreateUsuarioDto, { validateNested: true })
```

**Padrão**: `true`

## Troubleshooting

### Problema: Validação não está funcionando

**Sintomas**: Dados inválidos passam pela validação

**Solução**:
1. Verificar se o middleware está adicionado antes do handler
2. Verificar se os decorators estão corretos
3. Verificar se `transform: true` está habilitado para conversão de tipos

### Problema: Erros de validação não aparecem

**Sintomas**: Validação falha mas erro não é retornado

**Solução**:
1. Verificar se `ErrorHandler` está adicionado ao Express app
2. Verificar se `ValidationException` está sendo lançada corretamente
3. Verificar ordem dos middlewares

### Problema: Tipos não são convertidos

**Sintomas**: Query params são strings ao invés de números

**Solução**:
1. Verificar se `transform: true` está habilitado
2. Usar `@Type(() => Number)` para conversão explícita
3. Verificar se `enableImplicitConversion` está habilitado

### Problema: Propriedades extras são removidas

**Sintomas**: Campos não definidos no DTO são removidos

**Solução**:
1. Configurar `whitelist: false` se necessário
2. Adicionar campos ao DTO se devem ser aceitos
3. Usar `forbidNonWhitelisted: false` para permitir propriedades extras
