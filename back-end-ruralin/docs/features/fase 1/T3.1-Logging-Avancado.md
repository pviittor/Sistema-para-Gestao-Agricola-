## Decisões de Implementação

### Abordagem Escolhida

**Rotação de Logs**: Implementada usando múltiplos transports do Pino:
- Em desenvolvimento: apenas pretty print no console
- Em produção com rotação: arquivos separados para logs gerais e erros
- Configurável via variáveis de ambiente

**Performance Logging**: Middleware dedicado que:
- Registra tempo de execução de cada requisição
- Identifica requisições lentas (> 1 segundo) e muito lentas (> 5 segundos)
- Integra com RequestContext para rastreabilidade

**SQL Logging**: Integração com Sequelize que:
- Registra queries SQL em nível debug
- Identifica queries lentas (> 100ms) em nível warn
- Configurável via variáveis de ambiente

## Implementação Detalhada

### Rotação de Logs

A rotação de logs é configurada através de variáveis de ambiente:

```typescript
// LoggerService.ts
const enableFileRotation = config?.enableFileRotation ?? process.env.LOG_FILE_ROTATION === 'true';
const logDirectory = config?.logDirectory || process.env.LOG_DIRECTORY || './logs';

if (enableFileRotation && environment !== 'development') {
  // Log geral em app.log
  transports.push({
    target: 'pino/file',
    level: level as pino.Level,
    options: {
      destination: `${logDirectory}/app.log`,
      mkdir: true,
    },
  });

  // Log de erros em error.log
  transports.push({
    target: 'pino/file',
    level: 'error' as pino.Level,
    options: {
      destination: `${logDirectory}/error.log`,
      mkdir: true,
    },
  });
}
```

**Variáveis de Ambiente**:
- `LOG_FILE_ROTATION=true` - Habilita rotação de logs
- `LOG_DIRECTORY=./logs` - Diretório para arquivos de log (padrão: `./logs`)

### Performance Logging Middleware

O middleware registra métricas de performance para cada requisição:

```typescript
export const performanceLoggerMiddleware = (
  req: Request,
  res: Response,
  next: NextFunction
): void => {
  const startTime = Date.now();
  const context = req.context;

  res.on('finish', () => {
    const duration = Date.now() - startTime;
    const isSlowRequest = duration > 1000; // Mais de 1 segundo
    
    logger.info('Request completed', {
      method: req.method,
      path: req.path,
      statusCode: res.statusCode,
      duration: `${duration}ms`,
      durationMs: duration,
      requestId: context?.getRequestId(),
      userId: context?.getUserId(),
    });
  });

  next();
};
```

**Thresholds**:
- Requisições normais: log em nível `info`
- Requisições lentas (> 1 segundo): log em nível `warn`
- Requisições muito lentas (> 5 segundos): log adicional em nível `error`

### SQL Query Logging

O logging de queries SQL é configurado através de funções dedicadas:

```typescript
// Configurar logging básico de queries
configureSequelizeLogging(sequelize);

// Configurar detecção de queries lentas
setupSlowQueryLogging(sequelize, 1000); // Threshold de 1 segundo
```

**Variáveis de Ambiente**:
- `LOG_SQL=true` - Habilita logging de queries SQL (padrão: habilitado em desenvolvimento)
- `LOG_SLOW_QUERIES=true` - Habilita detecção de queries lentas

**Níveis de Log**:
- Queries normais (< 100ms): nível `debug`
- Queries lentas (> 100ms): nível `warn`
- Queries muito lentas (> threshold configurado): nível `warn` com detalhes adicionais

## Configuração por Ambiente

### Desenvolvimento

```env
NODE_ENV=development
LOG_LEVEL=debug
LOG_SQL=true
LOG_FILE_ROTATION=false
```

**Comportamento**:
- Logs formatados com pretty print no console
- Todas as queries SQL são logadas
- Rotação de arquivo desabilitada

### Produção

```env
NODE_ENV=production
LOG_LEVEL=info
LOG_SQL=false
LOG_FILE_ROTATION=true
LOG_DIRECTORY=/var/log/ruralin
LOG_SLOW_QUERIES=true
```

**Comportamento**:
- Logs em formato JSON
- Queries SQL não são logadas (apenas queries lentas se habilitado)
- Rotação de arquivo habilitada
- Logs separados: `app.log` e `error.log`

## Integração com RequestContext

O performance logging integra automaticamente com o RequestContext:

```typescript
const performanceData = addContextToMeta(req, {
  method: req.method,
  path: req.path,
  statusCode: res.statusCode,
  duration: `${duration}ms`,
  durationMs: duration,
});
```

Isso garante que todos os logs de performance incluam:
- `requestId`: ID único da requisição
- `userId`: ID do usuário autenticado (quando disponível)

## Troubleshooting

### Problema: Logs não aparecem em arquivo

**Sintomas**: `LOG_FILE_ROTATION=true` mas arquivos não são criados

**Solução**:
1. Verificar permissões do diretório de logs
2. Verificar se `NODE_ENV` não está como `development` (rotação desabilitada em dev)
3. Verificar se diretório existe ou se `mkdir: true` está configurado

### Problema: Muitos logs de queries SQL

**Sintomas**: Logs excessivos de queries SQL

**Solução**:
1. Desabilitar logging de queries: `LOG_SQL=false`
2. Aumentar nível de log: `LOG_LEVEL=info` (queries são logadas em `debug`)
3. Habilitar apenas queries lentas: `LOG_SLOW_QUERIES=true` e `LOG_SQL=false`

### Problema: Performance logging não funciona

**Sintomas**: Métricas de performance não aparecem nos logs

**Solução**:
1. Verificar se `performanceLoggerMiddleware` está adicionado ao Express app
2. Verificar se está após `requestContextMiddleware`
3. Verificar se Logger está registrado no container DI

### Problema: Queries lentas não são detectadas

**Sintomas**: `LOG_SLOW_QUERIES=true` mas queries lentas não aparecem

**Solução**:
1. Verificar se `setupSlowQueryLogging()` está sendo chamado em `server.ts`
2. Verificar se threshold está configurado corretamente
3. Verificar se Logger está disponível quando hooks são executados
