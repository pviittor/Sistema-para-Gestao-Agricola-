## Decisões de Implementação

### Abordagem Escolhida

**Refatoração Incremental**: Optamos por refatorar os controllers mantendo o acesso direto aos models por enquanto, já que os repositories ainda não foram implementados. Isso permite:

- ✅ Migração gradual sem quebrar funcionalidade
- ✅ Preparação para futura injeção de repositories
- ✅ Melhoria imediata na testabilidade
- ✅ Estrutura pronta para próximas fases

### Estrutura de Interfaces

Criamos interfaces para cada controller para:
- Facilitar testes (mock de interfaces)
- Garantir contratos claros
- Permitir múltiplas implementações no futuro
- Melhorar type safety

## Implementação Detalhada

### 1. Criação de Interfaces

Cada controller agora tem uma interface correspondente que define seu contrato:

```typescript
// src/controllers/interfaces/IAuthController.ts
export interface IAuthController {
  authenticate(req: Request, res: Response): Promise<Response | void>;
  refresh(req: Request, res: Response): Promise<Response | void>;
}
```

**Benefícios**:
- Type safety
- Facilita testes (mock de interfaces)
- Documenta contrato do controller
- Permite múltiplas implementações

### 2. Refatoração dos Controllers

#### Antes

```typescript
class AuthController {
  async authenticate(req: Request, res: Response) {
    // ...
  }
}

export default new AuthController();
```

#### Depois

```typescript
@Injectable()
export class AuthController implements IAuthController {
  async authenticate(req: Request, res: Response): Promise<void> {
    // ...
  }
}

export default AuthController;
```

**Mudanças**:
- Adicionado `@Injectable()` decorator
- Implementa interface correspondente
- Exporta classe ao invés de instância
- Tipos de retorno explícitos

### 3. Registro no Container

Criado arquivo `registerControllers.ts` para centralizar o registro:

```typescript
export function registerControllers(): void {
  container.registerSingleton(TYPES.IAuthController, AuthController);
  container.registerSingleton(TYPES.IUsuarioController, UsuarioController);
  // ... outros controllers
}
```

**Chamado em**: `initializeContainer()` no `container.ts`

### 4. Atualização das Rotas

#### Antes

```typescript
import AuthController from '../controllers/AuthController';

router.post('/login', AuthController.authenticate);
```

#### Depois

```typescript
import { container } from '../core/di';
import { TYPES } from '../core/di/types';
import { IAuthController } from '../controllers/interfaces/IAuthController';

const authController = container.resolve<IAuthController>(TYPES.IAuthController);

router.post('/login', (req, res) => authController.authenticate(req, res));
```

**Benefícios**:
- Resolução via container de DI
- Facilita testes (mock do container)
- Desacoplamento de instanciação

## Padrões e Boas Práticas

### 1. Sempre Use Interfaces

Prefira injetar interfaces ao invés de classes concretas:

```typescript
// ✅ Bom
const controller = container.resolve<IAuthController>(TYPES.IAuthController);

// ⚠️ Evitar
const controller = container.resolve(AuthController);
```

### 2. Registro Centralizado

Todos os controllers devem ser registrados em `registerControllers.ts`:

```typescript
export function registerControllers(): void {
  container.registerSingleton(TYPES.IAuthController, AuthController);
  // ...
}
```

### 3. Nomenclatura Consistente

- Interfaces: `I` prefix (ex: `IAuthController`)
- Classes: PascalCase (ex: `AuthController`)
- Tokens: Em `TYPES` (ex: `TYPES.IAuthController`)

### 4. Preparação para Futuras Dependências


## Troubleshooting

### Problema: Controller não é resolvido

**Sintomas**: Erro "No matching bindings found"

**Solução**:
1. Verificar se controller está registrado em `registerControllers()`
2. Verificar se `registerControllers()` é chamado em `initializeContainer()`
3. Verificar se token está correto em `TYPES`

### Problema: Erro de tipo na interface

**Sintomas**: Erro "Property X is not assignable"

**Solução**:
1. Verificar se assinatura do método na interface corresponde à implementação
2. Verificar tipos de retorno (`Promise<Response | void>`)
3. Verificar se todos os métodos da interface estão implementados

### Problema: Rota não funciona

**Sintomas**: Erro 404 ou erro ao acessar rota

**Solução**:
1. Verificar se controller está sendo resolvido corretamente
2. Verificar se método do controller está sendo chamado
3. Verificar se rota está registrada corretamente
