## Introdução

Este documento serve como guia completo para o uso de Dependency Injection (DI) no projeto RuralIn. O sistema utiliza **TSyringe** como biblioteca de DI, permitindo desacoplamento, testabilidade e manutenibilidade do código.

### O que é Dependency Injection?

Dependency Injection é um padrão de design que permite que objetos recebam suas dependências ao invés de criá-las internamente. Isso promove:

- ✅ **Desacoplamento**: Classes não dependem de implementações concretas
- ✅ **Testabilidade**: Fácil criação de mocks para testes
- ✅ **Manutenibilidade**: Mudanças em dependências não afetam quem as usa
- ✅ **Reutilização**: Dependências podem ser compartilhadas

### Por que TSyringe?

- Leve e performático
- Compatível com TypeScript
- Suporte nativo a decorators
- Desenvolvido pela Microsoft
- Comunidade ativa

## Conceitos Fundamentais

### Container de DI

O container é o responsável por gerenciar o ciclo de vida e resolução de todas as dependências:

```typescript
import { container } from './core/di';

// Resolver uma dependência
const service = container.resolve<IService>(TYPES.IService);
```

### Decorators

#### @Injectable()

Marca uma classe como injetável no container:

```typescript
@Injectable()
export class MyService {
  // ...
}
```

#### @Inject()

Marca um parâmetro do construtor para injeção:

```typescript
@Injectable()
export class MyService {
  constructor(
    @Inject(TYPES.ILogger) private logger: ILogger
  ) {}
}
```

### Tokens

Tokens são identificadores únicos para dependências. Usamos `Symbol` para evitar colisões:

```typescript
export const TYPES = {
  ILogger: Symbol.for('ILogger'),
  IUserService: Symbol.for('IUserService'),
} as const;
```

### Escopos

- **Singleton**: Uma única instância compartilhada (padrão)
- **Transient**: Nova instância a cada resolução

## Guia de Uso

### 1. Criando um Service Injetável

```typescript
import { Injectable } from '../core/di';

// Definir interface
export interface IEmailService {
  sendEmail(to: string, subject: string): Promise<void>;
}

// Implementar service
@Injectable()
export class EmailService implements IEmailService {
  async sendEmail(to: string, subject: string): Promise<void> {
    console.log(`Enviando email para ${to}: ${subject}`);
    // Implementação...
  }
}
```

### 2. Registrando no Container

```typescript
// src/core/di/registerServices.ts
import { container } from './container';
import { TYPES } from './types';
import { EmailService } from '../../services/EmailService';

export function registerServices(): void {
  container.registerSingleton<IEmailService>(TYPES.IEmailService, EmailService);
}
```

### 3. Injetando Dependências

```typescript
import { Injectable, Inject } from '../core/di';
import { TYPES } from '../core/di/types';

@Injectable()
export class NotificationService {
  constructor(
    @Inject(TYPES.IEmailService) private emailService: IEmailService
  ) {}

  async notify(userId: number, message: string): Promise<void> {
    await this.emailService.sendEmail(userId.toString(), message);
  }
}
```

### 4. Resolvendo em Rotas

```typescript
import { container } from '../core/di';
import { TYPES } from '../core/di/types';
import { INotificationService } from '../services/interfaces/INotificationService';

const router = Router();
const notificationService = container.resolve<INotificationService>(
  TYPES.INotificationService
);

router.post('/notify', async (req, res) => {
  await notificationService.notify(req.body.userId, req.body.message);
  res.json({ success: true });
});
```

### 5. Usando Scope Transient

```typescript
@Injectable({ scope: 'transient' })
export class RequestContext {
  private id: string;

  constructor() {
    this.id = `req-${Date.now()}`;
  }

  getId(): string {
    return this.id;
  }
}
```

## Padrões e Convenções

### 1. Nomenclatura

#### Interfaces
- Sempre use prefixo `I` (ex: `ILogger`, `IUserService`)
- Nome descritivo do que a interface representa

```typescript
export interface ILogger {
  log(message: string): void;
}
```

#### Classes
- PascalCase (ex: `LoggerService`, `UserController`)
- Nome descritivo + tipo (Service, Controller, Repository)

```typescript
@Injectable()
export class LoggerService implements ILogger {
  // ...
}
```

#### Tokens
- Definidos em `src/core/di/types.ts`
- Mesmo nome da interface (ex: `TYPES.ILogger`)

```typescript
export const TYPES = {
  ILogger: Symbol.for('ILogger'),
} as const;
```

### 2. Estrutura de Pastas

```
src/
  core/
    di/
      container.ts          # Container principal
      types.ts              # Tokens de DI
      decorators.ts         # Decorators customizados
      registerControllers.ts # Registro de controllers
      registerServices.ts   # Registro de services
  controllers/
    interfaces/             # Interfaces dos controllers
      IAuthController.ts
      IUsuarioController.ts
  services/
    interfaces/             # Interfaces dos services
      IEmailService.ts
    EmailService.ts
```

### 3. Ordem de Dependências no Constructor

Mantenha ordem lógica:

1. **Core Services** (Logger, Cache, etc.)
2. **Repositories**
3. **Application Services**
4. **Outros Services**

```typescript
@Injectable()
export class UsuarioController {
  constructor(
    @Inject(TYPES.ILogger) private logger: ILogger,           // 1. Core
    @Inject(TYPES.IUsuarioRepository) private repo: IRepository, // 2. Repository
    @Inject(TYPES.IUsuarioApplicationService) private service: IApplicationService // 3. Application
  ) {}
}
```

### 4. Registro de Dependências

Sempre registre dependências em arquivos dedicados:

- `registerControllers.ts` - Para controllers
- `registerServices.ts` - Para services
- `registerRepositories.ts` - Para repositories

```typescript
// src/core/di/registerServices.ts
export function registerServices(): void {
  container.registerSingleton<ILogger>(TYPES.ILogger, LoggerService);
  container.registerSingleton<IEmailService>(TYPES.IEmailService, EmailService);
}
```

### 5. Uso de Interfaces

**Sempre** injete interfaces, nunca classes concretas:

```typescript
// ✅ Bom
@Injectable()
export class MyService {
  constructor(
    @Inject(TYPES.ILogger) private logger: ILogger
  ) {}
}

// ⚠️ Evitar
@Injectable()
export class MyService {
  constructor(
    private logger: LoggerService  // Classe concreta
  ) {}
}
```

    try {
      // Lógica de processamento

### Exemplo 2: Controller com Múltiplas Dependências

```typescript
// src/controllers/UsuarioController.ts
import { Injectable, Inject } from '../core/di';
import { TYPES } from '../core/di/types';
import { IUsuarioController } from './interfaces/IUsuarioController';
import { IUsuarioApplicationService } from '../application/services/interfaces/IUsuarioApplicationService';
import { ILogger } from '../core/logger/ILogger';

@Injectable()
export class UsuarioController implements IUsuarioController {
  constructor(
    @Inject(TYPES.ILogger) private logger: ILogger,
    @Inject(TYPES.IUsuarioApplicationService) 
    private usuarioService: IUsuarioApplicationService
  ) {}

  async create(req: Request, res: Response): Promise<void> {
    this.logger.info('Criando novo usuário');
    
    try {
      const result = await this.usuarioService.create(req.body);
      this.logger.info(`Usuário criado com ID: ${result.id}`);
      res.status(201).json(result);
    } catch (error) {
      this.logger.error('Erro ao criar usuário', error);
      res.status(500).json({ error: 'Erro ao criar usuário' });
    }
  }
}
```

### Exemplo 4: Teste com Mock

```typescript
// src/services/__tests__/OrderService.spec.ts
import { container } from '../../core/di';
import { TYPES } from '../../core/di/types';
import { OrderService } from '../OrderService';
import { ILogger } from '../../core/logger/ILogger';

describe('OrderService', () => {
  let orderService: OrderService;
  let mockLogger: jest.Mocked<ILogger>;

  beforeEach(() => {
    // Criar mock
    mockLogger = {
      info: jest.fn(),
      error: jest.fn(),
      warn: jest.fn(),
      debug: jest.fn(),
    };

    // Registrar mock no container
    container.registerInstance<ILogger>(TYPES.ILogger, mockLogger);

    // Resolver service
    orderService = container.resolve<OrderService>(OrderService);
  });

  afterEach(() => {
    container.clearInstances();
  });

  it('deve processar pedido e logar informações', async () => {
    await orderService.processOrder(123);

    expect(mockLogger.info).toHaveBeenCalledWith('Processando pedido 123');
    expect(mockLogger.info).toHaveBeenCalledWith('Pedido 123 processado com sucesso');
  });
});
```

@Injectable({ scope: 'transient' })

## Troubleshooting

### Problema 1: "Cannot find name 'Injectable'"

**Sintomas**: Erro de compilação TypeScript

**Causa**: Decorator não importado ou `reflect-metadata` não configurado

**Solução**:
1. Verificar import: `import { Injectable } from '../core/di';`
2. Verificar se `reflect-metadata` está importado no início do arquivo de entrada (`server.ts`)
3. Verificar `tsconfig.json`:
   ```json
   {
     "compilerOptions": {
       "experimentalDecorators": true,
       "emitDecoratorMetadata": true
     }
   }
   ```

### Problema 2: "No matching bindings found"

**Sintomas**: Erro ao resolver dependência

**Causa**: Dependência não registrada no container

**Solução**:
1. Verificar se dependência está registrada em `registerServices()` ou similar
2. Verificar se `registerServices()` é chamado em `initializeContainer()`
3. Verificar se token está correto:
   ```typescript
   // Token deve corresponder
   container.registerSingleton<ILogger>(TYPES.ILogger, LoggerService);
   // ...
   @Inject(TYPES.ILogger) // Mesmo token
   ```

### Problema 3: "Circular dependency detected"

**Sintomas**: Erro de dependência circular

**Causa**: Duas classes dependem uma da outra

**Solução**:
1. Usar interfaces para quebrar dependência circular
2. Refatorar para remover dependência circular
3. Usar injeção lazy se necessário:
   ```typescript
   @Injectable()
   export class ServiceA {
     constructor(
       @Inject(TYPES.IServiceB) private getServiceB: () => IServiceB
     ) {}
   }
   ```

### Problema 4: Múltiplas instâncias de singleton

**Sintomas**: Diferentes instâncias do mesmo service

**Causa**: Service não está marcado como singleton ou está sendo criado manualmente

**Solução**:
1. Verificar se `@Injectable()` está presente (singleton por padrão)
2. Verificar se não está usando `@Injectable({ scope: 'transient' })`
3. Verificar se não está criando instâncias manualmente:
   ```typescript
   // ❌ Errado
   const service = new MyService();
   
   // ✅ Correto
   const service = container.resolve<IMyService>(TYPES.IMyService);
   ```

### Problema 5: Dependência é undefined

**Sintomas**: Dependência injetada é `undefined`

**Causa**: Dependência não registrada ou token incorreto

**Solução**:
1. Verificar se dependência está registrada
2. Verificar se token está correto
3. Verificar se `initializeContainer()` foi chamado antes de usar
4. Adicionar logs para debug:
   ```typescript
   console.log('Container registrations:', container.isRegistered(TYPES.IService));
   ```

### Problema 6: Erro "Property X does not exist on type Y"

**Sintomas**: Erro de tipo TypeScript

**Causa**: Interface não corresponde à implementação

**Solução**:
1. Verificar se interface tem todos os métodos da implementação
2. Verificar tipos de retorno e parâmetros
3. Verificar se está usando a interface correta no `@Inject`

## Boas Práticas

### 1. Sempre Use Interfaces

```typescript
// ✅ Bom
@Injectable()
export class MyService {
  constructor(
    @Inject(TYPES.ILogger) private logger: ILogger
  ) {}
}

// ⚠️ Evitar
@Injectable()
export class MyService {
  constructor(
    private logger: LoggerService
  ) {}
}
```

### 2. Registre Todas as Dependências

```typescript
// ✅ Bom - Centralizado
export function registerServices(): void {
  container.registerSingleton<ILogger>(TYPES.ILogger, LoggerService);
  container.registerSingleton<IEmailService>(TYPES.IEmailService, EmailService);
}

// ⚠️ Evitar - Espalhado
container.registerSingleton<ILogger>(TYPES.ILogger, LoggerService); // Em algum lugar
container.registerSingleton<IEmailService>(TYPES.IEmailService, EmailService); // Em outro lugar
```

### 3. Use Tokens do TYPES

```typescript
// ✅ Bom
@Inject(TYPES.ILogger)

// ⚠️ Evitar
@Inject('ILogger')
```

### 4. Documente Dependências Complexas

```typescript
@Injectable()
export class ComplexService {
  /**
   * @param logger - Serviço de logging para registrar operações
   * @param cache - Serviço de cache para otimização
   * @param emailService - Serviço de email para notificações
   */
  constructor(
    @Inject(TYPES.ILogger) private logger: ILogger,
    @Inject(TYPES.ICacheService) private cache: ICacheService,
    @Inject(TYPES.IEmailService) private emailService: IEmailService
  ) {}
}
```

### 5. Limpe Container em Testes

```typescript
import { clearContainer } from '../core/di';

afterEach(() => {
  clearContainer();
});
```

### 6. Prefira Singleton para Services Stateless

```typescript
// ✅ Bom - Service stateless
@Injectable() // Singleton por padrão
export class LoggerService {
  log(message: string): void {
    console.log(message);
  }
}

// ✅ Bom - Service com estado temporário
@Injectable({ scope: 'transient' })
export class RequestContext {
  private id: string;
  // ...
}
```

### 7. Evite Resolver no Código de Negócio

```typescript
// ❌ Evitar - Resolver dentro de método
async processOrder() {
  const logger = container.resolve<ILogger>(TYPES.ILogger);
  logger.log('Processing order');
}

// ✅ Bom - Injetar no constructor
@Injectable()
export class OrderService {
  constructor(
    @Inject(TYPES.ILogger) private logger: ILogger
  ) {}

  async processOrder() {
    this.logger.log('Processing order');
  }
}
```
