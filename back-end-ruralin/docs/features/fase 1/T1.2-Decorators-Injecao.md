- ✅ Mantém simplicidade

**Singleton por Padrão**: TSyringe usa singleton por padrão, então mantivemos esse comportamento. Para transient, o registro é feito manualmente no container quando necessário.

## Implementação Detalhada

### 1. Decorator @Injectable()

O decorator `@Injectable()` marca uma classe como injetável no container de DI.

#### Sintaxe Básica

```typescript
@Injectable()
export class MyService {
  // ...
}
```

#### Com Scope Transient

```typescript
@Injectable({ scope: 'transient' })
export class MyTransientService {
  // Nova instância a cada resolução
}
```

#### Sintaxe Curta para Scope

```typescript
@Injectable('transient')
export class MyService {
  // ...
}
```

#### Com Token Customizado

```typescript
@Injectable({ token: TYPES.IMyService })
export class MyService implements IMyService {
  // Registrado com token customizado
}
```

#### Implementação

```typescript
export function Injectable(options?: InjectableOptions | 'singleton' | 'transient') {
  return function (target: any) {
    const opts: InjectableOptions = typeof options === 'string' 
      ? { scope: options }
      : (options || {});

    const scope = opts.scope || 'singleton';

    // Registrar com TSyringe
    tsyringeInjectable()(target);

    // Se token customizado fornecido, registrar com esse token
    if (opts.token) {
      const { container } = require('./container');
      if (scope === 'singleton') {
        container.registerSingleton(opts.token, target);
      } else {
        container.register(opts.token, { useClass: target });
      }
    } else if (scope === 'transient') {
      // Para transient sem token, registrar a classe como transient
      const { container } = require('./container');
      container.register(target, { useClass: target });
    }
  };
}
```

### 2. Decorator @Inject()

O decorator `@Inject()` marca um parâmetro do construtor para injeção automática.

#### Uso com Token

```typescript
@Injectable()
export class MyService {
  constructor(
    @Inject(TYPES.ILogger) private logger: ILogger
  ) {}
}
```

#### Injeção Automática por Classe

TSyringe também suporta injeção automática sem `@Inject` quando a classe está registrada:

```typescript
@Injectable()
export class MyService {
  constructor(
    private logger: LoggerService // Resolvido automaticamente
  ) {}
}
```

#### Implementação

```typescript
export function Inject(token: InjectionToken<any>) {
  return tsyringeInject(token);
}
```

### 3. Resolução Automática de Dependências

TSyringe resolve automaticamente dependências quando:
- A classe está marcada com `@Injectable()`
- A dependência está registrada no container
- O tipo da dependência corresponde a uma classe registrada

**Exemplo**:
```typescript
@Injectable()
export class LoggerService implements ILogger {
  // ...
}

@Injectable()
export class MyService {
  constructor(
    private logger: LoggerService // Resolvido automaticamente
  ) {}
}
```

### Exemplo 2: Service com Dependências

```typescript
import { Injectable, Inject } from '../core/di';
import { TYPES } from '../core/di/types';

export interface ILogger {
  log(message: string): void;
}

@Injectable()
export class LoggerService implements ILogger {
  log(message: string): void {
    console.log(message);
  }

@Injectable()
export class NotificationService {
  constructor(
    @Inject(TYPES.ILogger) private logger: ILogger
  ) {}

  async notify(message: string): Promise<void> {
    this.logger.log(`Notificando: ${message}`);
  }
}
```


## Padrões e Boas Práticas

### 1. Sempre Use Interfaces

Prefira injetar interfaces ao invés de classes concretas:

```typescript
// ✅ Bom
@Injectable()
export class MyService {
  constructor(
    @Inject(TYPES.ILogger) private logger: ILogger
  ) {}
}

// ⚠️ Evitar (acoplamento forte)
@Injectable()
export class MyService {
  constructor(
    private logger: LoggerService
  ) {}
}
```

### 2. Use Tokens do TYPES

Sempre use tokens definidos em `TYPES` para manter consistência:

```typescript
// ✅ Bom
@Inject(TYPES.ILogger)

// ⚠️ Evitar
@Inject('ILogger')
```

### 3. Singleton vs Transient

- **Singleton**: Use para serviços stateless, repositórios, services
- **Transient**: Use para contextos de requisição, objetos com estado temporário

### 4. Ordem de Dependências

Mantenha ordem lógica no construtor:
1. Core services (Logger, Cache)
2. Repositories
3. Application Services
4. Outros services

```typescript
@Injectable()
export class MyService {
  constructor(
    @Inject(TYPES.ILogger) private logger: ILogger,        // 1. Core
    @Inject(TYPES.IRepository) private repo: IRepository,  // 2. Repository
    private appService: ApplicationService                  // 3. Application
  ) {}
}
```

## Comparação: Antes vs Depois

### Antes (Sem DI)

```typescript
class UsuarioController {
  async create(req: Request, res: Response) {
    const usuarioService = new UsuarioApplicationService(
      new UsuarioRepository()
    );
    // ...
  }
}
```

**Problemas**:
- Acoplamento forte
- Difícil de testar
- Instanciação manual
- Dificulta mudanças

### Depois (Com DI)

```typescript
@Injectable()
class UsuarioController {
  constructor(
    @Inject(TYPES.IUsuarioApplicationService) 
    private usuarioService: IUsuarioApplicationService
  ) {}

  async create(req: Request, res: Response) {
    const result = await this.usuarioService.create(req.body);
    // ...
  }
}
```

**Benefícios**:
- Desacoplamento
- Fácil de testar (mock de dependências)
- Injeção automática
- Flexível para mudanças

## Troubleshooting

### Problema: Decorator não funciona

**Sintomas**: Erro "Cannot find name 'Injectable'"

**Solução**:
1. Verificar se `reflect-metadata` está importado no início do arquivo de entrada
2. Verificar se `experimentalDecorators: true` no tsconfig.json
3. Verificar se decorator está importado: `import { Injectable } from '../core/di'`

### Problema: Dependência não é injetada

**Sintomas**: `undefined` ou erro ao acessar dependência

**Solução**:
1. Verificar se dependência está registrada no container
2. Verificar se token está correto
3. Verificar se classe está marcada com `@Injectable()`
4. Verificar se `initializeContainer()` foi chamado

### Problema: Múltiplas instâncias de singleton

**Sintomas**: Diferentes instâncias do mesmo service

**Solução**:
1. Verificar se não está usando `@Injectable({ scope: 'transient' })`
2. Verificar se não está criando instâncias manualmente
3. Verificar se container está sendo limpo entre testes
