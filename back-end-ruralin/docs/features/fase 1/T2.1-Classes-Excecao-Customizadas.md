## Decisões de Implementação

### Hierarquia de Exceções

```
Error (nativo)
  └── BaseException (abstrata)
       ├── BusinessException (400)
       ├── ValidationException (400)
       ├── NotFoundException (404)
       ├── UnauthorizedException (401)
       └── ForbiddenException (403)
```

### Estrutura Base

Todas as exceções herdam de `BaseException` que fornece:
- `statusCode`: Código HTTP apropriado
- `code`: Código de erro único para identificação
- `message`: Mensagem descritiva
- `details`: Detalhes adicionais (opcional)
- `toJSON()`: Método para serialização

## Implementação Detalhada

### BaseException

```typescript
export abstract class BaseException extends Error {
  public readonly statusCode: number;
  public readonly code: string;
  public readonly details?: any;

  constructor(
    message: string,
    statusCode: number,
    code: string,
    details?: any
  ) {
    super(message);
    this.name = this.constructor.name;
    
    if (Error.captureStackTrace) {
      Error.captureStackTrace(this, this.constructor);
    }
    
    this.statusCode = statusCode;
    this.code = code;
    this.details = details;
    
    Object.setPrototypeOf(this, BaseException.prototype);
  }

  toJSON(): {
    name: string;
    message: string;
    statusCode: number;
    code: string;
    details?: any;
  } {
    return {
      name: this.name,
      message: this.message,
      statusCode: this.statusCode,
      code: this.code,
      ...(this.details && { details: this.details }),
    };
  }
}
```

**Características**:
- Classe abstrata (não pode ser instanciada diretamente)
- Preserva stack trace
- Método `toJSON()` para serialização
- Propriedades readonly para imutabilidade

### Exemplo de Exceção Específica

```typescript
export class NotFoundException extends BaseException {
  constructor(
    resource: string,
    id?: string | number,
    code: string = 'NOT_FOUND'
  ) {
    const message = id
      ? `${resource} com id ${id} não encontrado`
      : `${resource} não encontrado`;
    
    super(message, 404, code, { resource, id });
  }
}
```

### Exemplo 2: ValidationException

```typescript
import { ValidationException } from '../core/exceptions';

function validarUsuario(dto: CreateUsuarioDto): void {
  const errors: Array<{ field: string; message: string }> = [];
  
  if (!dto.email || !isValidEmail(dto.email)) {
    errors.push({ field: 'email', message: 'Email inválido' });
  }
  
  if (!dto.senha || dto.senha.length < 8) {

  if (errors.length > 0) {
    throw new ValidationException('Dados inválidos', 'VALIDATION_ERROR', errors);
  }
}
```

```typescript
import { UnauthorizedException } from '../core/exceptions';

async function autenticar(email: string, senha: string): Promise<Usuario> {
  const usuario = await usuarioRepository.findByEmail(email);
  
  if (!usuario) {
    throw new UnauthorizedException('Credenciais inválidas', 'INVALID_CREDENTIALS');
  }
  
  const isValid = await bcrypt.compare(senha, usuario.senha);

  return usuario;

```

### Exemplo 5: ForbiddenException

```typescript
import { ForbiddenException } from '../core/exceptions';

async function deletarUsuario(userId: number, currentUser: Usuario): Promise<void> {
  // Verificar se usuário tem permissão
  if (!currentUser.hasPermission('usuario.delete')) {
    throw new ForbiddenException(
      'Você não tem permissão para deletar usuários',
      'INSUFFICIENT_PERMISSION',
      { requiredPermission: 'usuario.delete' }
    );
  }
  
  // Verificar se não está tentando deletar a si mesmo
  if (userId === currentUser.id) {
    throw new ForbiddenException('Você não pode deletar sua própria conta');
  }
  
  await usuarioRepository.delete(userId);
}
```

## Quando Usar Cada Exceção

### BusinessException (400)

Use quando:
- Uma regra de negócio for violada
- Operação não pode ser executada por restrição de negócio
- Estado inválido para a operação

**Exemplos**:
- Saldo insuficiente
- Produto fora de estoque
- Período de cancelamento expirado

### ValidationException (400)

Use quando:
- Dados de entrada não passarem na validação
- Formato de dados inválido
- Campos obrigatórios faltando

**Exemplos**:
- Email inválido
- Senha muito curta
- Data inválida

### NotFoundException (404)

Use quando:
- Recurso solicitado não existir
- ID não encontrado no banco de dados
- Endpoint não existir

**Exemplos**:
- Usuário não encontrado
- Produto não encontrado
- Arquivo não encontrado

### UnauthorizedException (401)

Use quando:
- Usuário não estiver autenticado
- Token inválido ou expirado
- Credenciais inválidas

**Exemplos**:
- Token JWT inválido
- Senha incorreta
- Sessão expirada

### ForbiddenException (403)

Use quando:
- Usuário estiver autenticado mas não tiver permissão
- Acesso negado a recurso específico
- Operação não permitida para o usuário

**Exemplos**:
- Usuário sem permissão para deletar
- Tentativa de acessar recurso de outro usuário
- Operação restrita a administradores

```typescript
// ✅ Bom
throw new BusinessException(
  'Saldo insuficiente',

);

// ⚠️ Evitar
```

