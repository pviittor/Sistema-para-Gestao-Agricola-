## Implementação Detalhada

### Validador Customizado IsExists

```typescript
@ValidatorConstraint({ async: true })
export class IsExistsConstraint implements ValidatorConstraintInterface {
  async validate(value: any, args: ValidationArguments): Promise<boolean> {
    const [modelName, columnName] = args.constraints;
    const Model = sequelize.models[modelName];
    
    const existing = await Model.findOne({
      where: { [columnName]: value },
    });
    
    return !!existing; // Retorna true se existir
  }
}
```

**Uso**:
```typescript
@IsExists('Local', 'id', { message: 'Local não encontrado' })
localId!: number;
```

### Validador Customizado IsTimeAfter

```typescript
@ValidatorConstraint({ async: false })
export class IsTimeAfterConstraint implements ValidatorConstraintInterface {
  validate(value: any, args: ValidationArguments): boolean {
    const [startTimeProperty, dateProperty] = args.constraints;
    const object = args.object as any;
    
    const endTime = value;
    const startTime = object[startTimeProperty];
    const date = object[dateProperty];
    
    // Compara horários considerando data se fornecida
    if (date) {
      const startDateTime = new Date(`${date}T${startTime}`);
      const endDateTime = new Date(`${date}T${endTime}`);
      return endDateTime > startDateTime;
    }
    
    // Compara apenas horários
    return endTotalSeconds > startTotalSeconds;
  }
}
```

**Uso**:
```typescript
@IsTimeAfter('horario_inicio', 'data', { message: 'Horário de fim deve ser posterior ao início' })
horario_fim!: string;
```

### CreateEventoDto

```typescript
export class CreateEventoDto extends CreateDto {
  @IsString({ message: 'Título deve ser uma string' })
  @IsNotEmpty({ message: 'Título é obrigatório' })
  titulo!: string;

  @IsString({ message: 'Descrição deve ser uma string' })
  @IsNotEmpty({ message: 'Descrição é obrigatória' })
  descricao!: string;

  @IsDateString({}, { message: 'Data deve ser uma data válida no formato YYYY-MM-DD' })
  @IsNotEmpty({ message: 'Data é obrigatória' })
  data!: string;

  @IsString({ message: 'Horário de início deve ser uma string' })
  @IsNotEmpty({ message: 'Horário de início é obrigatório' })
  @Matches(/^([0-1][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]$/, {
    message: 'Horário de início deve estar no formato HH:mm:ss',
  })
  horario_inicio!: string;

  @IsString({ message: 'Horário de fim deve ser uma string' })
  @IsNotEmpty({ message: 'Horário de fim é obrigatório' })
  @Matches(/^([0-1][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]$/, {
    message: 'Horário de fim deve estar no formato HH:mm:ss',
  })
  @Validate(IsTimeAfter, ['horario_inicio', 'data'])
  horario_fim!: string;

  @IsInt({ message: 'Local ID deve ser um número inteiro' })
  @Min(1, { message: 'Local ID deve ser maior que zero' })
  @IsNotEmpty({ message: 'Local ID é obrigatório' })
  @Validate(IsExists, ['Local', 'id'])
  localId!: number;
}
```

## Validador Customizado IsExists

### Funcionamento

O validador `IsExists` verifica se um valor existe no banco de dados:

1. **Busca no Modelo**: Usa o nome do modelo Sequelize para buscar
2. **Valida Existência**: Verifica se existe registro com o valor fornecido
3. **Retorna Resultado**: Retorna `true` se existir, `false` caso contrário

### Implementação

```typescript
@IsExists('Local', 'id', { message: 'Local não encontrado' })
localId!: number;
```

**Parâmetros**:
- `modelName`: Nome do modelo Sequelize ('Local')
- `columnName`: Nome da coluna ('id')
- `validationOptions`: Opções do class-validator

### Exemplo de Uso

```typescript
// CreateEventoDto
@IsExists('Local', 'id', { message: 'Local não encontrado' })
localId!: number;
```

## Validador Customizado IsTimeAfter

### Funcionamento

O validador `IsTimeAfter` valida que um horário é posterior a outro:

1. **Comparação com Data**: Se data fornecida, cria objetos Date completos
2. **Comparação sem Data**: Se não houver data, compara apenas horários
3. **Eventos Históricos**: Permite qualquer horário para eventos no passado
4. **Validação Condicional**: Só valida se horário de início também for fornecido

### Implementação

```typescript
@IsTimeAfter('horario_inicio', 'data', { message: 'Horário de fim deve ser posterior ao início' })
horario_fim!: string;
```

**Parâmetros**:
- `startTimeProperty`: Nome da propriedade com horário de início ('horario_inicio')
- `dateProperty`: Nome da propriedade com data ('data', opcional)
- `validationOptions`: Opções do class-validator

### Exemplo de Uso

```typescript
// CreateEventoDto
@IsTimeAfter('horario_inicio', 'data', { message: 'Horário de fim deve ser posterior ao início' })
horario_fim!: string;

// UpdateEventoDto (validação condicional)
@ValidateIf((o) => o.horario_fim !== undefined && (o.horario_inicio !== undefined || o.data !== undefined))
@Validate(IsTimeAfter, ['horario_inicio', 'data'])
horario_fim?: string;
```

## Padrões de Formato

### Data

Formato: `YYYY-MM-DD`

**Exemplos**:
- ✅ `2025-01-20` - Válido
- ✅ `2025-12-31` - Válido
- ❌ `20-01-2025` - Inválido
- ❌ `2025/01/20` - Inválido
- ❌ `data-invalida` - Inválido

### Horário

Formato: `HH:mm:ss`

**Exemplos**:
- ✅ `09:00:00` - Válido
- ✅ `23:59:59` - Válido
- ❌ `9:00:00` - Inválido (deve ter dois dígitos)
- ❌ `25:00:00` - Inválido (hora > 23)
- ❌ `09:60:00` - Inválido (minuto > 59)

### Validação de Horários

- ✅ `horario_fim` deve ser posterior a `horario_inicio`
- ✅ Eventos históricos (datas no passado) permitem qualquer horário
- ✅ Em updates, validação só ocorre se ambos os horários forem fornecidos

## Troubleshooting

### Problema: Validação de IsExists não funciona

**Sintomas**: Local inexistente passa na validação

**Solução**:
1. Verificar se o modelo Sequelize está registrado corretamente
2. Verificar se o nome do modelo está correto ('Local' vs 'Locals')
3. Verificar logs de erro do validador

### Problema: Validação de IsTimeAfter falha em updates

**Sintomas**: Validação falha mesmo quando horários são válidos

**Solução**:
1. Verificar se está usando `@ValidateIf()` corretamente
2. Verificar se `horario_inicio` ou `data` estão sendo fornecidos
3. Verificar se o formato de horário está correto (HH:mm:ss)

### Problema: Data inválida passa na validação

**Sintomas**: Data em formato incorreto passa na validação

**Solução**:
1. Verificar se `@IsDateString()` está aplicado corretamente
2. Verificar se o formato está correto (YYYY-MM-DD)
3. Verificar se `transform: true` está habilitado no middleware

### Problema: Validação de relacionamento muito lenta

**Sintomas**: Validação demora muito tempo

**Solução**:
1. Verificar se há índices no banco de dados para `localId`
2. Considerar cache para validações frequentes
3. Verificar se não há queries N+1
