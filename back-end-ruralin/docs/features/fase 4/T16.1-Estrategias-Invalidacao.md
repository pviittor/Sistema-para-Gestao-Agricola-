# T16.1 - Estratégias de Invalidação

## Resumo Executivo

Implementação de estratégias avançadas de invalidação de cache usando tags e invalidação em cascata. O sistema permite invalidar grupos relacionados de cache e automaticamente invalidar entidades relacionadas quando uma entidade é atualizada.

## Funcionalidades Implementadas

### 1. Sistema de Tags

**Conceito**:
Cada entrada de cache pode ter múltiplas tags que permitem agrupar entradas relacionadas.

**Exemplo**:
```typescript
// Armazenar com tags
await cacheService.setWithTags(
  'usuario:getById:1',
  userData,
  3600,
  ['usuario', 'usuario:1']
);

// Invalidar todas as entradas com tag 'usuario'
await cacheService.invalidateByTag('usuario');
// Remove: usuario:getById:1, usuario:list:1:10, usuario:findByEmail:*, etc.

// Invalidar todas as entradas com tag 'usuario:1'
await cacheService.invalidateByTag('usuario:1');
// Remove apenas entradas relacionadas ao usuário ID 1
```

**Implementação**:
- **Redis**: Usa Sets (`tag:cache:{tag}`) para armazenar chaves por tag
- **InMemory**: Usa `Map<string, Set<string>>` para índice de tags

### 2. Invalidação por Tag

**Funcionalidade**:
Remove todas as entradas do cache que possuem uma tag específica.

**Exemplo**:
```typescript
// Invalidar todas as entradas com tag 'usuario'
const deleted = await cacheService.invalidateByTag('usuario');
console.log(`Invalidated ${deleted} entries`);
```

**Uso em Decorators**:
```typescript
@CacheEvict({ tags: ['usuario', 'usuario:1'] })
async update(id: number, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
  // Todas as entradas com tags 'usuario' ou 'usuario:1' serão invalidadas
}
```

### 3. Invalidação em Cascata

**Funcionalidade**:
Quando uma entidade é atualizada, automaticamente invalida cache de entidades relacionadas.

**Relacionamentos Padrão**:
- **Usuario** → Evento, Lembrete, Local
- **Local** → Evento

**Exemplo**:
```typescript
// Quando atualizar Usuario ID 1, automaticamente invalida:
// - Cache de Eventos do usuário
// - Cache de Lembretes do usuário
// - Cache de Locais do usuário
@CacheEvict({ cascade: true, entityName: 'usuario' })
async update(id: number, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
  // Invalidação em cascata será executada automaticamente
}
```

**Implementação**:
- `CacheInvalidationService` mantém mapa de relacionamentos
- Quando `invalidateCascade` é chamado, invalida entidades relacionadas
- Relacionamentos podem ser registrados dinamicamente

### 4. Invalidação Parcial

**Funcionalidade**:
Invalida apenas entradas específicas, mantendo outras no cache.

**Exemplo**:
```typescript
const invalidationService = container.resolve<ICacheInvalidationService>(TYPES.ICacheInvalidationService);

// Invalidar apenas chaves específicas
await invalidationService.invalidatePartial([
  'usuario:getById:1',
  'usuario:findByEmail:user@example.com'
]);
// Outras entradas de cache permanecem intactas
```

**Uso**:
- Útil quando você quer invalidar apenas algumas entradas específicas
- Mantém outras entradas no cache para melhor performance

### 5. Decorators Atualizados

**@Cacheable com Tags**:
```typescript
@Cacheable({
  key: 'usuario:getById:{0}',
  ttl: 3600,
  tags: ['usuario', 'usuario:{0}'] // Tags dinâmicas
})
async getById(id: number): Promise<UsuarioResponseDto | null> {
  // Cache será armazenado com tags 'usuario' e 'usuario:1' (se id=1)
}
```

**@CacheEvict com Tags**:
```typescript
@CacheEvict({ tags: ['usuario', 'usuario:{0}'] })
async update(id: number, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
  // Invalidará todas as entradas com tags 'usuario' ou 'usuario:1'
}
```

**@CacheEvict com Cascata**:
```typescript
@CacheEvict({
  cascade: true,
  entityName: 'usuario'
})
async update(id: number, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
  // Invalidará em cascata: Eventos, Lembretes, Locais do usuário
}
```

## Exemplos de Uso

### Exemplo 1: Cache com Tags

```typescript
@Injectable()
export class UsuarioApplicationService {
  @Cacheable({
    key: 'usuario:getById:{0}',
    ttl: 3600,
    tags: ['usuario', 'usuario:{0}'] // Tags dinâmicas
  })
  async getById(id: number): Promise<UsuarioResponseDto | null> {
    // Cache armazenado com tags: 'usuario' e 'usuario:1'
    return await this.repository.findById(id);
  }

  @CacheEvict({ tags: ['usuario', 'usuario:{0}'] })
  async update(id: number, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
    // Invalidará todas as entradas com tags 'usuario' ou 'usuario:1'
    return await this.repository.update(id, dto);
  }
}
```

### Exemplo 2: Invalidação em Cascata

```typescript
@Injectable()
export class UsuarioApplicationService {
  @CacheEvict({
    cascade: true,
    entityName: 'usuario'
  })
  async update(id: number, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
    // Automaticamente invalida:
    // - Cache de Eventos do usuário
    // - Cache de Lembretes do usuário
    // - Cache de Locais do usuário
    return await this.repository.update(id, dto);
  }
}
```

### Exemplo 3: Invalidação Parcial

```typescript
@Injectable()
export class UsuarioApplicationService {
  async refreshSpecificCache(userIds: number[]): Promise<void> {
    const invalidationService = container.resolve<ICacheInvalidationService>(
      TYPES.ICacheInvalidationService
    );

    // Invalidar apenas caches específicos
    const keys = userIds.map(id => `usuario:getById:${id}`);
    await invalidationService.invalidatePartial(keys);
  }
}
```

### Exemplo 4: Registrar Relacionamento Customizado

```typescript
// Em algum lugar da inicialização da aplicação
const invalidationService = container.resolve<ICacheInvalidationService>(
  TYPES.ICacheInvalidationService
);

// Registrar relacionamento customizado
invalidationService.registerCascadeRelationship('evento', {
  entity: 'lembrete',
  foreignKey: 'eventoId'
});

// Agora, quando atualizar Evento, Lembretes relacionados serão invalidados
```

## Relacionamentos Padrão

O `CacheInvalidationService` registra automaticamente os seguintes relacionamentos:

### Usuario → Entidades Relacionadas

Quando `Usuario` é atualizado, invalida cache de:
- **Evento** (via `usuarioId`)
- **Lembrete** (via `usuarioId`)
- **Local** (via `usuarioId`)

### Local → Entidades Relacionadas

Quando `Local` é atualizado, invalida cache de:
- **Evento** (via `localId`)

## Implementação Técnica

### Redis (Produção)

**Armazenamento de Tags**:
- Usa Redis Sets: `tag:cache:{tag}` → Set de chaves
- Cada tag tem um Set com todas as chaves que possuem essa tag
- TTL aplicado também no Set da tag (TTL + 1 minuto de margem)

**Invalidação por Tag**:
1. Buscar todas as chaves do Set da tag
2. Deletar todas as chaves
3. Deletar o Set da tag

### InMemory (Desenvolvimento)

**Armazenamento de Tags**:
- Usa `Map<string, Set<string>>` (tagIndex)
- Cada tag mapeia para um Set de chaves
- Tags armazenadas também na entrada do cache

**Invalidação por Tag**:
1. Buscar Set de chaves do índice
2. Deletar todas as chaves do cache
3. Remover tag do índice

### Vantagens

- **Invalidação Eficiente**: Invalidar grupos relacionados de uma vez
- **Consistência**: Garantir que dados relacionados sejam atualizados juntos
- **Flexibilidade**: Diferentes estratégias para diferentes cenários

## Considerações Importantes

### Boas Práticas

1. **Tags Descritivas**: Usar tags claras e consistentes
2. **Tags Granulares**: Usar tags específicas (ex: `usuario:1`) e genéricas (ex: `usuario`)
3. **Cascata Apropriada**: Usar cascata apenas quando necessário
4. **Invalidação Parcial**: Usar para casos específicos onde não quer invalidar tudo

### Tags Recomendadas

**Formato**:
- `{entity}` - Tag genérica da entidade (ex: `usuario`)
- `{entity}:{id}` - Tag específica do registro (ex: `usuario:1`)
- `{entity}:{method}` - Tag do método (ex: `usuario:getById`)

**Exemplo**:
```typescript
@Cacheable({
  key: 'usuario:getById:{0}',
  tags: ['usuario', 'usuario:{0}', 'usuario:getById']
})
async getById(id: number): Promise<UsuarioResponseDto | null> {
  // Tags: 'usuario', 'usuario:1', 'usuario:getById'
}
```

### Limitações

- **Tags no Redis**: Requer espaço adicional para Sets
- **Invalidação em Cascata**: Pode ser muito agressiva (invalida tudo da entidade relacionada)
- **Performance**: Invalidação por tag pode ser mais lenta que por padrão (depende do número de chaves)
