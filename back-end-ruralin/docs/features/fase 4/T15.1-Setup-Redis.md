## Contexto Técnico

### Por que Redis?

**Necessidades de negócio**:
- **Cache Distribuído**: Compartilhar cache entre múltiplas instâncias
- **Performance**: Reduzir carga no banco de dados
- **Escalabilidade**: Suportar crescimento da aplicação
- **Persistência**: Cache pode sobreviver a reinicializações

**Vantagens sobre InMemory**:
- ✅ Compartilhado entre instâncias
- ✅ Persistência opcional
- ✅ Melhor performance em grandes volumes
- ✅ Suporta estruturas de dados avançadas

## Configuração

### Variáveis de Ambiente

Configure o Redis via variáveis de ambiente:

```bash
# .env

# Opção 1: URL completa (recomendado para produção)
REDIS_URL=redis://localhost:6379
# ou com senha
REDIS_URL=redis://:password@localhost:6379

# Opção 2: Configuração individual
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_PASSWORD=  # Opcional
REDIS_DB=0       # Opcional, padrão: 0

# Forçar uso do Redis (mesmo sem REDIS_URL)
USE_REDIS=true
```

### Exemplo de Configuração

**Desenvolvimento Local**:

## Funcionalidades Implementadas

### 1. Conexão e Reconexão

**Características**:
- Conexão automática ao criar instância
- Reconexão automática em caso de falha
- Retry strategy com backoff exponencial
- Health check com ping

**Eventos tratados**:
- `connect` - Conectando
- `ready` - Pronto para uso
- `error` - Erro de conexão
- `close` - Conexão fechada
- `reconnecting` - Reconectando

### 2. Operações de Cache

**Métodos implementados**:
- `get<T>(key)` - Recupera valor
- `set(key, value, ttl?)` - Armazena valor
- `delete(key)` - Remove valor
- `clear()` - Limpa todo o cache
- `exists(key)` - Verifica existência
- `deleteByPattern(pattern)` - Remove por padrão

**Características**:
- Serialização JSON automática
- Suporte a TTL em segundos
- Tratamento de erros (não quebra aplicação)
- Logging de erros

### 3. Padrões de Invalidação

Suporte a padrões usando `SCAN` e `MATCH`:

```typescript
// Remove todas as chaves que começam com 'user:'
await cacheService.deleteByPattern('user:*');

// Remove todas as chaves que contêm 'permission'
await cacheService.deleteByPattern('*permission*');
```

### 4. Estatísticas e Debugging

Método `getStats()` para obter informações:

```typescript
const stats = await cacheService.getStats();
console.log(stats.connected); // true/false
console.log(stats.info);      // Informações do Redis
```

## Exemplos de Uso

### Exemplo 1: Uso Básico

```typescript
import { container } from '../core/di';
import { TYPES } from '../core/di/types';
import { ICacheService } from '../core/cache/ICacheService';

const cacheService = container.resolve<ICacheService>(TYPES.ICacheService);

// Armazenar valor
await cacheService.set('user:1', { id: 1, name: 'João' }, 3600);

// Recuperar valor
const user = await cacheService.get<{ id: number; name: string }>('user:1');

// Verificar existência
const exists = await cacheService.exists('user:1');

// Remover valor
await cacheService.delete('user:1');
```

### Exemplo 2: Cache com TTL

```typescript
// Cache por 1 hora (3600 segundos)
await cacheService.set('data', myData, 3600);

// Cache por 30 minutos (1800 segundos)
await cacheService.set('data', myData, 1800);

// Cache permanente (sem TTL)
await cacheService.set('data', myData);
```

### Exemplo 3: Invalidação por Padrão

```typescript
// Invalidar todos os caches de usuário
await cacheService.deleteByPattern('user:*');

// Invalidar todos os caches de permissões
await cacheService.deleteByPattern('auth:permission:*');
```

### Exemplo 4: Integração com AuthorizationService

O `AuthorizationService` já usa cache automaticamente:

```typescript
// Cache de permissões (já implementado)
const hasPermission = await authorizationService.hasPermission(userId, 'usuario.create');

// Cache de roles (já implementado)
const hasRole = await authorizationService.hasRole(userId, 'ADMIN');
```

## Integração com Sistema Existente

### Seleção Automática de Implementação

O sistema seleciona automaticamente a implementação:

```typescript
// registerServices.ts
const useRedis = process.env.USE_REDIS === 'true' || process.env.REDIS_URL !== undefined;
if (useRedis) {
  container.registerSingleton(TYPES.ICacheService, RedisCacheService);
} else {
  container.registerSingleton(TYPES.ICacheService, InMemoryCacheService);
}
```

## Tratamento de Erros

### Estratégia

**Falhas de conexão**:
- Não quebra a aplicação
- Loga erros para monitoramento
- Retorna valores padrão (null, false, 0)
- Reconexão automática

**Exemplo**:
```typescript
// Se Redis estiver offline, retorna null
const value = await cacheService.get('key'); // null se erro

// Se Redis estiver offline, não armazena (silenciosamente)
await cacheService.set('key', value); // Não lança erro
```

### Logging

Todos os erros são logados:
```
[ERROR] Redis client error: Connection refused
[ERROR] Error getting cache key "user:1": Connection refused
[WARN] Redis client connection closed
[INFO] Redis client reconnecting...
```

### Exemplo de Teste

```typescript
describe('RedisCacheService', () => {
  let cacheService: RedisCacheService;
  let redisClient: Redis;

  beforeAll(async () => {
    // Iniciar Redis de teste
    redisClient = new Redis({ port: 6379, db: 15 }); // DB de teste
    cacheService = new RedisCacheService(mockLogger);
  });

  afterAll(async () => {
    await redisClient.flushdb();
    await cacheService.disconnect();
    await redisClient.quit();
  });

  it('deve armazenar e recuperar valores', async () => {
    await cacheService.set('test', { data: 'value' });
    const value = await cacheService.get<{ data: string }>('test');
    expect(value).toEqual({ data: 'value' });
  });

  it('deve respeitar TTL', async () => {
    await cacheService.set('test', 'value', 1); // 1 segundo
    await new Promise(resolve => setTimeout(resolve, 1100));
    const value = await cacheService.get('test');
    expect(value).toBeNull();
  });
});
```

- Configurar backup automático
