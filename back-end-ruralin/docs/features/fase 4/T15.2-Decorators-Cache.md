## Funcionalidades Implementadas

### 1. Decorator @Cacheable

Cacheia resultado do método, verificando cache antes de executar.

**Sintaxe**:
```typescript
// Sintaxe simples: apenas key
@Cacheable('usuario:getById:{0}')

// Sintaxe simples: key e ttl
@Cacheable('usuario:getById:{0}', 3600)

// Sintaxe completa: opções
@Cacheable({ key: 'usuario:getById:{0}', ttl: 3600 })

// Key automática
@Cacheable() // ou @Cacheable(undefined, 3600)
```

**Comportamento**:
1. Verifica cache antes de executar
2. Se encontrado, retorna do cache
3. Se não encontrado, executa método
4. Cacheia resultado após execução

**Exemplo**:
```typescript
@Injectable()
export class UsuarioApplicationService {
  @Cacheable('usuario:getById:{0}', 3600)
  async getById(id: number): Promise<UsuarioResponseDto> {
    // Primeira chamada: executa método e cacheia
    // Chamadas subsequentes: retorna do cache
    return await this.repository.findById(id);
  }
}
```

### 2. Decorator @CacheEvict

Invalida cache quando método é executado.

**Sintaxe**:
```typescript
// Sintaxe simples: apenas key
@CacheEvict('usuario:getById:{0}')

// Sintaxe simples: key e allEntries
@CacheEvict('usuario:*', true)

// Sintaxe completa: opções
@CacheEvict({ 
  key: 'usuario:*', 
  allEntries: true, 
  beforeInvocation: false 
})

// Key automática
@CacheEvict()
```

**Comportamento**:
1. Executa método
2. Invalida cache após execução (padrão)
3. Suporta invalidação antes (`beforeInvocation: true`)
4. Suporta padrões para múltiplas chaves (`allEntries: true`)

**Exemplo**:
```typescript
@Injectable()
export class UsuarioApplicationService {
  @CacheEvict('usuario:getById:{0}')
  async update(id: number, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
    // Após atualização, cache será invalidado
    return await this.repository.update(id, dto);
  }

  @CacheEvict('usuario:*', true)
  async delete(id: number): Promise<boolean> {
    // Após exclusão, todos os caches de 'usuario:*' serão invalidados
    return await this.repository.delete(id);
  }
}
```

### 3. Decorator @CachePut

Atualiza cache com resultado do método (sempre executa método).

**Sintaxe**:
```typescript
// Sintaxe simples: apenas key
@CachePut('usuario:getById:{0}')

// Sintaxe simples: key e ttl
@CachePut('usuario:getById:{0}', 3600)

// Sintaxe completa: opções
@CachePut({ key: 'usuario:getById:{0}', ttl: 3600 })

// Key automática
@CachePut()
```

**Comportamento**:
1. Sempre executa método (não verifica cache)
2. Atualiza cache com resultado
3. Útil para refresh de cache

**Exemplo**:
```typescript
@Injectable()
export class UsuarioApplicationService {
  @CachePut('usuario:getById:{0}', 3600)
  async refreshCache(id: number): Promise<UsuarioResponseDto> {
    // Sempre executa e atualiza cache
    return await this.repository.findById(id);
  }
}
```

### 4. Geração Automática de Keys

Keys são geradas automaticamente se não fornecidas.

**Formato**:
```
{entityName}:{methodName}:{arg1}:{arg2}:...
```

**Exemplo**:
```typescript
// Classe: UsuarioApplicationService
// Método: getById
// Args: [1]
// Key gerada: 'usuario:getById:1'
```

**Normalização**:
- Remove sufixo `ApplicationService` do nome da classe
- Converte para lowercase
- Serializa argumentos de forma consistente

### 5. Placeholders em Keys

Suporte a placeholders para substituição de argumentos.

**Placeholders**:
- `{0}`, `{1}`, `{2}`, etc. - Índice do argumento
- `{*}` - Todos os argumentos restantes

**Exemplo**:
```typescript
@Cacheable('usuario:getById:{0}')
async getById(id: number): Promise<UsuarioResponseDto> {
  // Key: 'usuario:getById:1' (se id = 1)
}

@Cacheable('usuario:findByEmail:{0}')
async findByEmail(email: string): Promise<UsuarioResponseDto> {
  // Key: 'usuario:findByEmail:user@example.com'
}
```

## Exemplos de Uso

### Exemplo 1: Cache em Método de Leitura

```typescript
@Injectable()
export class UsuarioApplicationService {
  @Cacheable('usuario:getById:{0}', 3600)
  async getById(id: number): Promise<UsuarioResponseDto> {
    const entity = await this.repository.findById(id);
    return entity ? this.mapper.toDto(entity) : null;
  }

  @Cacheable('usuario:findByEmail:{0}', 1800)
  async findByEmail(email: string): Promise<UsuarioResponseDto | null> {
    const entity = await this.repository.findByEmail(email);
    return entity ? this.mapper.toDto(entity) : null;
  }
}
```

### Exemplo 2: Invalidação em Métodos de Escrita

```typescript
@Injectable()
export class UsuarioApplicationService {
  @RequirePermission('usuario.update')
  @CacheEvict('usuario:getById:{0}')
  @CacheEvict('usuario:*', true) // Invalidar todos os caches de usuario
  async update(id: number, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
    // Cache será invalidado após atualização
    return await this.repository.update(id, dto);
  }

  @RequirePermission('usuario.delete')
  @CacheEvict('usuario:getById:{0}')
  @CacheEvict('usuario:*', true)
  async delete(id: number): Promise<boolean> {
    // Cache será invalidado após exclusão
    return await this.repository.delete(id);
  }
}
```

### Exemplo 3: Múltiplos Decorators

```typescript
@Injectable()
export class UsuarioApplicationService {
  @RequirePermission('usuario.create')
  @Transactional()
  @Auditable('Usuario')
  @CacheEvict('usuario:*', true) // Invalidar cache de listagem
  async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
    // Ordem dos decorators:
    // 1. RequirePermission - Verifica permissão
    // 2. Transactional - Inicia transação
    // 3. Auditable - Registra auditoria
    // 4. CacheEvict - Invalida cache após criação
    return await this.repository.create(dto);
  }
}
```

### Exemplo 4: Refresh de Cache

```typescript
@Injectable()
export class UsuarioApplicationService {
  @CachePut('usuario:getById:{0}', 3600)
  async refreshCache(id: number): Promise<UsuarioResponseDto> {
    // Sempre executa e atualiza cache

```

### Exemplo 5: Key Automática

```typescript
@Injectable()
export class UsuarioApplicationService {
  @Cacheable() // Key gerada automaticamente: 'usuario:getById:1'
  async getById(id: number): Promise<UsuarioResponseDto> {
    return await this.repository.findById(id);
  }

  @Cacheable(undefined, 1800) // Key automática, TTL de 30 minutos
  async list(page: number, limit: number): Promise<PaginatedResult<UsuarioResponseDto>> {
    return await this.repository.findAllPaginated(page, limit);
  }
}
```

## Geração de Keys

### Formato de Key Automática

```
{entityName}:{methodName}:{arg1}:{arg2}:...
```

**Exemplo**:
- Classe: `UsuarioApplicationService`
- Método: `getById`
- Args: `[1]`
- Key: `usuario:getById:1`

### Serialização de Argumentos

**Tipos primitivos**:
- `number` → `"1"`
- `string` → `"value"`
- `boolean` → `"true"` ou `"false"`
- `null` → `"null"`
- `undefined` → `"null"`

**Objetos**:
- Serializados com `JSON.stringify` com chaves ordenadas
- Garante consistência mesmo com ordem diferente

**Exemplo**:
```typescript
@Cacheable()
async findByFilters(filters: { name: string; age: number }): Promise<UsuarioResponseDto[]> {
  // Key: 'usuario:findByFilters:{"age":30,"name":"João"}'
  // Chaves ordenadas alfabeticamente
}
```

### Placeholders

**Sintaxe**:
- `{0}` - Primeiro argumento
- `{1}` - Segundo argumento
- `{*}` - Todos os argumentos restantes

**Exemplo**:
```typescript
@Cacheable('usuario:getById:{0}')
async getById(id: number): Promise<UsuarioResponseDto> {
  // {0} será substituído por id
}

@Cacheable('usuario:findByEmailAndRole:{0}:{1}')
async findByEmailAndRole(email: string, role: string): Promise<UsuarioResponseDto> {
  // {0} = email, {1} = role
}
```

## Ordem dos Decorators

A ordem dos decorators importa. Ordem recomendada:

1. **Autorização** (`@RequirePermission`, `@RequireRole`)
2. **Transação** (`@Transactional`)
3. **Auditoria** (`@Auditable`)
4. **Cache** (`@Cacheable`, `@CacheEvict`, `@CachePut`)

**Exemplo**:
```typescript
@RequirePermission('usuario.update')
@Transactional()
@Auditable('Usuario')
@CacheEvict('usuario:getById:{0}')
async update(id: number, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
  // 1. Verifica permissão
  // 2. Inicia transação
  // 3. Captura estado antes (auditoria)
  // 4. Executa método
  // 5. Registra auditoria
  // 6. Invalida cache
  // 7. Commit transação
}
```

## Considerações Importantes

### Boas Práticas

1. **TTL Apropriado**: Usar TTL baseado em frequência de mudança
2. **Invalidação**: Sempre invalidar em métodos de escrita
3. **Keys Descritivas**: Usar keys claras e consistentes
4. **Padrões**: Usar padrões para invalidação em massa

### TTL Recomendado

- **Dados raramente mudam**: 24 horas (86400s)
- **Dados ocasionalmente mudam**: 1 hora (3600s)
- **Dados frequentemente mudam**: 5-15 minutos (300-900s)
- **Dados muito dinâmicos**: Não usar cache ou TTL muito curto

### Invalidação

**Quando invalidar**:
- `create` → Invalidar cache de listagem
- `update` → Invalidar cache do registro e listagem
- `delete` → Invalidar cache do registro e listagem

**Padrões úteis**:
- `usuario:*` - Todos os caches de usuario
- `usuario:getById:*` - Todos os caches de getById
- `usuario:list:*` - Todos os caches de listagem
