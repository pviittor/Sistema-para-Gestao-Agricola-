## Funcionalidades Implementadas

### 1. Análise de Métricas

**Conceito**:
Analisa métricas coletadas e identifica padrões, problemas e oportunidades de otimização.

**Métricas Analisadas**:
- Taxa de hit geral
- Chaves mais acessadas
- Chaves com maior número de misses
- Chaves problemáticas (alta taxa de miss)

**Exemplo**:
```typescript
const utils = new CacheOptimizationUtils(metricsService);
const analysis = utils.analyzeMetrics();

console.log(`Hit rate: ${(analysis.overallHitRate * 100).toFixed(2)}%`);
console.log(`Chaves problemáticas: ${analysis.problematicKeys.length}`);
```

### 2. Recomendações de TTL

**Conceito**:
Gera recomendações de TTL baseadas em análise de métricas.

**Tipos de Recomendações**:
- **Geral**: Baseada em taxa de hit geral
- **Específica**: Para chaves problemáticas
- **Otimização**: Para chaves muito acessadas

**Exemplo**:
```typescript
const recommendations = utils.getTTLRecommendations(analysis);

recommendations.forEach(rec => {
  console.log(`${rec.keyPattern}: TTL ${rec.recommendedTTL}s - ${rec.reason}`);
});
```

### 3. Otimização de Chaves

**Conceito**:
Otimiza geração de chaves de cache para melhor performance e menor uso de memória.

**Otimizações**:
- Remoção de espaços e caracteres especiais
- Normalização de separadores
- Redução de duplicatas

**Exemplo**:
```typescript
const optimized = utils.optimizeCacheKey('usuario:getById: 1 ');
// Retorna: 'usuario:getbyid:1'
```

### 4. Relatório de Otimização

**Conceito**:
Gera relatório completo com análise e recomendações.

**Conteúdo**:
- Taxa de hit/miss geral
- Chaves problemáticas
- Recomendações de TTL
- Recomendações gerais

**Exemplo**:
```typescript
const report = utils.generateOptimizationReport();
console.log(report);
```

## Estratégias de TTL

### TTL por Tipo de Dado

**Dados Estáticos** (ex: Roles, Permissões):
- **TTL Recomendado**: 24 horas (86400s)
- **Razão**: Dados raramente mudam

**Dados Semi-Estáticos** (ex: Usuários, Locais):
- **TTL Recomendado**: 1-2 horas (3600-7200s)
- **Razão**: Podem mudar ocasionalmente

**Dados Dinâmicos** (ex: Eventos, Lembretes):
- **TTL Recomendado**: 5-15 minutos (300-900s)
- **Razão**: Mudam frequentemente

**Listas Paginadas**:
- **TTL Recomendado**: 5 minutos (300s)
- **Razão**: Podem mudar com novas inserções

### TTL por Padrão de Acesso

**Alta Frequência** (muitos acessos):
- **TTL Recomendado**: Aumentar TTL
- **Razão**: Benefício maior de cache

**Baixa Frequência** (poucos acessos):
- **TTL Recomendado**: Manter ou reduzir TTL
- **Razão**: Menor benefício de cache

**Alta Taxa de Miss**:
- **TTL Recomendado**: Aumentar significativamente
- **Razão**: Cache não está sendo efetivo

## Otimização de Chaves

### Boas Práticas

1. **Consistência**: Use formato consistente para todas as chaves
2. **Brevidade**: Mantenha chaves curtas (menos memória)
3. **Legibilidade**: Use separadores claros (`:`)
4. **Normalização**: Normalize IDs e valores

### Formato Recomendado

```
{entity}:{method}:{params}
```

**Exemplos**:
- `usuario:getById:1`
- `usuario:list:1:10`
- `evento:findByLocal:5`

### Evitar

- ❌ Chaves muito longas
- ❌ Informações desnecessárias
- ❌ Caracteres especiais
- ❌ Espaços

---

## Guia de Boas Práticas

### 1. Escolha de TTL

**Regra Geral**:
- Dados que mudam raramente: TTL longo (horas/dias)
- Dados que mudam frequentemente: TTL curto (minutos)
- Dados críticos: TTL médio com invalidação agressiva

**Exemplo**:
```typescript
// Dados estáticos
@Cacheable({ key: 'role:getById:{0}', ttl: 86400 }) // 24 horas

// Dados semi-estáticos
@Cacheable({ key: 'usuario:getById:{0}', ttl: 3600 }) // 1 hora

// Dados dinâmicos
@Cacheable({ key: 'evento:getById:{0}', ttl: 300 }) // 5 minutos
```

### 2. Uso de Tags

**Quando Usar**:
- Para agrupar entradas relacionadas
- Para invalidação em cascata
- Para invalidação eficiente

**Exemplo**:
```typescript
@Cacheable({
  key: 'usuario:getById:{0}',
  ttl: 3600,
  tags: ['usuario', 'usuario:{0}']
})
```

### 3. Invalidação

**Estratégias**:
- **Por Chave**: Para atualizações específicas
- **Por Tag**: Para atualizações relacionadas
- **Por Padrão**: Para limpezas em massa
- **Em Cascata**: Para entidades relacionadas

**Exemplo**:
```typescript
@CacheEvict({ tags: ['usuario', 'usuario:{0}'] })
async update(id: number, dto: UpdateUsuarioDto) {
  // Invalida todas as entradas relacionadas ao usuário
}
```

### 4. Monitoramento

**Métricas Importantes**:
- Taxa de hit (objetivo: > 60%)
- Número de misses
- Chaves problemáticas
- Uso de memória

**Ações**:
- Monitorar regularmente
- Ajustar TTLs baseado em métricas
- Identificar padrões de uso

### 5. Performance

**Otimizações**:
- Use chaves curtas
- Evite serialização desnecessária
- Cache apenas dados necessários
- Use TTL apropriado

## Análise de Performance

### Interpretação de Métricas

**Taxa de Hit**:
- **> 80%**: Excelente - Cache muito eficiente
- **60-80%**: Bom - Cache funcionando bem
- **40-60%**: Aceitável - Pode melhorar
- **< 40%**: Baixo - Revisar estratégias

**Ações Baseadas em Taxa de Hit**:
- **< 40%**: Aumentar TTLs, revisar invalidação
- **40-60%**: Otimizar TTLs específicos
- **> 80%**: Manter estratégia atual

### Chaves Problemáticas

**Identificação**:
- Alta taxa de miss (> 70%)
- Muitos acessos (> 10)
- TTL muito curto

**Soluções**:
- Aumentar TTL
- Revisar estratégia de invalidação
- Considerar pré-carregamento

## Exemplos de Uso

### Exemplo 1: Análise de Métricas

```typescript
import { CacheOptimizationUtils } from '../core/cache/CacheOptimizationUtils';
import { container } from '../core/di/container';
import { TYPES } from '../core/di/types';
import { ICacheMetricsService } from '../core/cache/ICacheMetricsService';

const metricsService = container.resolve<ICacheMetricsService>(TYPES.ICacheMetricsService);
const utils = new CacheOptimizationUtils(metricsService);

// Analisar métricas
const analysis = utils.analyzeMetrics();

console.log('Taxa de Hit:', (analysis.overallHitRate * 100).toFixed(2) + '%');
console.log('Chaves Problemáticas:', analysis.problematicKeys.length);

// Obter recomendações
const recommendations = utils.getTTLRecommendations(analysis);
recommendations.forEach(rec => {
  console.log(`${rec.keyPattern}: TTL ${rec.recommendedTTL}s`);
});
```

### Exemplo 2: Gerar Relatório

```typescript
const report = utils.generateOptimizationReport();
console.log(report);

// Salvar em arquivo
fs.writeFileSync('cache-optimization-report.txt', report);
```

```typescript
const keys = [
```

## Considerações Importantes

### Boas Práticas

1. **Monitorar Regularmente**: Analisar métricas semanalmente
2. **Ajustar Incrementalmente**: Fazer mudanças graduais
3. **Testar Mudanças**: Validar melhorias antes de aplicar
4. **Documentar Decisões**: Registrar razões para TTLs escolhidos

### Limitações

- **Dados em Memória**: Métricas são em memória (não persistem)
- **Análise Manual**: Requer análise periódica
- **Contexto Específico**: TTLs dependem do contexto da aplicação

### Troubleshooting

**Problema**: Taxa de hit baixa mesmo com TTL alto
- **Solução**: Verificar se invalidação está muito agressiva

**Problema**: Cache muito grande
- **Solução**: Reduzir TTLs, revisar o que está sendo cacheado

**Problema**: Dados desatualizados
- **Solução**: Reduzir TTLs ou melhorar estratégia de invalidação
