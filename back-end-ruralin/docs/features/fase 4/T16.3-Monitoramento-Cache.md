## Funcionalidades Implementadas

### 1. Contadores de Hit/Miss

**Conceito**:
Conta acessos ao cache, diferenciando entre hits (cache encontrado) e misses (cache não encontrado).

**Implementação**:
- `recordHit(key?)` - Registra quando cache é encontrado
- `recordMiss(key?)` - Registra quando cache não é encontrado
- Contadores incrementais em memória

**Exemplo**:
```typescript
// Automaticamente registrado pelo cache service
await cacheService.get('usuario:getById:1');
// → Se encontrado: recordHit('usuario:getById:1')
// → Se não encontrado: recordMiss('usuario:getById:1')
```

### 2. Taxa de Hit

**Cálculo**:
```
hitRate = hits / (hits + misses)
missRate = misses / (hits + misses)
```

**Exemplo**:
- 100 hits, 50 misses
- hitRate = 100 / 150 = 0.6667 (66.67%)
- missRate = 50 / 150 = 0.3333 (33.33%)

### 3. Logging Automático

**Frequência**:
- Log a cada 100 hits
- Log a cada 100 misses

**Formato**:
```json
{
  "level": "info",
  "message": "Cache metrics",
  "hits": 1000,
  "misses": 500,
  "totalAccesses": 1500,
  "hitRate": "66.67%",
  "missRate": "33.33%",
  "sets": 200,
  "deletes": 50
}
```

### 4. Endpoint de Métricas

**GET /api/cache/metrics**:
```json
{
  "success": true,
  "data": {
    "hits": 1000,
    "misses": 500,
    "totalAccesses": 1500,
    "hitRate": 0.6667,
    "missRate": 0.3333,
    "sets": 200,
    "deletes": 50,
    "patternInvalidations": 10,
    "tagInvalidations": 5,
    "lastUpdated": 1704067200000
  }
}
```

**GET /api/cache/metrics?detailed=true**:
```json
{
  "success": true,
  "data": {
    "hits": 1000,
    "misses": 500,
    "totalAccesses": 1500,
    "hitRate": 0.6667,
    "missRate": 0.3333,
    "sets": 200,
    "deletes": 50,
    "patternInvalidations": 10,
    "tagInvalidations": 5,
    "lastUpdated": 1704067200000,
    "byKey": {
      "usuario:getById:1": {
        "hits": 50,
        "misses": 5
      },
      "usuario:list:1:10": {
        "hits": 30,
        "misses": 2
      }
    }
  }
}
```

**POST /api/cache/metrics/reset**:
```json
{
  "success": true,
  "message": "Cache metrics reset successfully"
}
```

### 5. Métricas Detalhadas por Chave

**Configuração**:
```env
CACHE_DETAILED_METRICS=true
```

**Funcionalidade**:
- Quando habilitado, rastreia hits/misses por chave individual
- Útil para identificar chaves problemáticas
- Consome mais memória (use com cuidado)

## Exemplos de Uso

### Exemplo 1: Consultar Métricas

```bash
# Métricas gerais
curl -X GET http://localhost:3000/api/cache/metrics \
  -H "Authorization: Bearer <token>"

# Métricas detalhadas
curl -X GET "http://localhost:3000/api/cache/metrics?detailed=true" \
  -H "Authorization: Bearer <token>"
```

### Exemplo 2: Resetar Métricas

```bash
curl -X POST http://localhost:3000/api/cache/metrics/reset \
  -H "Authorization: Bearer <token>"
```

### Exemplo 3: Usar Métricas Programaticamente

```typescript
const metricsService = container.resolve<ICacheMetricsService>(
  TYPES.ICacheMetricsService
);

// Obter métricas
const metrics = metricsService.getMetrics();
console.log(`Hit rate: ${(metrics.hitRate * 100).toFixed(2)}%`);

// Obter métricas detalhadas
const detailedMetrics = metricsService.getMetrics(true);
console.log('Top keys:', Array.from(detailedMetrics.byKey.entries())
  .sort((a, b) => b[1].hits - a[1].hits)
  .slice(0, 10));
```

### Exemplo 4: Monitorar Performance

```typescript
// Verificar se hit rate está abaixo do esperado
const metrics = metricsService.getMetrics();
if (metrics.hitRate < 0.5) {
  logger.warn('Cache hit rate is low', { hitRate: metrics.hitRate });
  // Ajustar TTLs ou estratégias de cache
}
```

## Métricas Coletadas

### Métricas Básicas

- **hits**: Número de hits (cache encontrado)
- **misses**: Número de misses (cache não encontrado)
- **totalAccesses**: Total de acessos (hits + misses)
- **hitRate**: Taxa de hit (0.0 a 1.0)
- **missRate**: Taxa de miss (0.0 a 1.0)

### Métricas de Operações

- **sets**: Número de escritas no cache
- **deletes**: Número de remoções do cache
- **patternInvalidations**: Número de invalidações por padrão
- **tagInvalidations**: Número de invalidações por tag

### Métricas de Tempo

- **lastUpdated**: Timestamp da última métrica registrada

### Métricas Detalhadas (Opcional)

- **byKey**: Map de chave -> { hits, misses }

## Performance

### Vantagens

- **Baixo Overhead**: Contadores incrementais são muito rápidos
- **Memória Eficiente**: Métricas básicas usam pouca memória
- **Logging Periódico**: Não impacta cada operação

### Considerações

- **Métricas Detalhadas**: Consomem mais memória (use com cuidado)
- **Thread Safety**: Contadores são thread-safe em Node.js (single-threaded)
- **Persistência**: Métricas são em memória (resetadas ao reiniciar)

## Análise de Métricas

### Interpretação de Taxa de Hit

- **> 80%**: Excelente - Cache muito eficiente
- **60-80%**: Bom - Cache funcionando bem
- **40-60%**: Aceitável - Pode melhorar
- **< 40%**: Baixo - Revisar estratégias de cache

### Ações Baseadas em Métricas

**Taxa de Hit Baixa**:
- Aumentar TTLs
- Revisar estratégias de invalidação
- Verificar se dados estão sendo cacheados corretamente

**Muitos Misses em Chaves Específicas**:
- Verificar se TTL está muito curto
- Verificar se invalidação está muito agressiva
- Considerar pré-carregamento

**Muitos Sets**:
- Verificar se há escrita excessiva
- Considerar estratégias de write-through vs write-back

## Considerações Importantes

### Boas Práticas

1. **Monitorar Regularmente**: Verificar métricas periodicamente
2. **Alertas**: Configurar alertas para hit rate baixo
3. **Análise**: Usar métricas para otimizar TTLs e estratégias
4. **Métricas Detalhadas**: Usar apenas quando necessário

### Limitações

- **Memória**: Métricas são em memória (não persistem)
- **Escalabilidade**: Em múltiplas instâncias, métricas são por instância
- **Precisão**: Contadores podem ter pequenas imprecisões em alta concorrência

### Troubleshooting

**Problema**: Métricas não estão sendo coletadas
- **Solução**: Verificar se `CacheMetricsService` está registrado

**Problema**: Hit rate muito baixo
- **Solução**: Revisar TTLs, estratégias de invalidação, e padrões de uso

**Problema**: Métricas detalhadas consumindo muita memória
- **Solução**: Desabilitar `CACHE_DETAILED_METRICS` ou limpar periodicamente
