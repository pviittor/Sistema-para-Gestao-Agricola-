# T15.3 - Cache no Repository

## Funcionalidades Implementadas

### 1. Cache em findById

**Comportamento**:
1. Gera chave de cache: `{entityName}:findById:{id}`
2. Verifica cache antes de executar query
3. Se encontrado no cache, retorna imediatamente
4. Se não encontrado, executa query no banco
5. Cacheia resultado (apenas se encontrado)
6. TTL padrão: 1 hora (3600 segundos)

**Exemplo**:
```typescript
// Primeira chamada: executa query e cacheia
const usuario1 = await usuarioRepository.findById(1);
// Key: 'usuario:findById:1'

// Segunda chamada: retorna do cache (sem query)
const usuario2 = await usuarioRepository.findById(1);
// Retorna do cache, não executa query
```

### 2. Cache em findAllPaginated

**Comportamento**:
1. Gera chave de cache: `{entityName}:findAllPaginated:{page}:{limit}:{options}`
2. Verifica cache antes de executar query
3. Se encontrado no cache, retorna imediatamente
4. Se não encontrado, executa query no banco
5. Cacheia resultado completo (data, total, page, limit, totalPages)
6. TTL padrão: 1 hora (3600 segundos)

**Exemplo**:
```typescript
// Primeira chamada: executa query e cacheia
const result1 = await usuarioRepository.findAllPaginated(1, 10);
// Key: 'usuario:findAllPaginated:1:10:{"where":{"tipo":"ROOT"}}'

// Segunda chamada: retorna do cache (sem query)
const result2 = await usuarioRepository.findAllPaginated(1, 10);
// Retorna do cache, não executa query
```

### 3. Invalidação Automática em create

**Comportamento**:
1. Executa `create` normalmente
2. Após criar, invalida cache de `findAllPaginated`
3. Usa padrão: `{entityName}:findAllPaginated:*`

**Exemplo**:
```typescript
// Criar novo usuário
await usuarioRepository.create({ nome: 'João', email: 'joao@example.com' });
// Invalida automaticamente: 'usuario:findAllPaginated:*'
// Próxima chamada de findAllPaginated executará query novamente
```

### 4. Invalidação Automática em update

**Comportamento**:
1. Busca entidade sem cache (para garantir versão mais recente)
2. Executa `update` normalmente
3. Após atualizar, invalida cache do registro específico (`findById`)
4. Invalida cache de listagem (`findAllPaginated`)

**Exemplo**:
```typescript
// Atualizar usuário
await usuarioRepository.update(1, { nome: 'João Atualizado' });
// Invalida automaticamente:
// - 'usuario:findById:1'
// - 'usuario:findAllPaginated:*'
```

### 5. Invalidação Automática em delete

**Comportamento**:
1. Busca entidade sem cache (para garantir versão mais recente)
2. Executa `delete` normalmente
3. Após deletar, invalida cache do registro específico (`findById`)
4. Invalida cache de listagem (`findAllPaginated`)

**Exemplo**:
```typescript
// Deletar usuário
await usuarioRepository.delete(1);
// Invalida automaticamente:
// - 'usuario:findById:1'
// - 'usuario:findAllPaginated:*'
```

## Geração de Chaves de Cache

### Formato de Chaves

**findById**:
```
{entityName}:findById:{id}
```

**Exemplo**:
- Entidade: `Usuario`
- ID: `1`
- Key: `usuario:findById:1`

**findAllPaginated**:
```
{entityName}:findAllPaginated:{page}:{limit}:{options}
```

**Exemplo**:
- Entidade: `Usuario`
- Page: `1`
- Limit: `10`
- Options: `{"where":{"tipo":"ROOT"}}`
- Key: `usuario:findAllPaginated:1:10:{"where":{"tipo":"ROOT"}}`

### Normalização de Nome da Entidade

O nome da entidade é normalizado:
- Remove sufixo `Model` se presente
- Converte para lowercase

**Exemplo**:
- `UsuarioModel` → `usuario`
- `Evento` → `evento`
- `Local` → `local`

### Serialização de Options

As `options` são serializadas com `JSON.stringify` com chaves ordenadas para garantir consistência:

```typescript
const options = { where: { tipo: 'ROOT' }, order: [['nome', 'ASC']] };
// Serializado como: '{"order":[["nome","ASC"]],"where":{"tipo":"ROOT"}}'
// Chaves ordenadas alfabeticamente
```

## TTL (Time To Live)

### TTL Padrão

**Valor padrão**: 3600 segundos (1 hora)

**Configuração**:
```typescript
protected readonly DEFAULT_CACHE_TTL = 3600;
```

### Personalização

Repositórios podem sobrescrever `DEFAULT_CACHE_TTL` para ajustar TTL:

```typescript
export class UsuarioRepository extends BaseRepository<Usuario> {
  protected readonly DEFAULT_CACHE_TTL = 1800; // 30 minutos

  constructor() {
    super(Usuario);
  }
}
```

## Invalidação de Cache

### Estratégia de Invalidação

**Operações de Leitura**:
- `findById` - Cacheia resultado
- `findAllPaginated` - Cacheia resultado

**Operações de Escrita**:
- `create` - Invalida cache de listagem
- `update` - Invalida cache do registro e listagem
- `delete` - Invalida cache do registro e listagem

### Padrões de Invalidação

**Cache Específico**:
```typescript
// Invalida apenas o registro específico
await this.cacheService.delete('usuario:findById:1');
```

**Cache por Padrão**:
```typescript
// Invalida todos os caches de listagem
await this.cacheService.deleteByPattern('usuario:findAllPaginated:*');
```

## Exemplos de Uso

### Exemplo 1: Cache Automático em findById

```typescript
// Application Service
@Injectable()
export class UsuarioApplicationService {
  constructor(
    @Inject(TYPES.IUsuarioRepository) private repository: IUsuarioRepository
  ) {}

  async getById(id: number): Promise<UsuarioResponseDto> {
    // Primeira chamada: executa query e cacheia
    // Chamadas subsequentes: retorna do cache
    const entity = await this.repository.findById(id);
    return entity ? this.mapper.toDto(entity) : null;
  }
}
```

### Exemplo 2: Cache Automático em findAllPaginated

```typescript
// Application Service
@Injectable()
export class UsuarioApplicationService {
  async list(page: number, limit: number): Promise<PaginatedResult<UsuarioResponseDto>> {
    // Primeira chamada: executa query e cacheia
    // Chamadas subsequentes com mesmos parâmetros: retorna do cache
    const result = await this.repository.findAllPaginated(page, limit);
    return {
      ...result,
      data: result.data.map(this.mapper.toDto),
    };
  }
}
```

### Exemplo 3: Invalidação Automática em create

```typescript
// Application Service
@Injectable()
export class UsuarioApplicationService {
  @RequirePermission('usuario.create')
  @Transactional()
  @Auditable('Usuario')
  async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
    // Após criar, cache de listagem é invalidado automaticamente
    const entity = await this.repository.create(dto);
    return this.mapper.toDto(entity);
  }
}
```

### Exemplo 4: Invalidação Automática em update

```typescript
// Application Service
@Injectable()
export class UsuarioApplicationService {
  @RequirePermission('usuario.update')
  @Transactional()
  @Auditable('Usuario')
  async update(id: number, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
    // Após atualizar, cache do registro e listagem são invalidados automaticamente
    const entity = await this.repository.update(id, dto);
    return this.mapper.toDto(entity);
  }
}
```

### Exemplo 5: Invalidação Automática em delete

```typescript

@Injectable()
export class UsuarioApplicationService {
  @RequirePermission('usuario.delete')
  @Transactional()
  @Auditable('Usuario')
  async delete(id: number): Promise<boolean> {
    // Após deletar, cache do registro e listagem são invalidados automaticamente

  }
```

## Integração com Sistema Existente

### Compatibilidade

O cache é totalmente transparente:
- ✅ Não requer mudanças no código que usa repositórios
- ✅ Funciona com todos os repositórios existentes
- ✅ Compatível com decorators (`@RequirePermission`, `@Transactional`, `@Auditable`)
- ✅ Funciona com `ICacheService` (InMemory ou Redis)

### Injeção de Dependência

O `ICacheService` é injetado automaticamente via DI:

```typescript
constructor(
  model: ModelStatic<T>,
  @Inject(TYPES.ICacheService) cacheService: ICacheService
) {
  this.model = model;
  this.cacheService = cacheService;
}
```

**Nota**: Todos os repositórios que estendem `BaseRepository` recebem automaticamente o `ICacheService` injetado.

## Performance

### Vantagens

- **Redução de Queries**: Menos acesso ao banco de dados
- **Latência**: Cache é muito mais rápido que queries SQL
- **Throughput**: Suporta mais requisições simultâneas
- **Escalabilidade**: Reduz carga no banco de dados

### Métricas Esperadas

**findById**:
- **Sem cache**: ~10-50ms (query SQL)
- **Com cache**: ~1-5ms (cache hit)
- **Melhoria**: 10-50x mais rápido

**findAllPaginated**:
- **Sem cache**: ~50-200ms (query SQL com count)
- **Com cache**: ~1-5ms (cache hit)
- **Melhoria**: 50-200x mais rápido

### Considerações

- **TTL**: Configurar TTL apropriado baseado em frequência de mudança
- **Memória**: Monitorar uso de memória do cache
- **Hit Rate**: Monitorar taxa de acertos do cache
- **Invalidação**: Invalidação automática garante consistência

## Considerações Importantes

### Boas Práticas

1. **TTL Apropriado**: Usar TTL baseado em frequência de mudança
2. **Invalidação**: Invalidação automática garante consistência
3. **Monitoramento**: Monitorar hit rate e uso de memória
4. **Cache Warming**: Considerar pre-carregar cache para dados críticos

### TTL Recomendado

- **Dados raramente mudam**: 24 horas (86400s)
- **Dados ocasionalmente mudam**: 1 hora (3600s) - **Padrão**
- **Dados frequentemente mudam**: 5-15 minutos (300-900s)
- **Dados muito dinâmicos**: Não usar cache ou TTL muito curto

### Limitações

- **Cache de null**: Resultados `null` não são cacheados (para evitar cache de "não encontrado")
- **Cache de listagem**: Apenas `findAllPaginated` é cacheado, não `findAll` (muito variável)
- **Transações**: Cache não considera transações (pode haver inconsistência temporária)
