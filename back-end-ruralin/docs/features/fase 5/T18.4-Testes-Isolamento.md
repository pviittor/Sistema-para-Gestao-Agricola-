### 1. Testes de Isolamento - BaseRepository

**Arquivo**: `src/tests/multi-tenancy/isolation.test.ts`

#### 1.1. Testes de findById

**Cenários**:
- ✅ Retorna entidade quando pertence ao tenant atual
- ✅ Retorna null quando entidade não pertence ao tenant atual
- ✅ Retorna null quando não há tenantId definido
- ✅ Valida cache por tenant
- ✅ Remove cache inválido de outro tenant

**Exemplo**:
```typescript
it('deve retornar entidade quando pertence ao tenant atual', async () => {
  const tenantId = 1;
  const entity = { id: 1, tenantId, nome: 'Teste' } as MockModel;
  mockTenantService.getCurrentTenantId.mockReturnValue(tenantId);
  (mockModel.findOne as jest.Mock).mockResolvedValue(entity);

  const result = await repository.findById(1);

  expect(result).toBe(entity);
  expect(mockModel.findOne).toHaveBeenCalledWith({
    where: { id: 1, tenantId },
  });
});
```

#### 1.2. Testes de findAll

**Cenários**:

**Exemplo**:

#### 1.3. Testes de create

**Cenários**:

**Exemplo**:

## Cenários de Teste

### 1. Isolamento de Dados

#### Cenário 1: Tenant A não acessa dados de Tenant B
- **Dado**: Tenant 1 e Tenant 2 com dados
- **Quando**: Tenant 1 busca dados
- **Então**: Retorna apenas dados de Tenant 1

#### Cenário 2: Queries filtradas por tenant
- **Dado**: Múltiplos tenants com dados
- **Quando**: Executa query com tenant específico
- **Então**: Retorna apenas dados do tenant atual

### 2. Segurança

#### Cenário 1: Bloqueio de acesso cross-tenant
- **Dado**: Tentativa de acessar dados de outro tenant
- **Quando**: Executa operação
- **Então**: Acesso negado (ForbiddenException)

#### Cenário 2: Validação de tenant em creates
- **Dado**: Tentativa de criar entidade sem tenantId
- **Quando**: Executa create
- **Então**: ForbiddenException lançada

#### Cenário 3: Validação de tenant em updates
- **Dado**: Tentativa de atualizar entidade de outro tenant
- **Quando**: Executa update
- **Então**: NotFoundException lançada

### 3. Cache

#### Cenário 1: Cache isolado por tenant
- **Dado**: Cache para Tenant 1 e Tenant 2
- **Quando**: Busca dados com diferentes tenants
- **Então**: Cache keys incluem tenantId e são diferentes

#### Cenário 2: Invalidação isolada
- **Dado**: Cache para Tenant 1 e Tenant 2
- **Quando**: Invalida cache de Tenant 1
- **Então**: Cache de Tenant 2 permanece intacto

## Decisões de Design

### 1. Estrutura de Testes

**Decisão**: Separar testes em arquivos específicos (isolation, security, integration)

**Razão**:
- Organização clara
- Facilita manutenção
- Permite execução seletiva

**Alternativa Considerada**: Todos os testes em um único arquivo
- Rejeitada: Difícil manutenção e navegação

### 2. Mocking de Dependências

**Decisão**: Mockar TenantService, CacheService e Repositories

**Razão**:
- Testes unitários rápidos
- Isolamento de dependências
- Facilita debugging

**Alternativa Considerada**: Usar instâncias reais
- Rejeitada: Testes mais lentos e dependentes de configuração

### 3. Testes de Integração

**Decisão**: Criar estrutura de testes de integração (execução requer banco real)

**Razão**:
- Validação end-to-end
- Testa integração completa
- Detecta problemas de integração

**Alternativa Considerada**: Apenas testes unitários
- Rejeitada: Não valida integração completa
