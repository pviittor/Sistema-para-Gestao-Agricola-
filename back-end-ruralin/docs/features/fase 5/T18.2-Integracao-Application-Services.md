## Implementação

### 1. Validações Cross-Tenant

**Objetivo**: Garantir que recursos relacionados pertencem ao mesmo tenant.

**Exemplo**: Ao criar um Evento, validar que o Local referenciado pertence ao mesmo tenant.

#### 1.1. EventoApplicationService

**Arquivo**: `src/application/services/evento/EventoApplicationService.ts`

**Validações Implementadas**:

##### create()

```typescript
async create(dto: CreateEventoDto): Promise<EventoResponseDto> {
  // Validação cross-tenant: verificar se local pertence ao mesmo tenant
  const local = await this.localRepository.findById(dto.localId);
  if (!local) {
    throw new NotFoundException('Local', dto.localId);
  }

  const currentTenantId = this.tenantService.getCurrentTenantId();
  if (currentTenantId && (local as any).tenantId !== currentTenantId) {
    throw new ForbiddenException(
      'Local não pertence ao tenant atual',
      'CROSS_TENANT_ACCESS_DENIED'
    );
  }

  // ... resto da lógica
}
```

**Características**:
- Valida que Local existe
- Valida que Local pertence ao mesmo tenant
- Lança `ForbiddenException` se cross-tenant

##### update()

```typescript
async update(id: number | string, dto: UpdateEventoDto): Promise<EventoResponseDto> {
  // Verificar se evento existe
  const existing = await this.repository.findById(id);
  if (!existing) {
    throw new NotFoundException('Evento', id);
  }

  // Validação cross-tenant: verificar se local pertence ao mesmo tenant (se fornecido)
  if (dto.localId) {
    const local = await this.localRepository.findById(dto.localId);
    if (!local) {
      throw new NotFoundException('Local', dto.localId);
    }

    const currentTenantId = this.tenantService.getCurrentTenantId();
    if (currentTenantId && (local as any).tenantId !== currentTenantId) {
      throw new ForbiddenException(
        'Local não pertence ao tenant atual',
        'CROSS_TENANT_ACCESS_DENIED'
      );
    }
  }

  // ... resto da lógica
}
```

**Características**:
- Valida Local apenas se `localId` for fornecido
- Valida que Local pertence ao mesmo tenant
- Lança `ForbiddenException` se cross-tenant

### 3. Integração com Repositories

**Isolamento Automático**:

Como os repositories já filtram automaticamente por tenantId (T18.1), as validações cross-tenant são complementares:

1. **Repository**: Filtra automaticamente por tenantId
2. **Application Service**: Valida recursos relacionados por tenant

**Exemplo de Fluxo**:

```typescript
// 1. Repository filtra automaticamente
const local = await this.localRepository.findById(dto.localId);
// Se local não pertence ao tenant, retorna null

// 2. Application Service valida explicitamente
if (!local) {
  throw new NotFoundException('Local', dto.localId);
}

if (currentTenantId && local.tenantId !== currentTenantId) {
  throw new ForbiddenException('Local não pertence ao tenant atual');
}
```

## Funcionalidades

### 1. Validação Cross-Tenant

**Quando Aplicar**:
- Ao criar/atualizar recursos que referenciam outros recursos
- Quando o recurso referenciado tem tenantId

**Exemplos**:
- Evento → Local (validado)
- Evento → Usuario (validado pelo tenantMiddleware)
- Lembrete → Usuario (validado pelo tenantMiddleware)

### 2. Isolamento Automático

**Níveis de Isolamento**:

1. **Middleware**: Identifica e valida tenant
2. **Repository**: Filtra automaticamente por tenantId
3. **Application Service**: Valida recursos relacionados

**Garantias**:
- Usuário só acessa dados do seu tenant
- Recursos relacionados pertencem ao mesmo tenant
- Impossível criar referências cross-tenant

### 3. Tratamento de Erros

**Erros Tratados**:

#### NotFoundException (404)

**Condição**: Recurso relacionado não existe

**Exemplo**:
```json
{
  "success": false,
  "error": {
    "code": "NOT_FOUND",
    "message": "Local não encontrado"
  }
}
```

#### ForbiddenException (403)

**Condição**: Recurso relacionado pertence a outro tenant

**Exemplo**:
```json
{
  "success": false,
  "error": {
    "code": "CROSS_TENANT_ACCESS_DENIED",
    "message": "Local não pertence ao tenant atual"
  }
}
```

## Integração

### 1. Com TenantMiddleware

**Fluxo Completo**:

1. **tenantMiddleware**: Identifica tenant e armazena no TenantService
2. **Application Service**: Obtém tenantId do TenantService
3. **Repository**: Filtra automaticamente por tenantId
4. **Application Service**: Valida recursos relacionados

### 2. Com BaseRepository

**Isolamento em Duas Camadas**:

1. **Repository**: Filtro automático em todas as queries
2. **Application Service**: Validação explícita de recursos relacionados

**Vantagens**:
- Defesa em profundidade
- Validação explícita e clara
- Prevenção de bugs cross-tenant

### 3. Com Authorization

**Integração com Permissões**:

- Validações cross-tenant são independentes de permissões
- Permissões controlam **o que** o usuário pode fazer
- Validações cross-tenant garantem **isolamento de dados**

## Uso

### Exemplo de Create com Validação Cross-Tenant

```typescript
// EventoApplicationService.create()
async create(dto: CreateEventoDto): Promise<EventoResponseDto> {
  // 1. Validar que Local existe e pertence ao tenant
  const local = await this.localRepository.findById(dto.localId);
  if (!local) {
    throw new NotFoundException('Local', dto.localId);
  }

  const currentTenantId = this.tenantService.getCurrentTenantId();
  if (currentTenantId && local.tenantId !== currentTenantId) {
    throw new ForbiddenException('Local não pertence ao tenant atual');
  }

  // 2. Criar evento (tenantId adicionado automaticamente pelo repository)
  const entity = await this.mapper.toEntity(dto);
  const created = await this.repository.create(entity);

  return this.mapper.toDto(created);
}
```

### Exemplo de Update com Validação Cross-Tenant

```typescript
// EventoApplicationService.update()
async update(id: number, dto: UpdateEventoDto): Promise<EventoResponseDto> {
  // 1. Verificar se evento existe (já filtrado por tenant)
  const existing = await this.repository.findById(id);
  if (!existing) {
    throw new NotFoundException('Evento', id);
  }

  // 2. Validar Local se fornecido
  if (dto.localId) {
    const local = await this.localRepository.findById(dto.localId);
    if (!local || local.tenantId !== this.tenantService.getCurrentTenantId()) {
      throw new ForbiddenException('Local não pertence ao tenant atual');
    }
  }

  // 3. Atualizar evento
  const entity = await this.mapper.toEntity(dto);
  const updated = await this.repository.update(id, entity);

  return this.mapper.toDto(updated);
}
```

## Decisões de Design

### 1. Validação Explícita vs. Implícita

**Decisão**: Validação explícita em Application Services

**Razão**:
- Mais clara e legível
- Mensagens de erro específicas
- Facilita debugging

**Alternativa Considerada**: Validação apenas no repository
- Rejeitada: Menos clara, mensagens de erro genéricas

### 2. Validação Condicional em Update

**Decisão**: Validar apenas se recurso relacionado for fornecido

**Razão**:
- Evita queries desnecessárias
- Permite atualizações parciais
- Melhor performance

**Alternativa Considerada**: Sempre validar
- Rejeitada: Queries desnecessárias, pior performance

### 3. ForbiddenException vs. BusinessException

**Decisão**: Usar `ForbiddenException` para erros cross-tenant

**Razão**:
- Erro de segurança (403)
- Consistente com outras validações de acesso
- Claro para o cliente

**Alternativa Considerada**: `BusinessException`
- Rejeitada: Erro de negócio (400), menos claro

## Notas de Implementação

### Considerações

1. **Validação Explícita**: Validações cross-tenant são explícitas e claras
2. **Defesa em Profundidade**: Isolamento em múltiplas camadas
3. **Performance**: Validações condicionais evitam queries desnecessárias
4. **Mensagens Claras**: Erros específicos para debugging

### Limitações Atuais

1. **Validações Manuais**: Cada Application Service precisa validar manualmente
2. **Sem Helper**: Não há helper genérico para validações cross-tenant
3. **Validações Específicas**: Validações são específicas para cada relacionamento

### Melhorias Futuras

1. **Helper Genérico**: Criar helper para validações cross-tenant
2. **Decorator**: Criar decorator para validações automáticas
3. **Validação Automática**: Validar automaticamente em BaseApplicationService
