# T18.1 - Filtro Automático no Repository

## Resumo Executivo

Implementação de filtro automático por `tenantId` no `BaseRepository` para garantir isolamento de dados em todas as queries. Todas as operações CRUD (create, read, update, delete) agora filtram automaticamente por tenant, garantindo que usuários só acessem dados do seu tenant.

  this.cacheService = cacheService;

#### 1.2. Método getTenantFilter()

```typescript
protected getTenantFilter(): { tenantId: number } | null {
  const tenantId = this.tenantService.getCurrentTenantId();
  if (!tenantId) {
    return null;
  }
  return { tenantId };
}
```

#### 1.3. Método isEntityFromCurrentTenant()

```typescript
protected isEntityFromCurrentTenant(entity: T): boolean {
  const tenantId = this.tenantService.getCurrentTenantId();
  if (!tenantId) {
    return false;
  }
  return (entity as any).tenantId === tenantId;
}
```

### 2. Métodos de Query Atualizados

#### 2.1. findById

**Antes**:
```typescript
async findById(id: number | string): Promise<T | null> {
  const result = await this.model.findByPk(id);
  return result;
}
```

**Depois**:
```typescript
async findById(id: number | string): Promise<T | null> {
  const tenantFilter = this.getTenantFilter();
  if (!tenantFilter) {
    return null;
  }

  const result = await this.model.findOne({
    where: {
      id,
      ...tenantFilter,
    } as any,
  });

  return result;
}
```

**Características**:
- Filtra por tenantId automaticamente
- Valida cache por tenant
- Retorna null se não houver tenantId

#### 2.2. findAll

**Antes**:
```typescript
async findAll(options?: FindOptions): Promise<T[]> {
  return await this.model.findAll({
    where: options?.where,
    // ...
  });
}
```

**Depois**:
```typescript
async findAll(options?: FindOptions): Promise<T[]> {
  const tenantFilter = this.getTenantFilter();
  if (!tenantFilter) {
    return [];
  }

  return await this.model.findAll({
    where: {
      ...options?.where,
      ...tenantFilter,
    } as any,
    // ...
  });
}
```

**Características**:
- Combina filtros do usuário com filtro de tenant
- Retorna array vazio se não houver tenantId

#### 2.3. findOne

Similar a `findAll`, mas retorna uma única entidade.

#### 2.4. findAllPaginated

Similar a `findAll`, mas com paginação e cache isolado por tenant.

### 3. Métodos de Mutação Atualizados

#### 3.1. create

**Antes**:
```typescript
async create(entity: Partial<T>): Promise<T> {
  const result = await this.model.create(entity as any);
  return result;
}
```

**Depois**:
```typescript
async create(entity: Partial<T>): Promise<T> {
  const tenantFilter = this.getTenantFilter();
  if (!tenantFilter) {
    throw new ForbiddenException('Tenant não identificado');
  }

  const entityWithTenant = {
    ...entity,
    ...tenantFilter,
  } as any;

  const result = await this.model.create(entityWithTenant);
  return result;
}
```

**Características**:
- Adiciona tenantId automaticamente
- Lança exceção se não houver tenantId
- Previne criação sem tenant

#### 3.2. update

**Antes**:
```typescript
async update(id: number | string, entity: Partial<T>): Promise<T> {
  const instance = await this.model.findByPk(id);
  if (!instance) {
    throw new NotFoundException('Entidade', id);
  }
  await instance.update(entity);
  return instance;
}
```

**Depois**:
```typescript
async update(id: number | string, entity: Partial<T>): Promise<T> {
  const tenantFilter = this.getTenantFilter();
  if (!tenantFilter) {
    throw new ForbiddenException('Tenant não identificado');
  }

  const instance = await this.model.findOne({
    where: {
      id,
      ...tenantFilter,
    } as any,
  });

  if (!instance) {
    throw new NotFoundException('Entidade', id);
  }

  // Garantir que tenantId não seja alterado
  const entityWithoutTenant = { ...entity };
  if ('tenantId' in entityWithoutTenant) {
    delete (entityWithoutTenant as any).tenantId;
  }

  await instance.update(entityWithoutTenant);
  return instance;
}
```

**Características**:
- Valida que entidade pertence ao tenant
- Previne alteração de tenantId
- Lança NotFoundException se não encontrar (por segurança)

#### 3.3. delete

Similar a `update`, mas deleta a entidade após validação.

### 4. Cache Isolado por Tenant

#### 4.1. Chaves de Cache Atualizadas

**Antes**:
```typescript
protected getFindByIdCacheKey(id: number | string): string {
  return `${entityName}:findById:${id}`;
}
```

**Depois**:
```typescript
protected getFindByIdCacheKey(id: number | string): string {
  const entityName = this.getEntityName();
  const tenantId = this.tenantService.getCurrentTenantId() || 'no-tenant';
  return `${entityName}:tenant:${tenantId}:findById:${id}`;
}
```

**Características**:
- Inclui tenantId na chave
- Isolamento completo de cache
- Previne vazamento de dados entre tenants

#### 4.2. Invalidação de Cache

```typescript
protected async invalidateFindAllCache(): Promise<void> {
  const entityName = this.getEntityName();
  const tenantId = this.tenantService.getCurrentTenantId() || '*';
  const pattern = `${entityName}:tenant:${tenantId}:findAllPaginated:*`;
  await this.cacheService.deleteByPattern(pattern);
}
```

## Tratamento de Erros

### Erros Tratados

#### 1. Tenant Não Identificado (403)

**Condição**: `getTenantFilter()` retorna `null` em operações de mutação

**Resposta**:
```json
{
  "success": false,
  "error": {
    "code": "TENANT_NOT_IDENTIFIED",
    "message": "Tenant não identificado. Não é possível criar/atualizar/deletar entidade sem tenantId."
  }
}
```

#### 2. Entidade Não Encontrada (404)

**Condição**: Entidade não existe ou pertence a outro tenant

**Resposta**:
```json
{
  "success": false,
  "error": {
    "code": "NOT_FOUND",
    "message": "Entidade não encontrada"
  }
}
```

## Integração

### 1. Com TenantService

O `BaseRepository` utiliza `TenantService` para:
- Obter tenantId atual: `getCurrentTenantId()`
- Validar tenant: `validateTenant()`

### 2. Com Middleware de Tenant

O `tenantMiddleware` define o tenantId no `TenantService`, que é então usado automaticamente pelo `BaseRepository`.

**Fluxo**:
1. `tenantMiddleware` identifica tenant
2. `TenantService.setCurrentTenantId()` armazena tenantId
3. `BaseRepository.getTenantFilter()` obtém tenantId
4. Queries filtram automaticamente por tenantId

### 3. Com Application Services

Application Services não precisam mais filtrar manualmente:

**Antes**:
```typescript
async index(): Promise<Evento[]> {
  const tenantId = this.tenantService.getCurrentTenantId();
  return await this.eventoRepository.findAll({
    where: { tenantId },
  });
}
```

**Depois**:
```typescript
async index(): Promise<Evento[]> {
  return await this.eventoRepository.findAll();
  // Filtro automático por tenantId
}
```

## Decisões de Design

### 1. Filtro Automático Obrigatório

**Decisão**: Todos os métodos filtram por tenantId automaticamente

**Razão**:
- Garante isolamento de dados
- Previne vazamento de dados entre tenants
- Simplifica Application Services

**Alternativa Considerada**: Filtro opcional
- Rejeitada: Pode levar a bugs de segurança

### 2. Retorno Vazio/Null Sem TenantId

**Decisão**: Retorna vazio/null se não houver tenantId em queries

**Razão**:
- Comportamento seguro (fail-safe)
- Previne vazamento de dados
- Consistente com validação de tenant

**Alternativa Considerada**: Lançar exceção
- Rejeitada: Pode quebrar código legado

### 3. Cache Isolado por Tenant

**Decisão**: Incluir tenantId em todas as chaves de cache

**Razão**:
- Previne vazamento de cache entre tenants
- Melhora performance (cache específico)
- Facilita invalidação por tenant

**Alternativa Considerada**: Cache compartilhado
- Rejeitada: Risco de vazamento de dados

### 4. Prevenção de Alteração de tenantId

**Decisão**: Remover tenantId de dados em update

**Razão**:
- Previne mudança acidental de tenant
- Mantém integridade de dados
- Segurança adicional

**Alternativa Considerada**: Permitir alteração
- Rejeitada: Risco de segurança

## Notas de Implementação

### Considerações

1. **Isolamento Transparente**: Application Services não precisam mais filtrar manualmente
2. **Segurança por Padrão**: Filtro automático previne vazamento de dados
3. **Cache Isolado**: Cache separado por tenant melhora performance e segurança
4. **Validação Automática**: Updates/deletes validam tenant automaticamente

### Limitações Atuais

1. **Sem Suporte a Queries Raw**: Queries SQL raw não são filtradas automaticamente
2. **Sem Suporte a Transações Multi-Tenant**: Transações não podem acessar múltiplos tenants
3. **Role/Permissao**: Role e Permissao podem não ter tenantId (entidades globais)

### Melhorias Futuras

1. **Índices Compostos**: Criar índices (tenantId, id) para melhor performance
2. **Queries Raw**: Adicionar suporte a filtro automático em queries SQL raw
3. **Transações Multi-Tenant**: Suporte a transações que acessam múltiplos tenants (se necessário)
