## Migrations Criadas

### Migration 1: Adicionar tenantId em usuarios

**Arquivo**: `src/migrations/20240101000001-add-tenantId-to-usuarios.ts`

**Descrição**: Adiciona a coluna `tenantId` na tabela `usuarios` e cria o índice correspondente.

**Operações**:
- Adiciona coluna `tenantId INT NULL` após `id`
- Cria índice `idx_usuarios_tenantId` na coluna `tenantId`

**Código**:
```typescript
export async function up(queryInterface: QueryInterface): Promise<void> {
  await queryInterface.addColumn('usuarios', 'tenantId', {
    type: DataTypes.INTEGER,
    allowNull: true, // Será populado na migração de dados, depois será NOT NULL
    comment: 'ID do tenant ao qual o usuário pertence',
    after: 'id',
  });

  await queryInterface.addIndex('usuarios', ['tenantId'], {
    name: 'idx_usuarios_tenantId',
  });
}

export async function down(queryInterface: QueryInterface): Promise<void> {
  await queryInterface.removeIndex('usuarios', 'idx_usuarios_tenantId');
  await queryInterface.removeColumn('usuarios', 'tenantId');
}
```

### Migration 2: Adicionar tenantId em tabelas dependentes

**Arquivo**: `src/migrations/20240101000002-add-tenantId-to-dependent-tables.ts`

## Decisões de Design

### 1. Tipo de Dados

**Decisão**: `INTEGER` (number)

**Razão**:
- Simples e eficiente
- Compatível com IDs de usuários (que serão usados como tenantId para ROOTs)
- Suporta índices eficientes

### 2. Nullable Inicialmente

**Decisão**: `allowNull: true` inicialmente, depois `NOT NULL`

**Razão**:
- Permite adicionar coluna sem quebrar dados existentes
- Facilita migração incremental
- Será alterado para `NOT NULL` após população

### 3. Posicionamento da Coluna

**Decisão**: Coluna `tenantId` após `id`

**Razão**:
- Facilita leitura e manutenção
- Padrão comum em sistemas multi-tenant
- Não afeta performance

### 4. Índices

**Decisão**: Criar índice em todas as tabelas com `tenantId`

**Razão**:
- Queries filtradas por tenant serão muito comuns
- Melhora significativamente a performance
- Essencial para isolamento eficiente

---

## Tabelas Não Modificadas

### Roles e Permissões

**Decisão**: Não adicionar `tenantId` em `roles` e `permissoes` inicialmente

**Razão**:
- Estratégia inicial: dados compartilhados (tenantId = NULL)
- Pode ser migrado para isolados depois se necessário
- Simplifica implementação inicial

**Tabelas**:
- `roles` - Não tem `tenantId`
- `permissoes` - Não tem `tenantId`
- `role_has_permissao` - Não tem `tenantId`
