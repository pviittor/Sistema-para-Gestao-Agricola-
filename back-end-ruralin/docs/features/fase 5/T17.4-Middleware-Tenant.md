# T17.4 - Middleware de Tenant

## Implementação

### 1. Middleware tenantMiddleware

**Arquivo**: `src/middleware/tenant.ts`

**Funcionalidades**:
- Extrai tenantId do token JWT (usuário autenticado) ou header `X-Tenant-ID`
- Valida tenant usando `TenantService.validateTenant()`
- Armazena tenantId no `TenantService` e `Request`
- Adiciona tenantId ao `RequestContext` se disponível
- Trata erros (BadRequestException, ForbiddenException)

**Código Principal**:
```typescript
export const tenantMiddleware = async (
  req: Request,
  res: Response,
  next: NextFunction
): Promise<void> => {
  const tenantService = container.resolve<ITenantService>(TYPES.ITenantService);
  
  // Extrair tenantId
  const tenantId = await extractTenantId(req);
  
  if (!tenantId) {
    throw new BadRequestException('Tenant não identificado');
  }
  
  // Validar tenant
  const isValid = await tenantService.validateTenant(tenantId);
  if (!isValid) {
    throw new ForbiddenException('Acesso negado ao tenant');
  }
  
  // Armazenar tenantId
  tenantService.setCurrentTenantId(tenantId);
  (req as any).tenantId = tenantId;
  
  next();
};
```

### 2. Função extractTenantId

**Ordem de Prioridade**:
1. **Token JWT**: Extrai `tenantId` do usuário autenticado (via `req.userId`)
2. **Header X-Tenant-ID**: Extrai do header HTTP

**Lógica**:
```typescript
async function extractTenantId(req: Request): Promise<number | null> {
  // Prioridade 1: Do usuário autenticado
  if (req.userId) {
    const usuario = await Usuario.findByPk(req.userId, {
      attributes: ['id', 'tenantId'],
    });
    if (usuario?.tenantId) {
      return usuario.tenantId;
    }
  }
  
  // Prioridade 2: Do header
  const tenantHeader = req.headers['x-tenant-id'];
  if (tenantHeader) {
    const tenantId = parseInt(tenantHeader as string, 10);
    if (!isNaN(tenantId) && tenantId > 0) {
      return tenantId;
    }
  }
  
  return null;
}
```

## Ordem de Middlewares

### Ordem Recomendada

1. **requestContextMiddleware**: Cria RequestContext
2. **authMiddleware**: Autentica usuário (se rota protegida)
3. **tenantMiddleware**: Identifica e valida tenant
4. **authorizationMiddleware**: Verifica permissões (se necessário)
5. **Controller**: Processa requisição

### Exemplo de Uso

```typescript
import { tenantMiddleware } from './middleware/tenant';
import { authMiddleware } from './middleware/auth';
import { requirePermission } from './middleware/authorization';

router.get('/eventos',
  authMiddleware,
  tenantMiddleware,
  requirePermission('evento.read'),
  eventoController.index
);
```

## Funcionalidades

### 1. Extração de TenantId

**Prioridade 1 - Token JWT**:
- Busca usuário autenticado (`req.userId`)
- Retorna `usuario.tenantId`
- Mais seguro (baseado em autenticação)

**Prioridade 2 - Header X-Tenant-ID**:
- Extrai do header HTTP
- Útil para APIs públicas ou casos especiais
- Menos seguro (pode ser falsificado)

### 2. Validação de Tenant

**Validações Realizadas**:
1. TenantId válido (número positivo)
2. Tenant existe (há usuários com o tenantId)
3. Usuário tem acesso (se autenticado, verifica se pertence ao tenant)

**Erros**:
- `BadRequestException` (400): Tenant não identificado
- `ForbiddenException` (403): Acesso negado ao tenant

### 3. Armazenamento de TenantId

**Locais**:
- `TenantService.currentTenantId`: Para uso em services
- `req.tenantId`: Para uso em controllers/middlewares
- `req.context.tenantId`: Para uso em RequestContext (se disponível)

## Tratamento de Erros

### Erros Tratados

**Condição**: `extractTenantId()` retorna `null`

**Resposta**:
```json

    "code": "TENANT_NOT_IDENTIFIED",

  "timestamp": "2024-01-01T00:00:00.000Z",

```

## Integração

### 1. Com authMiddleware

O `tenantMiddleware` funciona **após** o `authMiddleware`:
- `authMiddleware` define `req.userId`
- `tenantMiddleware` usa `req.userId` para buscar `tenantId`

**Ordem**:
```typescript
router.get('/eventos',
  authMiddleware,      // 1. Autentica usuário
  tenantMiddleware,    // 2. Identifica tenant
  eventoController.index
);
```

### 2. Com requestContextMiddleware

O `tenantMiddleware` adiciona `tenantId` ao `RequestContext`:
- `requestContextMiddleware` cria `req.context`
- `tenantMiddleware` adiciona `tenantId` ao contexto

**Ordem**:
```typescript
app.use(requestContextMiddleware);  // 1. Cria contexto
// ... outros middlewares
app.use('/api', routes);            // 2. Rotas (com tenantMiddleware)
```

### 3. Com TenantService

O middleware utiliza `TenantService` para:
- Validar tenant: `validateTenant(tenantId)`
- Armazenar tenantId: `setCurrentTenantId(tenantId)`

## Decisões de Design

### 1. Ordem de Prioridade

**Decisão**: Token JWT primeiro, header depois

**Razão**:
- Token JWT é mais seguro (baseado em autenticação)
- Header permite flexibilidade para casos especiais
- Header pode ser usado quando não há autenticação

### 2. Validação Obrigatória

**Decisão**: Middleware valida tenant em todas as requisições

**Razão**:
- Garante isolamento de dados
- Previne acesso não autorizado
- Consistência em todo o sistema

**Alternativa Considerada**: Validação opcional
- Rejeitada: Pode levar a bugs de segurança

### 3. Armazenamento Múltiplo

**Decisão**: Armazenar em `TenantService`, `req.tenantId` e `req.context.tenantId`

**Razão**:
- `TenantService`: Para uso em services via DI
- `req.tenantId`: Para uso direto em controllers
- `req.context.tenantId`: Para uso em RequestContext

## Notas de Implementação

### Considerações

1. **Middleware Assíncrono**: O middleware é `async` para permitir queries ao banco
2. **Ordem Importante**: Deve ser usado após `authMiddleware` e `requestContextMiddleware`
3. **Validação Obrigatória**: Todas as rotas protegidas devem usar este middleware
4. **Tratamento de Erros**: Erros são lançados como exceções customizadas

### Limitações Atuais

1. **Sem Cache**: Validações fazem queries ao banco a cada requisição (pode ser otimizado)
2. **Header Opcional**: Header `X-Tenant-ID` é opcional (pode ser obrigatório depois)
3. **Sem Suporte a Multi-Tenant por Subdomínio**: Suporte apenas por header/token

### Melhorias Futuras

1. **Cache de Validação**: Cachear validações de tenant para reduzir queries
2. **Suporte a Subdomínio**: Identificar tenant por subdomínio (ex: tenant1.app.com)
3. **Validação Opcional**: Permitir rotas públicas sem validação de tenant
