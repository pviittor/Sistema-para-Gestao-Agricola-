## Decisões de Implementação

### Abordagem Escolhida

**Application Service Pattern**:
- Separa controllers (HTTP) da lógica de negócio
- Centraliza regras de negócio em um único lugar
- Facilita testes e manutenção
- Reutilizável em diferentes contextos

**Integração com Dependências**:
- Usa `IFinanceiroRepository` para acesso a dados
- Usa `FinanceiroMapper` para conversão DTO-Entidade
- Injeta dependências via DI container

**Validações de Negócio**:
- Verifica se data de vencimento é posterior ou igual à data de emissão
- Verifica se valor não é zero
- Lança exceções apropriadas (`BusinessException`, `NotFoundException`)

**Sistema de Tipos**:
- Valores positivos representam RECEITA
- Valores negativos representam DESPESA
- Zero não é permitido

## Métodos Implementados

### `create(dto: CreateFinanceiroDto): Promise<FinanceiroResponseDto>`

Cria um novo registro financeiro com validações de negócio.

**Implementação**:
```typescript
async create(dto: CreateFinanceiroDto): Promise<FinanceiroResponseDto> {
  // Validação: verificar se data de vencimento é posterior ou igual à data de emissão
  const dataEmissao = new Date(dto.dataEmissao);
  const dataVencimento = new Date(dto.dataVencimento);
  
  if (dataVencimento < dataEmissao) {
    throw new BusinessException('Data de vencimento deve ser posterior ou igual à data de emissão');
  }

  // Validação: verificar se valor não é zero
  if (dto.valor === 0) {
    throw new BusinessException('Valor não pode ser zero');
  }

  // Converter DTO para entidade
  const entity = await this.mapper.toEntity(dto);

  // Criar via repositório
  const created = await this.repository.create(entity as any);

  // Retornar como DTO
  return this.mapper.toDto(created);
}
```

**Validações**:
- ✅ Data de vencimento deve ser posterior ou igual à data de emissão
- ✅ Valor não pode ser zero
- ✅ Validações de DTO (via middleware)

**Exemplo de Uso**:
```typescript
const service = container.resolve<IFinanceiroApplicationService>(TYPES.IFinanceiroApplicationService);

const registro = await service.create({
  dataEmissao: '2025-01-20',
  dataVencimento: '2025-01-25',
  valor: 1500.50, // Receita (positivo)
  // ...
});
```

```typescript
  const existing = await this.repository.findById(id);
  if (!existing) {
    throw new NotFoundException('Registro financeiro', id);
  }

  // Validação: verificar datas (se fornecidas)
  if (dto.dataEmissao && dto.dataVencimento) {
    // ... validação de datas
  }

  // Validação: verificar se valor não é zero (se fornecido)
  if (dto.valor !== undefined && dto.valor === 0) {
    throw new BusinessException('Valor não pode ser zero');
  }

  // Converter DTO para entidade
  const entity = await this.mapper.toEntity(dto);

  // Atualizar via repositório

  // Retornar como DTO

}
```

**Validações**:

## Validações de Negócio

### Regras Implementadas

1. **Data de vencimento deve ser posterior ou igual à data de emissão**:
   - Verificado no `create`
   - Verificado no `update` (se datas alteradas)
   - Lança `BusinessException` se violado

2. **Valor não pode ser zero**:
   - Verificado no `create`
   - Verificado no `update` (se valor alterado)
   - Lança `BusinessException` se violado

3. **Registro Deve Existir**:
   - Verificado no `update` e `delete`
   - Lança `NotFoundException` se não encontrado

### Exceções Utilizadas

- **`BusinessException`**: Para violações de regras de negócio (datas inválidas, valor zero)
- **`NotFoundException`**: Para recursos não encontrados (registro não existe)

## Sistema de Tipos Financeiros

### Receita vs Despesa

O sistema diferencia receitas e despesas pelo sinal do valor:

- **RECEITA**: Valores positivos (>= 0)
- **DESPESA**: Valores negativos (< 0)

**Exemplos**:
```typescript

  valor: 1500.50, // Positivo = Receita
  // ...
});

// Despesa

  // ...
});
```

**Busca por Tipo**:

## Comparação: Antes vs Depois

### Antes (Lógica no Controller)

```typescript
@Injectable()
export class FinanceiroController {
  async create(req: Request, res: Response) {
    // Lógica de negócio no controller ❌
    if (req.body.valor === 0) {
      return res.status(400).json({ error: 'Valor não pode ser zero' });
    }
    
    const registro = await Financeiro.create(req.body);
    return res.status(201).json(registro);
  }
}
```

**Problemas**:
- ❌ Lógica de negócio misturada com HTTP
- ❌ Difícil reutilizar em outros contextos
- ❌ Difícil testar isoladamente

### Depois (Com Application Service)

```typescript
@Injectable()
export class FinanceiroController {
  constructor(
    @Inject(TYPES.IFinanceiroApplicationService)
    private service: IFinanceiroApplicationService
  ) {}

  async create(req: Request, res: Response) {
    // Controller apenas orquestra HTTP ✅
    const dto = req.body as CreateFinanceiroDto;
    const registro = await this.service.create(dto);
    return res.status(201).json(registro);
  }
}
```

**Benefícios**:
- ✅ Controller focado em HTTP
- ✅ Lógica de negócio no service
- ✅ Fácil reutilizar service
- ✅ Fácil testar isoladamente
