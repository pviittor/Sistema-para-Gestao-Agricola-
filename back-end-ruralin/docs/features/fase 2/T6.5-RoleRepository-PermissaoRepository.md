## Decisões de Implementação

### Abordagem Escolhida

**Extensão de BaseRepository**:
- `RoleRepository` e `PermissaoRepository` estendem `BaseRepository` para herdar métodos CRUD
- Implementam suas respectivas interfaces para definir métodos customizados
- Usam `@Injectable` para integração com DI container
- Métodos customizados utilizam `findOne` do BaseRepository com filtros específicos

**Busca por Nome**:
- Ambos os repositórios implementam `findByNome` para busca por nome
- A busca é case-sensitive (diferencia maiúsculas de minúsculas)
- Retorna `null` se não encontrar

**Simplicidade**:
- Como `Role` e `Permissao` são entidades simples (apenas `id` e `nome`), não foram necessários métodos adicionais complexos
- Métodos CRUD padrão do BaseRepository são suficientes para a maioria dos casos de uso

## Métodos Implementados

### RoleRepository

#### `findByNome(nome: string): Promise<Role | null>`

Busca uma role por nome.

**Implementação**:
```typescript
async findByNome(nome: string): Promise<Role | null> {
  return await this.findOne({ where: { nome } });
}
```

**Exemplo de Uso**:
```typescript
const role = await roleRepository.findByNome('ADMIN');
if (role) {
  console.log(`Role encontrada: ${role.nome}`);
}
```

**Características**:
- Busca case-sensitive
- Retorna `null` se não encontrar
- Útil para verificar existência de roles antes de criar

**Casos de Uso**:
- Verificar se uma role existe antes de criar
- Buscar role por nome em sistemas de autorização
- Validação de roles em middlewares

### Uso em Application Services

```typescript
import { Injectable, Inject } from '../../core/di';
import { TYPES } from '../../core/di/types';
import { IRoleRepository } from '../../infrastructure/repository/IRoleRepository';
import { IPermissaoRepository } from '../../infrastructure/repository/IPermissaoRepository';

@Injectable()
export class AuthorizationService {
  constructor(
    @Inject(TYPES.IRoleRepository)
    private roleRepository: IRoleRepository,
    @Inject(TYPES.IPermissaoRepository)
    private permissaoRepository: IPermissaoRepository
  ) {}

  async verificarRole(nome: string): Promise<boolean> {
    const role = await this.roleRepository.findByNome(nome);
    return role !== null;
  }

  async verificarPermissao(nome: string): Promise<boolean> {
    const permissao = await this.permissaoRepository.findByNome(nome);
    return permissao !== null;
  }
}
```

### Uso em Controllers (Futuro)

import { Injectable, Inject } from '../core/di';
import { TYPES } from '../core/di/types';
import { IRoleRepository } from '../infrastructure/repository/IRoleRepository';
import { IPermissaoRepository } from '../infrastructure/repository/IPermissaoRepository';

@Injectable()

    @Inject(TYPES.IRoleRepository)

    const { nome } = req.params;
    const role = await this.roleRepository.findByNome(nome);

## Detalhes de Implementação

### Busca por Nome

Ambos os métodos `findByNome` utilizam `findOne` do BaseRepository:

```typescript
async findByNome(nome: string): Promise<Role | null> {
  return await this.findOne({ where: { nome } });
}
```

**Características**:
- Busca case-sensitive (diferencia maiúsculas de minúsculas)
- Retorna `null` se não encontrar
- Simples e eficiente

**Nota sobre Case-Sensitivity**:
- A busca é case-sensitive por padrão no Sequelize
- Se necessário buscar de forma case-insensitive, pode-se usar `Op.iLike` (PostgreSQL) ou `Op.like` com transformação

## Testes Unitários

### Estrutura de Testes

Os testes verificam:
1. **findByNome**: Retorna entidade quando encontrada
2. **findByNome com nome inexistente**: Retorna null
3. **Case-sensitivity**: Verifica que a busca diferencia maiúsculas de minúsculas
4. **Métodos herdados**: Verifica que métodos do BaseRepository estão disponíveis

### Exemplo de Teste

```typescript
describe('RoleRepository', () => {
  let repository: RoleRepository;
  let mockFindOne: jest.Mock;

  beforeEach(() => {
    repository = new RoleRepository();
    mockFindOne = jest.fn();
    (repository as any).findOne = mockFindOne;
  });

  it('deve retornar role quando encontrada', async () => {
    const mockRole = { id: 1, nome: 'ADMIN' } as Role;
    mockFindOne.mockResolvedValue(mockRole);

    const result = await repository.findByNome('ADMIN');

    expect(result).toBe(mockRole);
    expect(mockFindOne).toHaveBeenCalledWith({
      where: { nome: 'ADMIN' },
    });
  });
});
```

## Comparação: Antes vs Depois

### Antes (Acesso Direto ao Sequelize)

```typescript
// Controller
class RoleController {
  async getByNome(req: Request, res: Response) {
    const { nome } = req.params;
    
    // Acesso direto ao Sequelize
    const role = await Role.findOne({ where: { nome } });
    
    if (!role) {
      throw new NotFoundException('Role', nome);
    }
    
    return res.json(role);
  }
}
```

**Problemas**:
- ❌ Controller acoplado ao Sequelize
- ❌ Código duplicado em múltiplos lugares
- ❌ Difícil de testar

### Depois (Com Repository Pattern)

```typescript
// Controller
@Injectable()
class RoleController {
  constructor(
    @Inject(TYPES.IRoleRepository)
    private roleRepository: IRoleRepository
  ) {}

  async getByNome(req: Request, res: Response) {
    const { nome } = req.params;
    
    // Uso do repositório
    const role = await this.roleRepository.findByNome(nome);
    
    if (!role) {
      throw new NotFoundException('Role', nome);
    }
    
    return res.json(role);
  }
}
```

**Benefícios**:
- ✅ Controller desacoplado do Sequelize
- ✅ Código reutilizável
- ✅ Fácil de testar
