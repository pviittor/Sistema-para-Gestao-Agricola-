## Guias de Uso

### Guia 1: Uso Básico do UnitOfWork

#### Usando Manualmente

```typescript
import { IUnitOfWork } from '../../../core/unitofwork/IUnitOfWork';
import { TYPES } from '../../../core/di/types';
import { Inject, Injectable } from '../../../core/di';

@Injectable()
export class UsuarioApplicationService {
  constructor(
    @Inject(TYPES.IUsuarioRepository)
    private repository: IUsuarioRepository,
    @Inject(TYPES.IUnitOfWork)
    private unitOfWork: IUnitOfWork
  ) {}

  async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
    return await this.unitOfWork.execute(async (transaction) => {
      const entity = await this.mapper.toEntity(dto);
      const created = await this.repository.create(entity as any, { transaction });
      return this.mapper.toDto(created);
    });
  }
}
```

#### Usando @Transactional Decorator

```typescript
import { Transactional } from '../../../core/unitofwork/Transactional';
import { Inject, Injectable } from '../../../core/di';

@Injectable()
export class UsuarioApplicationService {
  constructor(
    @Inject(TYPES.IUsuarioRepository)
    private repository: IUsuarioRepository
  ) {}

  @Transactional()
  async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
    const entity = await this.mapper.toEntity(dto);
    const created = await this.repository.create(entity as any);
    return this.mapper.toDto(created);
  }
}
```

**Recomendação**: Use `@Transactional` sempre que possível, pois é mais simples e declarativo.

### Guia 2: Quando Usar @Transactional

#### ✅ Use @Transactional quando:

1. **Método modifica dados**:
   ```typescript
   @Transactional()
   async create(dto: CreateDto): Promise<ResponseDto> {
     // ...
   }
   ```

2. **Método executa múltiplas operações**:
   ```typescript
   @Transactional()
   async create(dto: CreateDto): Promise<ResponseDto> {
     const usuario = await this.usuarioRepository.create(dto);
     const role = await this.roleRepository.create({ nome: 'USER' });
     await this.usuarioRoleRepository.create({ usuarioId: usuario.id, roleId: role.id });
     return usuario;
   }
   ```

3. **Método tem validações que devem ser revertidas**:
   ```typescript
   @Transactional()
   async create(dto: CreateDto): Promise<ResponseDto> {
     const existing = await this.repository.findByEmail(dto.email);
     if (existing) {
       throw new BusinessException('Email já está em uso');
     }
     return await this.repository.create(dto);
   }
   ```

#### ❌ Não use @Transactional quando:

1. **Método apenas lê dados**:
   ```typescript
   // ❌ Incorreto
   @Transactional()
   async getById(id: number): Promise<ResponseDto | null> {
     return await this.repository.findById(id);
   }

   // ✅ Correto
   async getById(id: number): Promise<ResponseDto | null> {
     return await this.repository.findById(id);
   }
   ```

2. **Método não acessa banco de dados**:
   ```typescript
   // ❌ Incorreto
   @Transactional()
   async validateData(data: any): Promise<boolean> {
     return data !== null && data !== undefined;
   }
   ```

### Guia 3: Padrões de Uso

#### Padrão 1: Criação com Validações

```typescript
@Transactional()
async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
  // Validação 1 (dentro de transação)
  const existingByEmail = await this.repository.findByEmail(dto.email);
  if (existingByEmail) {
    throw new BusinessException('Email já está em uso');
  }

  // Validação 2 (dentro de transação)
  const existingByUsername = await this.repository.findByUsername(dto.username);
  if (existingByUsername) {
    throw new BusinessException('Username já está em uso');
  }

  // Criação (dentro de transação)
  const entity = await this.mapper.toEntity(dto);
  const created = await this.repository.create(entity as any);
  return this.mapper.toDto(created);
}
```

**Benefício**: Se qualquer validação ou criação falhar, nada é commitado.

#### Padrão 2: Atualização com Validações Condicionais

```typescript
@Transactional()
async update(id: number, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
  // Verificação (dentro de transação)
  const existing = await this.repository.findById(id);
  if (!existing) {
    throw new NotFoundException('Usuário', id);
  }

  // Validação condicional (dentro de transação)
  if (dto.email && dto.email !== existing.email) {
    const emailExists = await this.repository.findByEmail(dto.email);
    if (emailExists) {
      throw new BusinessException('Email já está em uso');
    }
  }

  // Atualização (dentro de transação)
  const entity = await this.mapper.toEntity(dto);
  const updated = await this.repository.update(id, entity as any);
  return this.mapper.toDto(updated);
}
```

**Benefício**: Validações e atualização são atômicas.

#### Padrão 3: Deleção com Verificações

```typescript
@Transactional()
async delete(id: number): Promise<boolean> {
```

## Exemplos Avançados

### Exemplo 1: Operação Complexa com Múltiplas Entidades

```typescript
@Transactional()
async criarUsuarioCompleto(dto: CreateUsuarioCompletoDto): Promise<UsuarioResponseDto> {
  // 1. Criar usuário (dentro de transação)
  const usuario = await this.usuarioRepository.create({
    nome: dto.nome,
    email: dto.email,
    username: dto.username,
    senha: dto.senha,
  });

  // 2. Criar roles padrão (dentro de transação)
  const role = await this.roleRepository.create({ nome: 'USER' });

  // 3. Associar role ao usuário (dentro de transação)
  await this.usuarioRoleRepository.create({
    usuarioId: usuario.id,
    roleId: role.id,
  });

  // 4. Criar local padrão (dentro de transação)
  const local = await this.localRepository.create({
    desc_simples: 'Local Padrão',
    desc_completa: 'Local padrão do usuário',
    usuarioId: usuario.id,
  });

  // Se qualquer operação falhar, todas são revertidas
  return this.mapper.toDto(usuario);
}
```

**Benefício**: Todas as operações são atômicas. Se qualquer uma falhar, todas são revertidas.

### Exemplo 2: Atualização com Validações Complexas

```typescript
@Transactional()
async atualizarEventoComValidacoes(id: number, dto: UpdateEventoDto): Promise<EventoResponseDto> {
  // 1. Verificar existência (dentro de transação)
  const existing = await this.repository.findById(id);
  if (!existing) {
    throw new NotFoundException('Evento', id);
  }

  // 2. Validação de data (dentro de transação)
  if (dto.data) {
    const dataEvento = new Date(dto.data);
    const hoje = new Date();
    hoje.setHours(0, 0, 0, 0);
    
    if (dataEvento < hoje) {
      throw new BusinessException('Não é possível atualizar evento com data no passado');
    }
  }

  // 3. Validação de horários (dentro de transação)
  if (dto.horario_inicio && dto.horario_fim) {
    const horarioInicio = dto.horario_inicio.split(':').map(Number);
    const horarioFim = dto.horario_fim.split(':').map(Number);
    const inicioMinutos = horarioInicio[0] * 60 + horarioInicio[1];
    const fimMinutos = horarioFim[0] * 60 + horarioFim[1];
    
    if (fimMinutos <= inicioMinutos) {
      throw new BusinessException('Horário de fim deve ser posterior ao horário de início');
    }
  }

  // 4. Validação de local (dentro de transação)
  if (dto.localId) {
    const local = await this.localRepository.findById(dto.localId);
    if (!local) {
      throw new NotFoundException('Local', dto.localId);
    }
  }

  // 5. Atualização (dentro de transação)
  const entity = await this.mapper.toEntity(dto);
  const updated = await this.repository.update(id, entity as any);
  return this.mapper.toDto(updated);
}
```

**Benefício**: Todas as validações e a atualização são atômicas.

## Boas Práticas

### 1. Sempre Aplicar em Métodos que Modificam Dados

```typescript
// ✅ Correto
@Transactional()
async create(dto: CreateDto): Promise<ResponseDto> {
  // ...
}

@Transactional()
async update(id: number, dto: UpdateDto): Promise<ResponseDto> {
  // ...
}

@Transactional()
async delete(id: number): Promise<boolean> {
  // ...
}
```

### 2. Não Aplicar em Métodos de Leitura

```typescript
// ✅ Correto - sem @Transactional
async getById(id: number): Promise<ResponseDto | null> {
  const entity = await this.repository.findById(id);
  return entity ? this.mapper.toDto(entity) : null;
}

async list(page: number = 1, limit: number = 10): Promise<PaginatedResult<ResponseDto>> {
  const result = await this.repository.findAllPaginated(page, limit);
  return {
    ...result,
    data: result.data.map(entity => this.mapper.toDto(entity)),
  };
}
```

### 3. Manter Validações Dentro da Transação

```typescript
// ✅ Correto - validações dentro da transação
@Transactional()
async create(dto: CreateDto): Promise<ResponseDto> {
  const existing = await this.repository.findByEmail(dto.email);
  if (existing) {
    throw new BusinessException('Email já está em uso');
  }
  return await this.repository.create(dto);
}

// ❌ Incorreto - validação fora da transação
async create(dto: CreateDto): Promise<ResponseDto> {
  const existing = await this.repository.findByEmail(dto.email);
  if (existing) {
    throw new BusinessException('Email já está em uso');
  }
  // Se criação falhar aqui, validação já foi feita mas não será revertida
  return await this.repository.create(dto);
}
```

### 4. Usar Exceções para Rollback

```typescript
// ✅ Correto - exceção causa rollback automático
@Transactional()
async create(dto: CreateDto): Promise<ResponseDto> {
  if (dto.valor < 0) {
    throw new BusinessException('Valor não pode ser negativo');
  }
  // Se exceção for lançada, rollback automático
  return await this.repository.create(dto);
}

// ❌ Incorreto - capturar exceção silenciosamente
@Transactional()
async create(dto: CreateDto): Promise<ResponseDto> {
  try {
    return await this.repository.create(dto);
  } catch (error) {
    // Erro capturado, mas transação já foi commitada
    console.error(error);
    return null;
  }
}
```

### 5. Evitar Operações Desnecessárias Dentro da Transação

```typescript
// ✅ Correto - apenas operações necessárias
@Transactional()
async create(dto: CreateDto): Promise<ResponseDto> {
  // Validação necessária
  const existing = await this.repository.findByEmail(dto.email);
  if (existing) {
    throw new BusinessException('Email já está em uso');
  }
  
  // Criação
  return await this.repository.create(dto);
}

// ❌ Incorreto - operações desnecessárias
@Transactional()
async create(dto: CreateDto): Promise<ResponseDto> {
  // Operação desnecessária dentro da transação
  const allUsers = await this.repository.findAll(); // Não precisa estar na transação
  
  const existing = await this.repository.findByEmail(dto.email);
  if (existing) {
    throw new BusinessException('Email já está em uso');
  }
  
  return await this.repository.create(dto);
}
```

## Troubleshooting

### Problema 1: Transação não está funcionando

**Sintomas**:
- Dados não são commitados
- Rollback não acontece em erros

**Soluções**:
1. Verifique se o decorator `@Transactional()` está aplicado corretamente
2. Verifique se o método é assíncrono (`async`)
3. Verifique se o `UnitOfWorkService` está registrado no DI container
4. Verifique se não há erros de compilação TypeScript

**Exemplo de verificação**:
```typescript
// Verificar se está registrado
import { container } from '../../../core/di/container';
import { TYPES } from '../../../core/di/types';
import { IUnitOfWork } from '../../../core/unitofwork/IUnitOfWork';

const unitOfWork = container.resolve<IUnitOfWork>(TYPES.IUnitOfWork);
console.log('UnitOfWork resolvido:', unitOfWork !== undefined);
```

### Problema 2: Rollback não está acontecendo

**Sintomas**:
- Erros ocorrem mas dados são commitados
- Transação não é revertida

**Soluções**:
1. Certifique-se de que as exceções estão sendo lançadas (não capturadas silenciosamente)
2. Certifique-se de que o erro está sendo propagado (não está sendo capturado e ignorado)
3. Verifique se está usando exceções customizadas que herdam de `BaseException`

**Exemplo correto**:
```typescript
@Transactional()
async create(dto: CreateDto): Promise<ResponseDto> {
  if (dto.valor < 0) {
    // ✅ Exceção lançada causa rollback automático
    throw new BusinessException('Valor não pode ser negativo');
  }
  return await this.repository.create(dto);
}
```

**Exemplo incorreto**:
```typescript
@Transactional()
async create(dto: CreateDto): Promise<ResponseDto> {
  try {
    if (dto.valor < 0) {
      // ❌ Erro capturado, transação não é revertida
      console.error('Valor inválido');
      return null;
    }
    return await this.repository.create(dto);
  } catch (error) {
    // ❌ Erro capturado, transação não é revertida
    console.error(error);
    return null;
  }
}
```

### Problema 3: Transação muito lenta

**Sintomas**:
- Operações demoram muito para completar
- Timeout de transação

**Soluções**:
1. Verifique se há operações desnecessárias dentro da transação
2. Considere mover validações simples para fora da transação
3. Use índices adequados no banco de dados
4. Considere dividir operações complexas em múltiplas transações menores

**Exemplo de otimização**:
```typescript
// ❌ Lento - muitas operações na transação
@Transactional()
async create(dto: CreateDto): Promise<ResponseDto> {
  const allUsers = await this.repository.findAll(); // Desnecessário
  const allRoles = await this.roleRepository.findAll(); // Desnecessário
  const existing = await this.repository.findByEmail(dto.email);
  if (existing) {
    throw new BusinessException('Email já está em uso');
  }
  return await this.repository.create(dto);
}

// ✅ Rápido - apenas operações necessárias
@Transactional()
async create(dto: CreateDto): Promise<ResponseDto> {
  const existing = await this.repository.findByEmail(dto.email);
  if (existing) {
    throw new BusinessException('Email já está em uso');
  }
  return await this.repository.create(dto);
}
```

### Problema 4: Erro "Too many keys specified"

**Sintomas**:
- Erro ao sincronizar banco de dados
- Erro ao criar constraints UNIQUE

**Soluções**:
1. Remova `unique: true` de modelos Sequelize
2. Use validação de unicidade apenas no nível da aplicação (DTO e Application Service)
3. Se necessário, crie índices manualmente via migrations

**Exemplo**:
```typescript
// ❌ Pode causar erro se tabela tiver muitas chaves
username: {
  type: DataTypes.STRING,
  allowNull: false,
  unique: true, // Pode causar erro
}

// ✅ Correto - validação no nível da aplicação
username: {
  type: DataTypes.STRING,
  allowNull: false,
  // unique: true removido - validação feita no DTO e Application Service
}
```
