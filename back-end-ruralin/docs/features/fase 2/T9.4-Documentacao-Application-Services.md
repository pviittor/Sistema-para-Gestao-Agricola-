## Visão Geral

### O que são Application Services?

Application Services são componentes que contêm a **lógica de negócio** da aplicação, separando controllers (camada HTTP) da lógica de aplicação. Eles seguem os princípios de **Clean Architecture** e **Domain-Driven Design (DDD)**.

### Responsabilidades

Application Services são responsáveis por:

- ✅ **Validações de negócio**: Verificar regras de negócio antes de operações
- ✅ **Orquestração**: Coordenar múltiplos repositórios ou serviços
- ✅ **Transformações**: Converter entre DTOs e entidades do domínio
- ✅ **Aplicação de políticas**: Aplicar regras e políticas de negócio
- ✅ **Transações**: Gerenciar transações complexas (futuro: Unit of Work)

### O que NÃO são Application Services?

Application Services **NÃO** são responsáveis por:

- ❌ **Acesso a dados**: Deve usar repositórios
- ❌ **Lógica HTTP**: Deve estar nos controllers
- ❌ **Validação de entrada**: Deve estar nos DTOs (class-validator)
- ❌ **Lógica de apresentação**: Deve estar nos DTOs de resposta

## Conceitos Fundamentais

### Arquitetura em Camadas

```
┌─────────────────────────────────────┐
│      Controllers (HTTP Layer)       │  ← Recebe requisições HTTP
└──────────────┬──────────────────────┘
               │ Usa
               ▼
┌─────────────────────────────────────┐
│   Application Services (Business)   │  ← Lógica de negócio
└──────────────┬──────────────────────┘
               │ Usa
               ▼
┌─────────────────────────────────────┐
│      Repositories (Data Access)     │  ← Acesso a dados
└──────────────┬──────────────────────┘
               │ Usa
               ▼
┌─────────────────────────────────────┐
│         Models (Domain)              │  ← Entidades do domínio
└─────────────────────────────────────┘
```

### Fluxo de Dados

```
1. Controller recebe Request HTTP
   ↓
2. Controller extrai DTO do body
   ↓
3. Controller chama Application Service
   ↓
4. Application Service valida regras de negócio
   ↓
5. Application Service converte DTO → Entidade (via Mapper)
   ↓
6. Application Service chama Repository
   ↓
7. Repository acessa banco de dados
   ↓
8. Repository retorna Entidade
   ↓
9. Application Service converte Entidade → DTO (via Mapper)
   ↓
10. Application Service retorna DTO
   ↓
11. Controller retorna Response HTTP
```

### Nomenclatura

**Interface**:
- Padrão: `I[Entity]ApplicationService`
- Exemplos: `IUsuarioApplicationService`, `IEventoApplicationService`

**Classe**:
- Padrão: `[Entity]ApplicationService`
- Exemplos: `UsuarioApplicationService`, `EventoApplicationService`

- Padrão: `[Entity]ApplicationService.ts`
- Exemplos: `UsuarioApplicationService.ts`, `EventoApplicationService.ts`

### Interface Base: `IApplicationService`

Todos os Application Services devem implementar esta interface:

```typescript
export interface IApplicationService<TDto, TCreateDto, TUpdateDto> {
  create(dto: TCreateDto): Promise<TDto>;
  update(id: number | string, dto: TUpdateDto): Promise<TDto>;
  delete(id: number | string): Promise<boolean>;
  getById(id: number | string): Promise<TDto | null>;
  list(page?: number, limit?: number): Promise<PaginatedResult<TDto>>;
}
```

### Métodos Padrão

#### 1. `create(dto: TCreateDto): Promise<TDto>`

Cria uma nova entidade.

**Responsabilidades**:
- Validar regras de negócio
- Converter DTO para entidade
- Criar via repositório
- Converter entidade para DTO
- Retornar DTO

**Exemplo**:
```typescript
async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
  // Validação de negócio
  const existing = await this.repository.findByEmail(dto.email);
  if (existing) {
    throw new BusinessException('Email já está em uso');
  }

  // Converter DTO → Entidade
  const entity = await this.mapper.toEntity(dto);

  // Criar via repositório
  const created = await this.repository.create(entity as any);

  // Retornar como DTO
  return this.mapper.toDto(created);
}
```

#### 2. `update(id: number | string, dto: TUpdateDto): Promise<TDto>`

Atualiza uma entidade existente.

**Responsabilidades**:
- Verificar se entidade existe
- Validar regras de negócio
- Converter DTO para entidade
- Atualizar via repositório
- Converter entidade para DTO
- Retornar DTO

**Exemplo**:
```typescript
async update(id: number | string, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
  // Verificar existência
  const existing = await this.repository.findById(id);
  if (!existing) {
    throw new NotFoundException('Usuário', id);
  }

  // Validação de negócio
  if (dto.email && dto.email !== existing.email) {
    const emailExists = await this.repository.findByEmail(dto.email);
    if (emailExists) {
      throw new BusinessException('Email já está em uso');
    }
  }

  // Converter DTO → Entidade
  const entity = await this.mapper.toEntity(dto);

  // Atualizar via repositório
  const updated = await this.repository.update(id, entity as any);

  // Retornar como DTO
  return this.mapper.toDto(updated);
}
```

#### 3. `delete(id: number | string): Promise<boolean>`

Remove uma entidade.

**Responsabilidades**:
- Verificar se entidade existe
- Validar dependências (se necessário)
- Remover via repositório
- Retornar `true` se removido, `false` caso contrário

**Exemplo**:
```typescript
async delete(id: number | string): Promise<boolean> {
  // Verificar existência
  const existing = await this.repository.findById(id);
  if (!existing) {
    return false;
  }

  // Validação de dependências (exemplo)
  // if (await this.hasRelatedData(id)) {
  //   throw new BusinessException('Não é possível remover usuário com dados relacionados');
  // }

  // Remover via repositório
  return await this.repository.delete(id);
}
```

#### 4. `getById(id: number | string): Promise<TDto | null>`

Busca uma entidade por ID.

**Responsabilidades**:
- Buscar via repositório
- Converter entidade para DTO
- Retornar DTO ou `null`

**Exemplo**:
```typescript
async getById(id: number | string): Promise<UsuarioResponseDto | null> {
  const entity = await this.repository.findById(id);
  return entity ? this.mapper.toDto(entity) : null;
}
```

#### 5. `list(page?: number, limit?: number): Promise<PaginatedResult<TDto>>`

Lista entidades com paginação.

**Responsabilidades**:
- Buscar via repositório com paginação
- Converter todas as entidades para DTOs
- Retornar resultado paginado

**Exemplo**:
```typescript
async list(page: number = 1, limit: number = 10): Promise<PaginatedResult<UsuarioResponseDto>> {
  const result = await this.repository.findAllPaginated(page, limit);
  return {
    ...result,
    data: result.data.map(entity => this.mapper.toDto(entity)),
  };
}
```

Application Services podem adicionar métodos específicos da entidade:

## Exemplos de Uso

### Exemplo 1: Uso em Controller

```typescript
import { Injectable, Inject } from '../core/di';
import { TYPES } from '../core/di/types';
import { IUsuarioApplicationService } from '../application/services/usuario/IUsuarioApplicationService';
import { CreateUsuarioDto } from '../application/dto/usuario/CreateUsuarioDto';

@Injectable()
export class UsuarioController {
  constructor(
    @Inject(TYPES.IUsuarioApplicationService)
    private usuarioService: IUsuarioApplicationService
  ) {}

  async create(req: Request, res: Response) {
    // req.body já está validado e tipado como CreateUsuarioDto
    const dto = req.body as CreateUsuarioDto;
    
    // Chamar Application Service
    const usuario = await this.usuarioService.create(dto);
    
    // Retornar resposta HTTP
    return res.status(201).json(usuario);
  }

  async show(req: Request, res: Response) {
    const { id } = req.params;
    
    const usuario = await this.usuarioService.getById(id);
    
    if (!usuario) {
      throw new NotFoundException('Usuário', id);
    }

    return res.json(usuario);
  }
}
```

## Boas Práticas

### 1. Sempre Retornar DTOs

**✅ Correto**:
```typescript
async getById(id: number): Promise<UsuarioResponseDto | null> {
  const entity = await this.repository.findById(id);
  return entity ? this.mapper.toDto(entity) : null;
}
```

**❌ Incorreto**:
```typescript
async getById(id: number): Promise<Usuario | null> {
  return await this.repository.findById(id); // Retorna entidade diretamente

```

## Guia de Criação

### Passo 1: Criar Interface

Criar arquivo `I[Entity]ApplicationService.ts`:

```typescript
import { IApplicationService } from '../IApplicationService';
import { CreateEntityDto } from '../../dto/entity/CreateEntityDto';
import { UpdateEntityDto } from '../../dto/entity/UpdateEntityDto';
import { EntityResponseDto } from '../../dto/entity/EntityResponseDto';

export interface IEntityApplicationService 
  extends IApplicationService<EntityResponseDto, CreateEntityDto, UpdateEntityDto> {
  // Métodos customizados (opcional)
  findByCustomField(field: string): Promise<EntityResponseDto | null>;
}
```

### Passo 2: Criar Implementação

Criar arquivo `[Entity]ApplicationService.ts`:

```typescript
import { Injectable, Inject } from '../../../core/di';
import { TYPES } from '../../../core/di/types';
import { IEntityApplicationService } from './IEntityApplicationService';
import { IEntityRepository } from '../../../infrastructure/repository/IEntityRepository';
import { EntityMapper } from '../../mappers/EntityMapper';
import { CreateEntityDto } from '../../dto/entity/CreateEntityDto';
import { UpdateEntityDto } from '../../dto/entity/UpdateEntityDto';
import { EntityResponseDto } from '../../dto/entity/EntityResponseDto';
import { NotFoundException, BusinessException } from '../../../core/exceptions';

@Injectable()
export class EntityApplicationService implements IEntityApplicationService {
  private mapper: EntityMapper;

  constructor(
    @Inject(TYPES.IEntityRepository)
    private repository: IEntityRepository
  ) {
    this.mapper = new EntityMapper();
  }

  async create(dto: CreateEntityDto): Promise<EntityResponseDto> {
    // Validações de negócio
    // ...

    // Converter DTO → Entidade
    const entity = await this.mapper.toEntity(dto);

    // Criar via repositório
    const created = await this.repository.create(entity as any);

    // Retornar como DTO
    return this.mapper.toDto(created);
  }

  async update(id: number | string, dto: UpdateEntityDto): Promise<EntityResponseDto> {
    // Verificar existência
    const existing = await this.repository.findById(id);
    if (!existing) {
      throw new NotFoundException('Entity', id);
    }

    // Validações de negócio
    // ...

    // Converter DTO → Entidade
    const entity = await this.mapper.toEntity(dto);

    // Atualizar via repositório
    const updated = await this.repository.update(id, entity as any);

    // Retornar como DTO
    return this.mapper.toDto(updated);
  }

  async delete(id: number | string): Promise<boolean> {
    const existing = await this.repository.findById(id);
    if (!existing) {
      return false;
    }

    return await this.repository.delete(id);
  }

  async getById(id: number | string): Promise<EntityResponseDto | null> {
    const entity = await this.repository.findById(id);
    return entity ? this.mapper.toDto(entity) : null;
  }

  async list(page: number = 1, limit: number = 10): Promise<PaginatedResult<EntityResponseDto>> {
    const result = await this.repository.findAllPaginated(page, limit);
    return {
      ...result,
      data: result.data.map(entity => this.mapper.toDto(entity)),
    };
  }

  // Métodos customizados
  async findByCustomField(field: string): Promise<EntityResponseDto | null> {
    const entity = await this.repository.findByCustomField(field);
    return entity ? this.mapper.toDto(entity) : null;
  }
}
```

## Troubleshooting

### Problema: Service não está sendo injetado

**Sintoma**: Erro "Cannot resolve dependency" ou service é `undefined`

**Solução**:
1. Verificar se service está registrado em `registerServices.ts`
2. Verificar se token está definido em `types.ts`
3. Verificar se `initializeContainer()` foi chamado em `server.ts`

### Problema: Mapper não está funcionando

**Sintoma**: Erro ao converter DTO para entidade ou vice-versa

**Solução**:
1. Verificar se mapper está sendo instanciado corretamente
2. Verificar se métodos `toEntity` e `toDto` estão implementados
3. Verificar se tipos estão corretos

### Problema: Validações de negócio não estão funcionando

**Sintoma**: Regras de negócio não são aplicadas

**Solução**:
1. Verificar se validações estão no service (não apenas no DTO)
2. Verificar se exceções estão sendo lançadas corretamente
3. Verificar se ErrorHandler está capturando exceções

### Problema: Repository não está sendo injetado

**Sintoma**: Erro ao acessar repository

**Solução**:
1. Verificar se repository está registrado em `registerRepositories.ts`
2. Verificar se token está correto em `@Inject()`
3. Verificar se interface do repository está correta
