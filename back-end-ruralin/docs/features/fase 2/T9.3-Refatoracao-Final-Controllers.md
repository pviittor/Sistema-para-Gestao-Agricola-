## Decisões de Implementação

### Abordagem Escolhida

**Controllers de Relacionamentos**:
- Não criamos Application Services para controllers de relacionamentos (RoleHasPermissao, UsuarioHasRole, UsuarioHasSubUsuario)
- Motivo: São operações simples de relacionamento many-to-many, sem lógica de negócio complexa
- Solução: Refatorados para usar DI, exceções padronizadas e seguir o mesmo padrão estrutural

**Padrão de DI**:
- Todos os controllers agora usam `@Injectable()` decorator
- Controllers principais registrados com tokens de interface
- Controllers de relacionamentos registrados diretamente (sem interfaces específicas)

**Tratamento de Exceções**:
- Removidos try-catch manuais
- Uso de exceções customizadas (`NotFoundException`)
- ErrorHandler middleware captura todas as exceções

**Rotas**:
- Atualizadas para usar resolução lazy via DI container
- Padrão consistente em todas as rotas

## Controllers Refatorados

### 1. RoleHasPermissaoController

**Antes**:
```typescript
class RoleHasPermissaoController {
  async index(req: Request, res: Response) {
    try {
      const roleHasPermissoes = await RoleHasPermissao.findAll();
      return res.json(roleHasPermissoes);
    } catch (error) {
      return res.status(500).json({ error: 'Erro ao buscar permissões de roles' });
    }
  }
  // ...
}
export default new RoleHasPermissaoController();
```

**Depois**:
```typescript
@Injectable()
export class RoleHasPermissaoController {
  async index(req: Request, res: Response) {
    const roleHasPermissoes = await RoleHasPermissao.findAll();
    return res.json(roleHasPermissoes);
  }

  async create(req: Request, res: Response) {
    const { roleId, permissaoId } = req.body;
    
    if (!roleId || !permissaoId) {
      throw new NotFoundException('Role ou Permissão');
    }

    const roleHasPermissao = await RoleHasPermissao.create({ roleId, permissaoId });
    return res.status(201).json(roleHasPermissao);
  }

  async delete(req: Request, res: Response) {
    const { roleId, permissaoId } = req.params;
    
    const roleHasPermissao = await RoleHasPermissao.findOne({
      where: { roleId, permissaoId }
    });

    if (!roleHasPermissao) {
      throw new NotFoundException('Associação Role-Permissão', `${roleId}-${permissaoId}`);
    }

    await roleHasPermissao.destroy();
    return res.status(204).send();
  }
}

export default RoleHasPermissaoController;
```

**Mudanças**:
- ✅ Adicionado `@Injectable()` decorator
- ✅ Removidos try-catch manuais
- ✅ Uso de `NotFoundException` para erros
- ✅ Validação de parâmetros obrigatórios
- ✅ Exportação da classe (não instância)

## Atualização de Rotas

### Padrão Anterior

```typescript
import RoleHasPermissaoController from '../controllers/RoleHasPermissaoController';

router.get('/', RoleHasPermissaoController.index);
```

**Problemas**:
- ❌ Importação direta de instância
- ❌ Não usa DI container
- ❌ Inconsistente com outros controllers

### Padrão Atualizado

```typescript
import { container } from '../core/di/container';
import RoleHasPermissaoController from '../controllers/RoleHasPermissaoController';

const getController = () => container.resolve(RoleHasPermissaoController);

router.get('/', (req, res) => getController().index(req, res));
```

**Benefícios**:
- ✅ Resolução via DI container
- ✅ Lazy resolution (resolve apenas quando necessário)
- ✅ Consistente com outros controllers
- ✅ Facilita testes e mocks

2. **`src/routes/usuarioHasRole.routes.ts`**

### 2. Tratamento de Exceções

- ErrorHandler middleware captura todas as exceções
- Respostas padronizadas

**Exemplo**:
```typescript
// Antes
try {
  const item = await Model.findOne({ where: { id } });
  if (!item) {
    return res.status(404).json({ error: 'Item não encontrado' });
  }
} catch (error) {
  return res.status(500).json({ error: 'Erro ao buscar item' });
}

// Depois
const item = await Model.findOne({ where: { id } });
if (!item) {
  throw new NotFoundException('Item', id);
}
```
