## Decisões de Implementação

### Abordagem Escolhida

**Application Service Pattern**:
- Separa controllers (HTTP) da lógica de negócio
- Centraliza regras de negócio em um único lugar
- Facilita testes e manutenção
- Reutilizável em diferentes contextos

**Integração com Dependências**:
- Usa `ILembreteRepository` para acesso a dados
- Usa `LembreteMapper` para conversão DTO-Entidade
- Injeta dependências via DI container

**Tratamento de Relacionamentos**:
- `LembreteDataHora` é tratado separadamente no controller
- Service foca apenas na entidade `Lembrete`
- Relacionamentos são enriquecidos no controller quando necessário

## Métodos Implementados

### `create(dto: CreateLembreteDto): Promise<LembreteResponseDto>`

Cria um novo lembrete.

**Implementação**:
```typescript
async create(dto: CreateLembreteDto): Promise<LembreteResponseDto> {
  // Converter DTO para entidade (sem lembrete_data_hora)
  const entity = await this.mapper.toEntity(dto);

  // Criar via repositório
  const created = await this.repository.create(entity as any);

  // Retornar como DTO
  return this.mapper.toDto(created);
}
```

**NOTA**: `LembreteDataHora` não é criado aqui, será tratado no controller.

**Exemplo de Uso**:
```typescript
const service = container.resolve<ILembreteApplicationService>(TYPES.ILembreteApplicationService);

const lembrete = await service.create({
  desc_simples: 'Reunião importante',
  desc_completa: 'Reunião com a equipe para discutir o planejamento',
});
```

### `update(id: number | string, dto: UpdateLembreteDto): Promise<LembreteResponseDto>`

Atualiza um lembrete existente.

**Implementação**:
```typescript
async update(id: number | string, dto: UpdateLembreteDto): Promise<LembreteResponseDto> {
  // Verificar se lembrete existe
  const existing = await this.repository.findById(id);
  if (!existing) {
    throw new NotFoundException('Lembrete', id);
  }

  // Converter DTO para entidade (sem lembrete_data_hora)
  const entity = await this.mapper.toEntity(dto);

  // Atualizar via repositório
  const updated = await this.repository.update(id, entity as any);

  // Retornar como DTO
  return this.mapper.toDto(updated);
}
```

**NOTA**: `LembreteDataHora` não é atualizado aqui, será tratado no controller.

**Exemplo de Uso**:
```typescript
const lembrete = await service.update(1, {
  desc_simples: 'Reunião Atualizada',
});
```

## Tratamento de Relacionamentos

### LembreteDataHora

O relacionamento `LembreteDataHora` é tratado separadamente no controller, não no Application Service. Isso porque:

1. **Complexidade**: Requer lógica específica de criação/atualização
2. **Separação de Responsabilidades**: Service foca na entidade principal
3. **Flexibilidade**: Controller pode enriquecer DTOs com relacionamentos quando necessário

**No Controller**:
```typescript
async create(req: Request, res: Response) {
  const dto = req.body as CreateLembreteDto;
  
  // Criar lembrete via service
  const lembrete = await this.lembreteService.create(dto);
  
  // Criar LembreteDataHora separadamente
  if (dto.lembrete_data_hora && Array.isArray(dto.lembrete_data_hora)) {
    await Promise.all(dto.lembrete_data_hora.map(item => 
      LembreteDataHora.create({
        lembreteId: lembrete.id,
        ...item,
      })
    ));
  }
  
  return res.status(201).json(lembrete);
}
```

**Futura Melhoria**:
Esta lógica pode ser movida para o Application Service em uma futura refatoração, criando métodos específicos como `createWithDataHora`.

## Comparação: Antes vs Depois

### Antes (Lógica no Controller)

```typescript
@Injectable()
export class LembreteController {
  async create(req: Request, res: Response) {
    // Lógica de negócio no controller ❌
    const lembrete = await Lembrete.create(req.body);
    return res.status(201).json(lembrete);
  }
}
```

**Problemas**:
- ❌ Lógica de negócio misturada com HTTP
- ❌ Difícil reutilizar em outros contextos
- ❌ Difícil testar isoladamente

### Depois (Com Application Service)

```typescript
@Injectable()
export class LembreteController {
  constructor(
    @Inject(TYPES.ILembreteApplicationService)
    private service: ILembreteApplicationService
  ) {}

  async create(req: Request, res: Response) {
    // Controller apenas orquestra HTTP ✅
    const dto = req.body as CreateLembreteDto;
    const lembrete = await this.service.create(dto);
    return res.status(201).json(lembrete);
  }
}
```

**Benefícios**:
- ✅ Controller focado em HTTP
- ✅ Lógica de negócio no service
- ✅ Fácil reutilizar service
- ✅ Fácil testar isoladamente
