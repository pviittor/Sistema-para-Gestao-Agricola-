## Decisões de Implementação

### Abordagem Escolhida

**Interface Genérica**:
- `IApplicationService<TDto, TCreateDto, TUpdateDto>` define contrato padrão
- Métodos CRUD padronizados: `create`, `update`, `delete`, `getById`, `list`
- Suporte a paginação via `PaginatedResult<TDto>`

**Classe Base Opcional**:
- `BaseApplicationService` fornece implementação base
- Métodos abstratos `toDto` e `toEntity` para mapeamento
- Services podem estender a classe base ou implementar a interface diretamente

**Padrões Definidos**:
- Nomenclatura: `[Entity]ApplicationService`
- Retorno sempre em DTOs, nunca entidades
- Integração com repositórios via DI
- Lógica de negócio centralizada

## Padrões e Convenções

### Nomenclatura

**Interface**:
- Padrão: `I[Entity]ApplicationService`
- Exemplo: `IUsuarioApplicationService`

**Classe**:
- Padrão: `[Entity]ApplicationService`
- Exemplo: `UsuarioApplicationService`

**Arquivo**:
- Padrão: `[Entity]ApplicationService.ts`
- Exemplo: `UsuarioApplicationService.ts`

### Métodos Padrão

Todos os Application Services devem implementar:

1. **`create(dto: TCreateDto): Promise<TDto>`**
   - Cria nova entidade
   - Valida e aplica regras de negócio
   - Retorna DTO

2. **`update(id: number | string, dto: TUpdateDto): Promise<TDto>`**
   - Atualiza entidade existente
   - Valida e aplica regras de negócio
   - Retorna DTO atualizado

3. **`delete(id: number | string): Promise<boolean>`**
   - Remove entidade
   - Aplica validações de dependências
   - Retorna `true`/`false`

4. **`getById(id: number | string): Promise<TDto | null>`**
   - Busca por ID
   - Retorna DTO ou `null`

5. **`list(page?: number, limit?: number): Promise<PaginatedResult<TDto>>`**
   - Lista com paginação
   - Retorna resultado paginado

### Retorno de DTOs

**Regra Fundamental**: Application Services **sempre retornam DTOs**, nunca entidades do domínio.

**✅ Correto**:
```typescript
async getById(id: number): Promise<UsuarioResponseDto | null> {
  const usuario = await this.repository.findById(id);
  return usuario ? this.toDto(usuario) : null;
}
```

**❌ Incorreto**:
```typescript
async getById(id: number): Promise<Usuario | null> {
  return await this.repository.findById(id); // Retorna entidade
}
```

### Mapeamento DTO ↔ Entidade

Application Services devem implementar métodos de mapeamento:

- **`toDto(entity: TEntity): TDto`** - Converte entidade para DTO
- **`toEntity(dto: TCreateDto | TUpdateDto): Partial<TEntity>`** - Converte DTO para entidade

**Exemplo**:
```typescript
protected toDto(entity: Usuario): UsuarioResponseDto {
  return {
    id: entity.id,
    nome: entity.nome,
    email: entity.email,
    // NÃO incluir senha!
  };
}

protected toEntity(dto: CreateUsuarioDto | UpdateUsuarioDto): Partial<Usuario> {
  const entity: any = {
    nome: dto.nome,
    email: dto.email,
  };
  
  // Hash de senha apenas se fornecida
  if ('senha' in dto && dto.senha) {
    entity.senha = await bcrypt.hash(dto.senha, 10);
  }
  
  return entity;
}
```

## Exemplo de Uso

### Implementação de Service

```typescript
import { Injectable, Inject } from '../../core/di';
import { TYPES } from '../../core/di/types';
import { IUsuarioRepository } from '../../infrastructure/repository/IUsuarioRepository';
import { IApplicationService } from './IApplicationService';
import { CreateUsuarioDto } from '../dto/usuario/CreateUsuarioDto';
import { UpdateUsuarioDto } from '../dto/usuario/UpdateUsuarioDto';
import { UsuarioResponseDto } from '../dto/usuario/UsuarioResponseDto';
import { NotFoundException, BusinessException } from '../../core/exceptions';
import bcrypt from 'bcryptjs';

export interface IUsuarioApplicationService 
  extends IApplicationService<UsuarioResponseDto, CreateUsuarioDto, UpdateUsuarioDto> {
  findByEmail(email: string): Promise<UsuarioResponseDto | null>;
}

@Injectable()
export class UsuarioApplicationService implements IUsuarioApplicationService {
  constructor(
    @Inject(TYPES.IUsuarioRepository)
    private repository: IUsuarioRepository
  ) {}

  async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
    // Validação de negócio
    const existing = await this.repository.findByEmail(dto.email);
    if (existing) {
      throw new BusinessException('Email já está em uso');
    }

    // Transformação
    const entity = this.toEntity(dto);
    const created = await this.repository.create(entity);
    return this.toDto(created);
  }

  async update(id: number, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
    const existing = await this.repository.findById(id);
    if (!existing) {
      throw new NotFoundException('Usuário', id);
    }

    const entity = this.toEntity(dto);
    const updated = await this.repository.update(id, entity);
    return this.toDto(updated);
  }

  async delete(id: number): Promise<boolean> {
    return await this.repository.delete(id);
  }

  async getById(id: number): Promise<UsuarioResponseDto | null> {
    const entity = await this.repository.findById(id);
    return entity ? this.toDto(entity) : null;
  }

  async list(page: number = 1, limit: number = 10): Promise<PaginatedResult<UsuarioResponseDto>> {
    const result = await this.repository.findAllPaginated(page, limit);
    return {
      ...result,
      data: result.data.map(entity => this.toDto(entity)),
    };
  }

  // Método customizado
  async findByEmail(email: string): Promise<UsuarioResponseDto | null> {
    const entity = await this.repository.findByEmail(email);
    return entity ? this.toDto(entity) : null;
  }

  private toDto(entity: Usuario): UsuarioResponseDto {
    return {
      id: entity.id,
      nome: entity.nome,
      email: entity.email,
      // ... outros campos (sem senha)
    };
  }

  private toEntity(dto: CreateUsuarioDto | UpdateUsuarioDto): Partial<Usuario> {
    const entity: any = {
      nome: dto.nome,
      email: dto.email,
      // ...
    };

    if ('senha' in dto && dto.senha) {
      entity.senha = await bcrypt.hash(dto.senha, 10);
    }

    return entity;
  }
}
```

### Uso em Controller

```typescript
@Injectable()
export class UsuarioController {
  constructor(
    @Inject(TYPES.IUsuarioApplicationService)
    private usuarioService: IUsuarioApplicationService
  ) {}

  async create(req: Request, res: Response) {
    const dto = req.body as CreateUsuarioDto;
    const usuario = await this.usuarioService.create(dto);
    return res.status(201).json(usuario);
  }
}
```

## Benefícios Alcançados

### 1. Separação de Responsabilidades
- ✅ Controllers focam em HTTP (request/response)
- ✅ Services focam em lógica de negócio
- ✅ Repositórios focam em acesso a dados

### 2. Reutilização
- ✅ Lógica de negócio pode ser reutilizada
- ✅ Services podem ser usados em diferentes contextos (API, CLI, Jobs)
- ✅ Redução de código duplicado

### 3. Testabilidade
- ✅ Fácil mockar repositórios em testes
- ✅ Testes unitários isolados
- ✅ Cobertura de testes mais simples

### 4. Manutenibilidade
- ✅ Código organizado e estruturado
- ✅ Padrões consistentes
- ✅ Fácil adicionar novas regras de negócio

### 5. Type Safety
- ✅ Interfaces garantem contratos claros
- ✅ TypeScript garante type safety
- ✅ Autocomplete funciona corretamente

## Comparação: Antes vs Depois

### Antes (Lógica no Controller)

```typescript
@Injectable()
export class UsuarioController {
  constructor(
    @Inject(TYPES.IUsuarioRepository)
    private repository: IUsuarioRepository
  ) {}

  async create(req: Request, res: Response) {
    const dto = req.body as CreateUsuarioDto;
    
    // Lógica de negócio no controller ❌
    const existing = await this.repository.findByEmail(dto.email);
    if (existing) {
      throw new BusinessException('Email já está em uso');
    }
    
    const entity = { ...dto, senha: await bcrypt.hash(dto.senha, 10) };
    const created = await this.repository.create(entity);
    
    return res.status(201).json(created.toJSON());
  }
}
```

**Problemas**:
- ❌ Lógica de negócio misturada com HTTP
- ❌ Difícil reutilizar lógica
- ❌ Controllers complexos e difíceis de testar

### Depois (Com Application Service)

```typescript
@Injectable()
export class UsuarioController {
  constructor(
    @Inject(TYPES.IUsuarioApplicationService)
    private usuarioService: IUsuarioApplicationService
  ) {}

  async create(req: Request, res: Response) {
    const dto = req.body as CreateUsuarioDto;
    
    // Delega para service ✅
    const usuario = await this.usuarioService.create(dto);
    
    return res.status(201).json(usuario);
  }
}

@Injectable()
export class UsuarioApplicationService {
  async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
    // Lógica de negócio no service ✅
    const existing = await this.repository.findByEmail(dto.email);
    if (existing) {
      throw new BusinessException('Email já está em uso');
    }
    
    const entity = this.toEntity(dto);
    const created = await this.repository.create(entity);
    return this.toDto(created);
  }
}
```

**Benefícios**:
- ✅ Separação clara de responsabilidades
- ✅ Lógica reutilizável
- ✅ Controllers simples e testáveis
