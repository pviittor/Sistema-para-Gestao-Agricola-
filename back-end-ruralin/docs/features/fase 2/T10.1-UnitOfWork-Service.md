# T10.1 - UnitOfWork Service - Documentação de Implementação

## Resumo Executivo

Implementação do padrão Unit of Work para gerenciamento automático de transações de banco de dados. O UnitOfWork Service garante atomicidade de operações, criando transações automaticamente, fazendo commit em sucesso e rollback em caso de erro. Esta implementação permite que Application Services executem múltiplas operações de banco de dados de forma transacional, garantindo consistência de dados.

## Decisões de Implementação

### Abordagem Escolhida

**Unit of Work Pattern**:
- Padrão de design que garante atomicidade de operações
- Cada método de Application Service pode ser uma unidade de trabalho
- Transações são criadas automaticamente e commitadas ao final
- Rollback automático em caso de erro

**Integração com Sequelize**:
- Usa `sequelize.transaction()` para criar transações
- Transação é passada para a função executada
- Commit e rollback são gerenciados automaticamente

**Simplicidade**:
- Interface simples com um único método `execute`
- Não gerencia transações aninhadas (cada chamada cria nova transação)
- Fácil de usar e entender

Interface que define o contrato para Unit of Work:

```typescript
export interface IUnitOfWork {
  execute<T>(fn: (transaction: Transaction) => Promise<T>): Promise<T>;
}
```

**Características**:
- Método genérico `execute` que aceita função assíncrona
- Transação é passada como parâmetro para a função
- Retorna o resultado da função executada
- Propaga erros após rollback

### 2. `src/core/unitofwork/UnitOfWorkService.ts`

Implementação do Unit of Work Service:

```typescript
@Injectable()
export class UnitOfWorkService implements IUnitOfWork {
  async execute<T>(fn: (transaction: Transaction) => Promise<T>): Promise<T> {
    const transaction = await sequelize.transaction();
    try {
      const result = await fn(transaction);
      await transaction.commit();
      return result;
    } catch (error) {
      await transaction.rollback();
      throw error;
    }
  }
}
```

**Características**:
- Cria transação usando Sequelize
- Executa função dentro da transação
- Faz commit em sucesso
- Faz rollback em erro
- Propaga erro após rollback
- Integrado com DI container

## Como Funciona

### Fluxo de Execução

```
1. Application Service chama unitOfWork.execute()
   ↓
2. UnitOfWork cria nova transação (sequelize.transaction())
   ↓
3. UnitOfWork executa função fornecida, passando transação
   ↓
4. Função executa operações usando transação
   ↓
5a. Se sucesso: UnitOfWork faz commit
5b. Se erro: UnitOfWork faz rollback e propaga erro
   ↓
6. Retorna resultado (ou lança erro)
```

### Exemplo de Uso

```typescript
@Injectable()
export class UsuarioApplicationService {
  constructor(
    @Inject(TYPES.IUsuarioRepository)
    private repository: IUsuarioRepository,
    @Inject(TYPES.IUnitOfWork)
    private unitOfWork: IUnitOfWork
  ) {}

  async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
    return await this.unitOfWork.execute(async (transaction) => {
      // Todas as operações dentro desta função serão transacionais
      const entity = await this.mapper.toEntity(dto);
      const created = await this.repository.create(entity as any, { transaction });
      return this.mapper.toDto(created);
    });
  }
}
```

## Métodos Implementados

### `execute<T>(fn: (transaction: Transaction) => Promise<T>): Promise<T>`

Executa uma função dentro de uma transação de banco de dados.

**Parâmetros**:
- `fn`: Função assíncrona que recebe a transação como parâmetro

**Retorno**:
- Promise que resolve com o resultado da função

**Comportamento**:
- Cria nova transação
- Executa função passando transação
- Faz commit se função executar com sucesso
- Faz rollback se função lançar exceção
- Propaga erro após rollback

**Exemplo**:
```typescript
const result = await unitOfWork.execute(async (transaction) => {
  const usuario = await usuarioRepository.create(dto, { transaction });
  const role = await roleRepository.create(roleDto, { transaction });
  await usuarioRoleRepository.create(
    { usuarioId: usuario.id, roleId: role.id },
    { transaction }
  );
  return usuario;
});
```

## Testes Unitários

### Estrutura de Testes

Os testes verificam:
1. **Execução bem-sucedida**: Cria transação, executa função, faz commit
2. **Rollback em erro**: Faz rollback e propaga erro
3. **Passagem de transação**: Transação é passada corretamente para função
4. **Retorno de resultado**: Retorna resultado da função
5. **Erro no commit**: Faz rollback mesmo se commit falhar
6. **Erro no rollback**: Propaga erro original mesmo se rollback falhar
7. **Funções assíncronas**: Suporta funções assíncronas
8. **Transações isoladas**: Cada chamada cria nova transação

## Casos de Uso

### Caso 1: Criação com Múltiplas Operações

```typescript
async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
  return await this.unitOfWork.execute(async (transaction) => {
    // Criar usuário
    const usuario = await this.usuarioRepository.create(dto, { transaction });
    
    // Criar role padrão
    const role = await this.roleRepository.create({ nome: 'USER' }, { transaction });
    
    // Associar usuário com role
    await this.usuarioRoleRepository.create(
      { usuarioId: usuario.id, roleId: role.id },
      { transaction }
    );
    
    return this.mapper.toDto(usuario);
  });
}
```

**Benefício**: Se qualquer operação falhar, todas são revertidas.

### Caso 2: Atualização com Validações

```typescript
async update(id: number, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
  return await this.unitOfWork.execute(async (transaction) => {
    // Verificar existência
    const existing = await this.repository.findById(id, { transaction });
    if (!existing) {
      throw new NotFoundException('Usuário', id);
    }
    
    // Validar email único
    if (dto.email && dto.email !== existing.email) {
      const emailExists = await this.repository.findByEmail(dto.email, { transaction });
      if (emailExists) {
        throw new BusinessException('Email já está em uso');
      }
    }
    
    // Atualizar
    const updated = await this.repository.update(id, dto, { transaction });
    return this.mapper.toDto(updated);
  });
}
```

**Benefício**: Validações e atualização são atômicas.

### Caso 3: Deleção com Dependências

```typescript
async delete(id: number): Promise<boolean> {
  return await this.unitOfWork.execute(async (transaction) => {
    // Verificar existência
    const existing = await this.repository.findById(id, { transaction });
    if (!existing) {
      return false;
    }
    
    // Remover dependências
    await this.usuarioRoleRepository.deleteByUsuario(id, { transaction });
    await this.usuarioSubUsuarioRepository.deleteByUsuario(id, { transaction });
    
    // Remover usuário
    await this.repository.delete(id, { transaction });
    
    return true;
  });
}
```

**Benefício**: Remoção de dependências e entidade principal são atômicas.

## Limitações e Considerações

### Transações Aninhadas

**Limitação Atual**:
- Cada chamada de `execute()` cria uma nova transação
- Não há suporte para transações aninhadas (reutilizar transação existente)

**Solução Futura**:
- Implementar gerenciamento de transações aninhadas usando contexto
- Reutilizar transação existente se já houver uma ativa

### Isolamento

**Limitação Atual**:
- Usa isolamento padrão do Sequelize
- Não permite configurar nível de isolamento

**Solução Futura**:
- Adicionar parâmetro opcional para nível de isolamento
- Suportar diferentes níveis (READ UNCOMMITTED, READ COMMITTED, etc.)

### Timeout

**Limitação Atual**:
- Não há timeout configurado
- Transações podem ficar abertas indefinidamente

**Solução Futura**:
- Adicionar timeout configurável
- Fazer rollback automático em timeout

## Comparação: Antes vs Depois

### Antes (Sem UnitOfWork)

```typescript
async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
  const transaction = await sequelize.transaction();
  try {
    const entity = await this.mapper.toEntity(dto);
    const created = await this.repository.create(entity as any, { transaction });
    await transaction.commit();
    return this.mapper.toDto(created);
  } catch (error) {
    await transaction.rollback();
    throw error;
  }
}
```

**Problemas**:
- ❌ Código repetitivo em cada método
- ❌ Fácil esquecer de fazer commit/rollback
- ❌ Difícil manter consistência
- ❌ Código mais verboso

### Depois (Com UnitOfWork)

```typescript
async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
  return await this.unitOfWork.execute(async (transaction) => {
    const entity = await this.mapper.toEntity(dto);
    const created = await this.repository.create(entity as any, { transaction });
    return this.mapper.toDto(created);
  });
}
```

**Benefícios**:
- ✅ Código mais limpo e conciso
- ✅ Commit e rollback automáticos
- ✅ Consistência garantida
- ✅ Fácil de usar e entender
