# T10.3 - Integração com Application Services - Documentação de Implementação

## Resumo Executivo

Integração completa do UnitOfWork com todos os Application Services do projeto, aplicando o decorator `@Transactional` em todos os métodos que modificam dados (create, update, delete). Esta integração garante que todas as operações de escrita sejam executadas dentro de transações, garantindo atomicidade e consistência de dados. Os métodos de leitura (getById, list, findBy*) não receberam o decorator, pois não modificam dados e não precisam de transação.

## Decisões de Implementação

### Abordagem Escolhida

**Aplicação Seletiva do Decorator**:
- Aplicar `@Transactional` apenas em métodos que modificam dados
- Não aplicar em métodos de leitura (getById, list, findBy*)
- Garantir atomicidade em operações de escrita

**Métodos Transacionais**:
- `create`: Sempre transacional (cria novos registros)
- `update`: Sempre transacional (modifica registros existentes)
- `delete`: Sempre transacional (remove registros)

**Métodos Não Transacionais**:
- `getById`: Apenas leitura
- `list`: Apenas leitura
- `findBy*`: Apenas leitura (findByEmail, findByUsername, findByNome, etc.)

**Simplicidade**:
- Não remover injeção de `IUnitOfWork` (pode ser útil no futuro)
- Apenas adicionar decorator `@Transactional`
- Não alterar lógica existente

## Comparação: Antes vs Depois

### Antes (Sem @Transactional)

```typescript
@Injectable()
export class UsuarioApplicationService {
  constructor(
    @Inject(TYPES.IUsuarioRepository)
    private repository: IUsuarioRepository,
    @Inject(TYPES.IUnitOfWork)
    private unitOfWork: IUnitOfWork  // Injetado mas não usado
  ) {}

  async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
    // Sem transação explícita
    const existing = await this.repository.findByEmail(dto.email);
    if (existing) {
      throw new BusinessException('Email já está em uso');
    }
    const entity = await this.mapper.toEntity(dto);
    const created = await this.repository.create(entity as any);
    return this.mapper.toDto(created);
  }
}
```

**Problemas**:
- ❌ Operações não são atômicas
- ❌ Se validação passar mas criação falhar, dados inconsistentes
- ❌ Não há garantia de rollback em caso de erro

### Depois (Com @Transactional)

```typescript
@Injectable()
export class UsuarioApplicationService {
  constructor(
    @Inject(TYPES.IUsuarioRepository)
    private repository: IUsuarioRepository
    // Não precisa mais injetar IUnitOfWork
  ) {}

  @Transactional()
  async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
    // Executado automaticamente dentro de transação
    const existing = await this.repository.findByEmail(dto.email);
    if (existing) {
      throw new BusinessException('Email já está em uso');
    }
    const entity = await this.mapper.toEntity(dto);
    const created = await this.repository.create(entity as any);
    return this.mapper.toDto(created);
  }
}
```

**Benefícios**:
- ✅ Operações são atômicas
- ✅ Se qualquer operação falhar, todas são revertidas
- ✅ Rollback automático em caso de erro
- ✅ Código mais limpo (não precisa injetar IUnitOfWork)

## Exemplos Práticos

### Exemplo 1: Criação com Validações

```typescript
@Transactional()
async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
  // Validação 1 (dentro de transação)
  const existingByEmail = await this.repository.findByEmail(dto.email);
  if (existingByEmail) {
    throw new BusinessException('Email já está em uso');
  }

  // Validação 2 (dentro de transação)
  const existingByUsername = await this.repository.findByUsername(dto.username);
  if (existingByUsername) {
    throw new BusinessException('Username já está em uso');
  }

  // Criação (dentro de transação)
  const entity = await this.mapper.toEntity(dto);
  const created = await this.repository.create(entity as any);
  
  // Se qualquer operação falhar, todas são revertidas
  return this.mapper.toDto(created);
}
```

**Benefício**: Se a criação falhar após as validações, nada é commitado.

### Exemplo 2: Atualização com Validações

```typescript
@Transactional()
async update(id: number | string, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
  // Verificação de existência (dentro de transação)
  const existing = await this.repository.findById(id);
  if (!existing) {
    throw new NotFoundException('Usuário', id);
  }

  // Validação de email único (dentro de transação)
  if (dto.email && dto.email !== existing.email) {
    const emailExists = await this.repository.findByEmail(dto.email);
    if (emailExists) {
      throw new BusinessException('Email já está em uso');
    }
  }

  // Atualização (dentro de transação)
  const entity = await this.mapper.toEntity(dto);
  const updated = await this.repository.update(id, entity as any);
  
  return this.mapper.toDto(updated);
}
```

**Benefício**: Se a atualização falhar após as validações, nada é commitado.

### Exemplo 3: Deleção

```typescript
@Transactional()
async delete(id: number | string): Promise<boolean> {
  // Verificação de existência (dentro de transação)
  const existing = await this.repository.findById(id);
  if (!existing) {
    return false;
  }

  // Remoção (dentro de transação)
  return await this.repository.delete(id);
}
```

**Benefício**: Se a remoção falhar, nada é commitado.

## Casos de Uso com Transações

### Caso 1: Criação com Múltiplas Validações

```typescript
@Transactional()
async create(dto: CreateEventoDto): Promise<EventoResponseDto> {
  // Validação 1: Data não pode ser no passado
  const dataEvento = new Date(dto.data);
  const hoje = new Date();
  hoje.setHours(0, 0, 0, 0);
  
  if (dataEvento < hoje) {
    throw new BusinessException('Não é possível criar evento com data no passado');
  }

  // Validação 2: Horário de fim deve ser posterior ao de início
  const horarioInicio = dto.horario_inicio.split(':').map(Number);
  const horarioFim = dto.horario_fim.split(':').map(Number);
  const inicioMinutos = horarioInicio[0] * 60 + horarioInicio[1];
  const fimMinutos = horarioFim[0] * 60 + horarioFim[1];
  
  if (fimMinutos <= inicioMinutos) {
    throw new BusinessException('Horário de fim deve ser posterior ao horário de início');
  }

  // Criação
  const entity = await this.mapper.toEntity(dto);
  const created = await this.repository.create(entity as any);
  
  return this.mapper.toDto(created);
}
```

**Benefício**: Se qualquer validação ou criação falhar, nada é commitado.

### Caso 2: Atualização com Validações Condicionais

```typescript
@Transactional()
async update(id: number | string, dto: UpdateFinanceiroDto): Promise<FinanceiroResponseDto> {
  const existing = await this.repository.findById(id);
  if (!existing) {
    throw new NotFoundException('Registro financeiro', id);
  }

  // Validação condicional: datas (se fornecidas)
  if (dto.dataEmissao && dto.dataVencimento) {
    const dataEmissao = new Date(dto.dataEmissao);
    const dataVencimento = new Date(dto.dataVencimento);
    
    if (dataVencimento < dataEmissao) {
      throw new BusinessException('Data de vencimento deve ser posterior ou igual à data de emissão');
    }
  }

  // Validação condicional: valor (se fornecido)
  if (dto.valor !== undefined && dto.valor === 0) {
    throw new BusinessException('Valor não pode ser zero');
  }

  // Atualização
  const entity = await this.mapper.toEntity(dto);
  const updated = await this.repository.update(id, entity as any);
  
  return this.mapper.toDto(updated);
}
```

**Benefício**: Validações e atualização são atômicas.

## Métodos Não Transacionais (Leitura)

### Por que não aplicar @Transactional?

Métodos de leitura não modificam dados, então não precisam de transação:

```typescript
// Sem @Transactional (correto)
async getById(id: number | string): Promise<UsuarioResponseDto | null> {
  const entity = await this.repository.findById(id);
  return entity ? this.mapper.toDto(entity) : null;
}

// Sem @Transactional (correto)
async list(page: number = 1, limit: number = 10): Promise<PaginatedResult<UsuarioResponseDto>> {
  const result = await this.repository.findAllPaginated(page, limit);
  return {
    ...result,
    data: result.data.map(entity => this.mapper.toDto(entity)),
  };
}

// Sem @Transactional (correto)
async findByEmail(email: string): Promise<UsuarioResponseDto | null> {
  const entity = await this.repository.findByEmail(email);
  return entity ? this.mapper.toDto(entity) : null;
}
```

**Razão**: Transações são desnecessárias para leitura e podem impactar performance.
