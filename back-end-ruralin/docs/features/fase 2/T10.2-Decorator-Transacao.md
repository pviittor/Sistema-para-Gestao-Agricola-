# T10.2 - Decorator de Transação - Documentação de Implementação

## Resumo Executivo

Implementação do decorator `@Transactional` para aplicar transações de banco de dados automaticamente em métodos de Application Services. O decorator intercepta a chamada do método e executa dentro de uma transação, usando o UnitOfWork Service para gerenciar commit e rollback automaticamente. Esta implementação simplifica o uso de transações, eliminando a necessidade de chamar `unitOfWork.execute()` manualmente em cada método.

## Decisões de Implementação

### Abordagem Escolhida

**Method Decorator Pattern**:
- Usa TypeScript method decorators para interceptar chamadas de métodos
- Substitui o método original por um wrapper que executa dentro de transação
- Mantém contexto (`this`) e argumentos do método original

**Integração com UnitOfWork**:
- Usa `IUnitOfWork` resolvido do DI container
- Delega gerenciamento de transações para UnitOfWork Service
- Não gerencia transações diretamente

**Simplicidade**:
- Decorator simples e fácil de usar
- Não requer mudanças na assinatura dos métodos
- Transparente para o código que usa o método

**Limitação Atual**:
- A transação não é passada automaticamente para o método
- Métodos que precisam da transação devem injetar `IUnitOfWork` e usar `execute()` internamente
- Preparado para extensão futura (passar transação via contexto)

## Arquivos Criados

### 1. `src/core/unitofwork/Transactional.ts`

Decorator `@Transactional` para aplicar transações automaticamente:

```typescript
export function Transactional(options?: TransactionOptions) {
  return function (target: any, propertyName: string, descriptor: PropertyDescriptor) {
    const originalMethod = descriptor.value;
    
    descriptor.value = async function (...args: any[]) {
      const unitOfWork = container.resolve<IUnitOfWork>(TYPES.IUnitOfWork);
      return await unitOfWork.execute(async (transaction: Transaction) => {
        return await originalMethod.apply(this, args);
      });
    };
    
    return descriptor;
  };
}
```

**Características**:
- Intercepta chamada do método
- Resolve `IUnitOfWork` do DI container
- Executa método original dentro de transação
- Mantém contexto e argumentos
- Valida que é aplicado apenas a métodos

## Como Funciona

### Fluxo de Execução

```
1. Método decorado é chamado
   ↓
2. Decorator intercepta a chamada
   ↓
3. Decorator resolve IUnitOfWork do container
   ↓
4. Decorator chama unitOfWork.execute()
   ↓
5. UnitOfWork cria transação
   ↓
6. Método original é executado dentro da transação
   ↓
7a. Se sucesso: UnitOfWork faz commit
7b. Se erro: UnitOfWork faz rollback e propaga erro
   ↓
8. Retorna resultado (ou lança erro)
```

### Exemplo de Uso

**Antes (sem decorator)**:
```typescript
@Injectable()
export class UsuarioApplicationService {
  constructor(
    @Inject(TYPES.IUsuarioRepository)
    private repository: IUsuarioRepository,
    @Inject(TYPES.IUnitOfWork)
    private unitOfWork: IUnitOfWork
  ) {}

  async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
    return await this.unitOfWork.execute(async (transaction) => {
      const entity = await this.mapper.toEntity(dto);
      const created = await this.repository.create(entity as any, { transaction });
      return this.mapper.toDto(created);
    });
  }
}
```

**Depois (com decorator)**:
```typescript
@Injectable()
export class UsuarioApplicationService {
  constructor(
    @Inject(TYPES.IUsuarioRepository)
    private repository: IUsuarioRepository
  ) {}

  @Transactional()
  async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
    // Método executado automaticamente dentro de transação
    const entity = await this.mapper.toEntity(dto);
    const created = await this.repository.create(entity as any);
    return this.mapper.toDto(created);
  }
}
```

**Benefício**: Código mais limpo, sem necessidade de injetar `IUnitOfWork` e chamar `execute()` manualmente.

## Integração com Application Services

### Exemplo Completo

```typescript
import { Injectable, Inject } from '../../../core/di';
import { TYPES } from '../../../core/di/types';
import { Transactional } from '../../../core/unitofwork/Transactional';
import { IUsuarioRepository } from '../../../infrastructure/repository/IUsuarioRepository';
import { UsuarioMapper } from '../../mappers/UsuarioMapper';
import { CreateUsuarioDto } from '../../dto/usuario/CreateUsuarioDto';
import { UpdateUsuarioDto } from '../../dto/usuario/UpdateUsuarioDto';
import { UsuarioResponseDto } from '../../dto/usuario/UsuarioResponseDto';
import { NotFoundException, BusinessException } from '../../../core/exceptions';

@Injectable()
export class UsuarioApplicationService {
  private mapper: UsuarioMapper;

  constructor(
    @Inject(TYPES.IUsuarioRepository)
    private repository: IUsuarioRepository
  ) {
    this.mapper = new UsuarioMapper();
  }

  @Transactional()
  async create(dto: CreateUsuarioDto): Promise<UsuarioResponseDto> {
    // Validação de negócio
    const existing = await this.repository.findByEmail(dto.email);
    if (existing) {
      throw new BusinessException('Email já está em uso');
    }

    // Criação (dentro de transação)
    const entity = await this.mapper.toEntity(dto);
    const created = await this.repository.create(entity as any);
    return this.mapper.toDto(created);
  }

  @Transactional()
  async update(id: number | string, dto: UpdateUsuarioDto): Promise<UsuarioResponseDto> {
    const existing = await this.repository.findById(id);
    if (!existing) {
      throw new NotFoundException('Usuário', id);
    }

    // Atualização (dentro de transação)
    const entity = await this.mapper.toEntity(dto);
    const updated = await this.repository.update(id, entity as any);
    return this.mapper.toDto(updated);
  }

  @Transactional()
  async delete(id: number | string): Promise<boolean> {
    const existing = await this.repository.findById(id);
    if (!existing) {
      return false;
    }

    // Remoção (dentro de transação)
    return await this.repository.delete(id);
  }

  // Métodos de leitura não precisam de transação
  async getById(id: number | string): Promise<UsuarioResponseDto | null> {
    const entity = await this.repository.findById(id);
    return entity ? this.mapper.toDto(entity) : null;
  }

  async list(page: number = 1, limit: number = 10): Promise<PaginatedResult<UsuarioResponseDto>> {
    const result = await this.repository.findAllPaginated(page, limit);
    return {
      ...result,
      data: result.data.map(entity => this.mapper.toDto(entity)),
    };
  }
}
```

## Limitações e Considerações

### Limitação: Transação Não Passada para Método

**Situação Atual**:
- O decorator executa o método dentro de uma transação
- Mas a transação não é passada como parâmetro para o método
- Métodos que precisam da transação não têm acesso direto

**Solução Atual**:
- Métodos que precisam da transação devem injetar `IUnitOfWork` e usar `execute()` internamente
- Ou usar `unitOfWork.execute()` manualmente quando necessário

**Solução Futura**:
- Implementar contexto de transação (similar a `RequestContext`)
- Passar transação via contexto para métodos que precisam
- Permitir acesso à transação atual sem injetar `IUnitOfWork`

### Limitação: Isolamento Não Implementado

**Situação Atual**:
- Opções de isolamento são aceitas mas não implementadas
- Todas as transações usam isolamento padrão do Sequelize

**Solução Futura**:
- Implementar suporte a níveis de isolamento
- Passar isolamento para `sequelize.transaction({ isolationLevel })`

### Limitação: Transações Aninhadas

**Situação Atual**:
- Cada método decorado cria nova transação
- Não há suporte para reutilizar transação existente

**Solução Futura**:
- Implementar gerenciamento de transações aninhadas
- Reutilizar transação existente se já houver uma ativa
