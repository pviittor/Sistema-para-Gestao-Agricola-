## Decisões de Implementação

### Abordagem Escolhida

**Injeção de Dependência**:
- Todos os controllers agora injetam seus respectivos repositórios via DI
- Uso de `@Inject(TYPES.IRepository)` para resolução de dependências
- Construtores recebem repositórios como dependências

**Substituição de Métodos**:
- `Model.findAll()` → `repository.findAll()`
- `Model.findByPk()` → `repository.findById()`
- `Model.findOne()` → `repository.findOne()`
- `Model.create()` → `repository.create()`
- `instance.update()` → `repository.update()`
- `instance.destroy()` → `repository.delete()`

**Relacionamentos**:
- Para relacionamentos simples (como Local em Evento), mantido acesso via `include` no `findAll`/`findOne`
- Para relacionamentos complexos (como LembreteDataHora), mantido acesso direto ao modelo para operações de criação/atualização em massa

## Controllers Refatorados

### 1. EventoController

**Antes**:
```typescript
import Evento from '../models/Evento';
import Local from '../models/Local';

@Injectable()
export class EventoController {
  async index(req: Request, res: Response) {
    const eventos = await Evento.findAll({
      where: { usuarioId: Number(userId) },
      include: [{ model: Local, as: 'local' }]
    });
  }
}
```

**Depois**:
```typescript
import { IEventoRepository } from '../infrastructure/repository/IEventoRepository';
import Local from '../models/Local'; // Mantido para include

@Injectable()
export class EventoController {
  constructor(
    @Inject(TYPES.IEventoRepository)
    private eventoRepository: IEventoRepository
  ) {}

  async index(req: Request, res: Response) {
    const eventos = await this.eventoRepository.findAll({
      where: { usuarioId: Number(userId) },
      include: [{ model: Local, as: 'local' }]
    });
  }
}
```

**Mudanças**:
- ✅ Injeta `IEventoRepository` via DI
- ✅ Substitui `Evento.findAll()` por `eventoRepository.findAll()`
- ✅ Substitui `Evento.findByPk()` por `eventoRepository.findById()` ou `findOne()`
- ✅ Substitui `Evento.create()` por `eventoRepository.create()`
- ✅ Substitui `evento.update()` por `eventoRepository.update()`
- ✅ Substitui `evento.destroy()` por `eventoRepository.delete()`
- ✅ Mantém import de `Local` para relacionamento

## Mapeamento de Métodos

### Métodos Sequelize → Repository

| Sequelize | Repository | Observações |
|-----------|------------|-------------|
| `Model.findAll(options)` | `repository.findAll(options)` | Mantém suporte a includes |
| `Model.findByPk(id)` | `repository.findById(id)` | Busca por ID |
| `Model.findOne(options)` | `repository.findOne(options)` | Busca única com filtros |
| `Model.create(data)` | `repository.create(data)` | Criação de entidade |
| `instance.update(data)` | `repository.update(id, data)` | Atualização (retorna entidade atualizada) |
| `instance.destroy()` | `repository.delete(id)` | Remoção (retorna boolean) |

### Métodos Customizados Utilizados

- **LocalController**: `findByUsuario(usuarioId)` - Busca locais do usuário
- **LembreteController**: `findByUsuario(usuarioId)` - Busca lembretes do usuário com relacionamentos
- **EventoController**: `findAll()` com includes para relacionamento com Local

## Comparação: Antes vs Depois

### Antes (Acesso Direto ao Sequelize)

```typescript
@Injectable()
export class EventoController {
  async index(req: Request, res: Response) {
    const eventos = await Evento.findAll({
      where: { usuarioId: Number(userId) },
    });
    return res.json(eventos);
  }

  async create(req: Request, res: Response) {
    const evento = await Evento.create(dto);
    return res.status(201).json(evento);
  }
}
```

**Problemas**:
- ❌ Controller acoplado ao Sequelize
- ❌ Difícil de testar (requer mock do Sequelize)
- ❌ Código duplicado em múltiplos controllers
- ❌ Difícil trocar ORM

### Depois (Com Repository Pattern)

```typescript
@Injectable()
export class EventoController {
  constructor(
    @Inject(TYPES.IEventoRepository)
    private eventoRepository: IEventoRepository
  ) {}

  async index(req: Request, res: Response) {
    const eventos = await this.eventoRepository.findAll({
      where: { usuarioId: Number(userId) },
    });
    return res.json(eventos);
  }

  async create(req: Request, res: Response) {
    const evento = await this.eventoRepository.create(dto);
    return res.status(201).json(evento);
  }
}
```

**Benefícios**:
- ✅ Controller desacoplado do Sequelize
- ✅ Fácil de testar (mock do repositório)
- ✅ Código reutilizável
- ✅ Fácil trocar ORM

## Casos Especiais

### Relacionamentos Mantidos

Alguns controllers mantêm acesso direto a modelos relacionados:

1. **EventoController**: Mantém import de `Local` para `include` em queries
2. **LembreteController**: Mantém acesso direto a `LembreteDataHora` para operações de relacionamento

**Justificativa**:
- Relacionamentos são tratados pelo Sequelize via `include`
- Operações complexas de relacionamento (bulkCreate, destroy) são mais simples com acesso direto
- O repositório não precisa gerenciar todos os relacionamentos

### Filtragem de Campos Undefined

O `FinanceiroController` mantém lógica de filtragem de campos `undefined`:

```typescript
const financeiroData: any = {
  usuarioId: Number(userId),
  dataEmissao: dto.dataEmissao,
  // ...
};
if (dto.contaId !== undefined) financeiroData.contaId = dto.contaId;
```

**Justificativa**:
- Sequelize não aceita campos `undefined` em operações de criação/atualização
- Esta lógica pode ser movida para o repositório no futuro se necessário
